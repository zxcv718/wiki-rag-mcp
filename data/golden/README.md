# 골든셋

가상 위키(`data/wiki`)에 대한 질문 300문항과 정답 문서입니다. M2 판정 실험(ADR-20)과 이후 CI 회귀 테스트(7장)에 씁니다. 첫 실험 전에 git 태그 `golden-v1`로 고정했습니다.

## 파일

| 파일 | 내용 |
|---|---|
| `golden.jsonl` | 골든셋. 문항마다 id, 유형, 질문, 질문자, 정답 문서(`relevant`), 출처 문서 |
| `sources.yaml` | 질문의 출처. 유형별 문항 수에 맞춰 시드로 고른 핵심 사실과 질문자 |
| `questions.jsonl` | LLM이 쓴 질문 |
| `blind_labels.jsonl` | 출처를 모르는 라벨러가 찾은 정답 문서와 근거 문장 |
| `overrides.yaml` | 출처 라벨과 블라인드 라벨이 다른 문항을 검토한 결정 |
| `review.md` | 검토 기록 |
| `generation_log.jsonl` | 질문 생성 LLM 호출 기록 |

## 만든 방법 (ADR-14)

1. **출처 고르기** (`tools/goldset/select.py`)
   - 유형별 문항 수(ADR-20)에 맞춰 가상 위키 생성 기록의 핵심 사실을 시드로 고릅니다.
   - 질문자는 그 문서를 볼 수 있는 가상 사용자 가운데 덜 뽑힌 사람입니다. 11명이 27~28문항씩 묻습니다.
   - 모순·개정 문항은 15쌍의 새 문서가 출처이고, 가능하면 옛 문서도 볼 수 있는 사람이 묻습니다.
   - 답 없음 문항은 위키에 없는 15개 주제에서 두 문항씩입니다.
2. **질문 쓰기** (`tools/goldset/write.py`, gpt-5.4)
   - 작성자에게는 핵심 사실과 질문자의 소속만 주고, 문서 제목과 본문은 주지 않습니다.
   - 답이 되는 표현을 질문에 넣거나, 사실 문장에서 공백을 뺀 8자 이상을 그대로 옮기면 다시 쓰게 했습니다.
3. **블라인드 라벨링** (Claude)
   - 질문을 쓴 모델과 다른 모델이 출처와 유형을 모른 채, 섞인 순서의 질문을 받아 위키 문서만 뒤져 정답 문서를 모두 찾았습니다.
   - 생성 기록과 골든셋 출처 파일은 열지 않게 했습니다.
4. **합치기와 검토** (`tools/goldset/labels.py`)
   - 출처 문서를 라벨러도 찾았으면, 출처 문서와 라벨러가 찾은 다른 문서를 모두 정답으로 둡니다.
   - 라벨러가 출처를 찾지 못했거나, 문서끼리 답이 다르거나, 질문이 모호하다고 했으면 검토했습니다.
   - 모순·개정 문항의 정답은 새 문서 하나입니다(ADR-20).
   - 질문자가 볼 수 없는 문서는 정답에서 뺍니다.

## 한계

- 다른 사람에게 받은 질문이 없습니다. 모든 질문이 같은 생성 방식에서 나왔습니다(ADR-14 감수한 비용).
- 질문 작성자는 핵심 사실을 보고 썼기 때문에, 실제 직원보다 답에 가까운 말을 쓸 수 있습니다. 질문과 정답 문서의 형태소 겹침 비율을 판정 결과와 함께 보고합니다.
- 문항끼리 완전히 독립이 아닙니다. 164개 문서에서 300문항이 나왔고, 한 문서에서 최대 2문항이 나옵니다.
