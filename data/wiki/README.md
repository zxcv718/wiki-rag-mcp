# 평가용 가상 위키

가상 IT 회사 새솔소프트의 사내 위키 200문서입니다. 검색 품질 판정(7장, ADR-20)과 권한·등급 테스트(4장)에 씁니다.
실제 사내 위키가 없어서 만들었고, 사내 위키에서 검색을 어렵게 만드는 요소를 일부러 심었습니다.

## 파일

| 파일 | 내용 |
|---|---|
| `schema.yaml` | 생성 스키마. 조직도, 가상 사용자 11명과 소속 그룹, 스페이스 14개와 권한 매트릭스, 약어·고유명사 사전, 위키에 없어야 하는 주제 |
| `manifest.yaml` | 문서 계획 겸 생성 기록. 문서마다 핵심 사실과 심은 의도(개정 전후, 모순, 제한, 기밀, 인젝션 등). 골든셋 정답 라벨의 기준 원장 |
| `generation_log.jsonl` | LLM 호출 기록. 단계, 대상, 모델, 프롬프트 해시, 토큰 수, 검증에서 걸린 문제 |
| `review.md` | 계획 검수 기록. 본문을 쓰기 전에 고친 내용과 이유 |
| `docs/*.md` | 문서. front matter에 권한(`restricted`)과 등급(`classification`)이 있다 |

심을 사례의 명세는 `tools/wikigen/plants.yaml`에 있습니다.

## 만든 방법

Karpathy의 LLM 위키 방식에서 스키마, 기록, 점검 세 가지만 빌렸습니다. 서비스에서 LLM이 종합한 페이지를 쓰지 않는 이유는 ADR-18에 있습니다.

1. **스키마를 먼저 정함**: 조직도, 권한 매트릭스, 약어 사전을 사람이 정했습니다. 모든 문서가 이 스키마를 따릅니다.
2. **심을 사례는 손으로 씀**: 개정 전후 쌍 10개, 모순 쌍 5개, 제한·기밀·빈 권한·인젝션 문서 등 53개 문서의 제목과 핵심 사실은 `plants.yaml`에 직접 적었습니다. 골든셋의 정답을 가르는 문서라 LLM에게 맡기지 않았습니다.
3. **나머지 147문서는 LLM이 계획**: 스페이스마다 제목과 핵심 사실만 계획하게 하고, 형식·개수·용어·연도 표기를 코드로 검증해 틀리면 문제를 알려 주며 다시 요청했습니다(`tools/wikigen/plan.py`).
4. **날짜와 id는 시드로 배정**: 수정일, 버전, 문서 id는 LLM이 아니라 스키마의 시드로 정해, 이번 달 수정 문서와 오래된 문서 수를 목표치에 정확히 맞췄습니다.
5. **계획 검수**: 본문을 쓰기 전에 계획 전체를 따로 검토해, 계획하지 않은 모순과 용어 오용을 고쳤습니다(`review.md`).
6. **본문 생성**: 문서마다 핵심 사실의 표현이 글자 그대로 들어갔는지, 금지한 주제·기호·지어낸 코드가 없는지 검증하고 틀리면 다시 쓰게 했습니다(`tools/wikigen/write.py`).
7. **점검**: 생성 기록과 실제 문서가 맞는지, 서버가 읽은 권한과 등급이 계획과 같은지, 심은 사례가 의도대로 들어갔는지 확인합니다. LLM을 부르지 않아 CI에서도 돕니다(`tools/wikigen/lint.py`).

생성 모델은 코디세이 Public API의 `gpt-5.4`입니다. 이 API는 seed를 받지 않아 같은 요청도 매번 결과가 다릅니다. 그래서 재현성은 다시 돌려 같은 결과를 얻는 것이 아니라, 생성 기록과 커밋한 결과물로 무엇을 어떻게 만들었는지 추적하는 것으로 확보합니다.

## 심은 것

<!-- 아래 표는 `uv run python -m tools.wikigen lint`의 출력이다 -->

| 항목 | 값 |
|---|---|
| 문서 | 200 |
| 스페이스 | 14 |
| 가상 사용자 | 11 |
| 개정 전후 쌍 | 10 |
| 모순 쌍 | 5 |
| 제한 문서 | 14 |
| 빈 권한 문서 | 3 |
| 기밀 문서 | 31 |
| 지시문을 심은 문서 | 3 |
| 이번 달 수정 문서 | 28 |
| 오래된 문서 | 36 |
| 약어·고유명사 | 43 |
| 없어야 할 주제 | 15 |
| 본문 평균 글자 수 | 1945 |

- **개정 전후 쌍·모순 쌍**: 같은 주제에 값이 다른 두 문서. 새 문서가 정답입니다(골든셋 모순·개정 15문항).
- **제한 문서**: 스페이스 보기 권한과 문서 제한을 둘 다 만족해야 보이는 문서(ADR-21). 스페이스 멤버이지만 제한 대상이 아닌 사용자와, 제한 대상이지만 스페이스 멤버가 아닌 사용자 사례를 모두 넣었습니다.
- **빈 권한 문서**: 권한 필드가 빈 채 저장된 문서. 아무에게도 나오면 안 됩니다(4장 "권한 모델").
- **기밀 문서**: 외부 LLM 클라이언트에는 제목과 링크만 나가야 하는 문서(ADR-17).
- **지시문을 심은 문서**: "이전 지시를 무시하라" 같은 문장을 본문에 넣은 문서(9장).
- **없어야 할 주제**: 어느 문서에도 없는 주제. 골든셋 답 없음 문항의 재료입니다.

생성에 쓴 토큰은 계획 약 28만, 본문 약 53만으로 모두 약 81만입니다(`generation_log.jsonl`).

## 다시 만들기

```bash
uv sync --group wikigen                                   # openai 패키지
cp .env.example .env                                      # COPA_API_KEY 입력
uv run --group wikigen python -m tools.wikigen plan       # 문서 계획 (manifest.yaml)
uv run --group wikigen python -m tools.wikigen write      # 본문 생성. 이미 쓴 문서는 건너뛴다
uv run python -m tools.wikigen lint                       # 점검
uv run wiki-rag-index --wiki-dir data/wiki --reset        # 색인
```
