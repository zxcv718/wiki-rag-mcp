# PII 등급별 정산 데이터 마스킹 기준

## 대상 데이터

이 문서는 정산 데이터 조회 시 적용하는 마스킹 기준을 설명합니다. 여기서 PII 등급은 개인정보 민감도를 1~3등급으로 나눈 사내 기준이며, 1등급이 가장 민감합니다. 대상은 데이터 스페이스에서 조회하는 테이블, 공용 조회 뷰, 추출 파일입니다.

정산 데이터에서 자주 확인하는 항목의 기본 분류는 아래와 같습니다.

| 항목 | PII 등급 | 기본 처리 |
|---|---:|---|
| 계좌번호 원문 | 1등급 | 원문 직접 조회를 제한합니다 |
| 휴대전화번호 | 2등급 | 공용 조회 뷰에서 마스킹합니다 |
| 상호명 | 3등급 | 기본 조회 권한으로 열람할 수 있습니다 |

계좌번호 원문은 "1등급"으로 분류합니다. 휴대전화번호는 정산 확인에 필요한 경우가 있으나 노출 범위를 줄이기 위해 공용 조회 뷰에서 부분 마스킹합니다. 상호명은 "3등급"으로 분류하며, 데이터 스페이스의 기본 조회 권한으로 열람할 수 있습니다.

## 권한 신청

기본 조회는 공용 조회 뷰를 기준으로 합니다. 공용 조회 뷰에는 업무상 자주 쓰는 컬럼만 포함하며, 민감도가 높은 컬럼은 원문 대신 마스킹된 값으로 제공합니다.

1등급 컬럼 원문 조회가 필요한 경우에는 데이터팀에 사유를 남겨 별도 승인을 받아야 합니다. 신청 시에는 조회 목적, 필요한 컬럼, 사용 기간, 결과 보관 위치를 함께 적습니다. 신청 내용에는 업무 티켓 번호나 요청 배경을 포함하는 것을 권장합니다.

개발본부에서 일시적으로 확인이 필요한 경우에도 동일하게 신청합니다. 외부 협력사는 기본적으로 공용 조회 뷰만 사용하며, 1등급 원문이 포함된 직접 조회는 데이터팀 검토 없이 진행하지 않습니다.

## 조회 방법

공용 조회 뷰에서는 휴대전화번호를 "뒤 4자리"만 남기고 마스킹합니다. 예시는 아래와 같습니다.

```sql
SELECT
    settlement_id,
    merchant_name,
    phone_masked,
    settled_amount,
    settled_at
FROM settlement_public_view
WHERE settled_at >= DATE '2026-08-01'
ORDER BY settled_at DESC
LIMIT 100;
```

위 조회에서 `merchant_name`은 상호명이며 3등급 기준으로 기본 조회 권한에서 확인할 수 있습니다. `phone_masked`는 원문이 아니라 마스킹된 값입니다.

원문이 필요한 승인 조회에서는 필요한 컬럼만 최소한으로 선택합니다.

```sql
SELECT
    settlement_id,
    account_number,
    phone_number
FROM settlement_restricted_view
WHERE settlement_id = '<조회대상ID>';
```

제한 조회 결과를 다시 공유용 파일로 옮길 때에는 불필요한 컬럼을 제거하고, 공용 전달본에는 1등급 원문을 포함하지 않도록 확인합니다.

## 주의점

1등급 컬럼이 포함된 추출 파일은 생성 후 "7일" 안에 삭제해야 합니다. 로컬 저장소, 개인 작업 폴더, 공유 폴더, 임시 업로드 위치를 모두 포함해 동일하게 적용합니다.

추출 파일을 만들 때에는 다음 사항을 지킵니다.

1. 조회 목적에 필요한 최소 컬럼만 포함합니다.
2. 공용 전달본에는 1등급 원문을 넣지 않습니다.
3. 휴대전화번호는 공용 용도에서는 마스킹된 값만 사용합니다.
4. 파일명과 메모에 계좌번호 원문 등 민감한 값을 직접 넣지 않습니다.
5. 사용이 끝난 파일은 즉시 삭제하고, 재생성이 필요하면 다시 승인 절차를 따릅니다.

마스킹 규칙 적용이 애매한 신규 컬럼이 생기면 임의로 공개 범위를 넓히지 말고 데이터팀에 확인합니다. 기준이 정리되기 전까지는 더 높은 민감도로 보고 보수적으로 처리합니다.
