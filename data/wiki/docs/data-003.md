# 개인정보 테이블 접근 권한 목록

## 대상 데이터

이 문서는 운영 환경과 운영 환경에서 복제된 조회용 데이터베이스에 있는 개인정보 포함 테이블의 접근 기준을 정리합니다. 여기서 PII 등급은 개인정보 민감도를 1~3등급으로 나눈 사내 기준이며, 1등급이 가장 민감합니다.

권한 기준은 아래와 같습니다.

| 구분 | 예시 데이터 | 직접 조회 가능 대상 |
|---|---|---|
| PII 등급 1 | 주민등록번호 대체식별값, 계좌번호, 카드 식별 정보, 연락처 원문 | DBA만 직접 조회합니다 |
| PII 등급 2 | 이름, 주소 일부, 예약자 식별 정보 | 승인된 업무 담당자가 조회할 수 있습니다 |
| PII 등급 3 | 내부 식별자와 결합 시 개인정보가 될 수 있는 데이터 | 승인된 업무 담당자가 조회할 수 있습니다 |

"PII 등급 1" 테이블은 DBA만 직접 조회합니다. 개발본부, 데이터팀, 고객지원팀, 제품기획팀을 포함한 일반 업무 담당자는 직접 조회하지 않습니다. 필요한 경우 목적과 기간을 적어 DBA에게 요청합니다.

## 권한 신청

개인정보 테이블 조회 권한은 상시 부여하지 않습니다. 업무상 필요가 확인된 사람에게만 최소 범위로 부여합니다.

권한 신청 절차는 아래와 같습니다.

1. 신청자는 조회 목적, 대상 테이블, 필요한 기간, 결과 활용 범위를 정리합니다.
2. 소속 팀장과 데이터 소유 업무 담당자의 확인을 받습니다.
3. DBA가 대상 테이블의 PII 등급과 조회 범위를 검토합니다.
4. 승인되면 필요한 계정에 한해 권한을 부여합니다.

신청 시 아래 내용을 함께 전달합니다.

- 신청자 이름과 소속
- 업무 목적
- 조회 대상 테이블명
- 필요한 컬럼
- 사용 기간
- 결과 저장 위치
- 외부 반출 여부

권한은 영구 유지하지 않습니다. 모든 개인정보 테이블 접근 권한은 분기마다 "접근 재인증"을 받습니다. 재인증 시점에 업무 필요성이 확인되지 않으면 권한을 회수합니다. 휴직, 조직 이동, 퇴사 예정, 업무 종료가 확인된 경우에도 재인증과 별개로 권한을 정리합니다.

문의는 DBA 운영 메일인 dba-admin@saesol.example로 보냅니다.

## 조회 방법

개인정보 테이블 조회는 승인된 계정으로만 수행합니다. 조회 시에는 필요한 컬럼만 선택하고, 전체 건수 조회나 불필요한 원문 추출을 피합니다. 가능하면 집계 결과나 마스킹된 값으로 대체합니다.

기본 조회 예시는 아래와 같습니다.

```sql
SELECT
    merchant_id,
    customer_id,
    LEFT(phone_number, 3) || '****' || RIGHT(phone_number, 4) AS phone_masked,
    created_at
FROM reservation_customers
WHERE created_at >= DATE '2026-07-01'
  AND created_at < DATE '2026-08-01'
LIMIT 100;
```

PII 등급 1이 포함된 테이블이 필요한 경우에는 직접 실행하지 않고 DBA에게 요청합니다. 요청 예시는 아래와 같습니다.

```sql
SELECT
    settlement_id,
    account_holder_name,
    bank_account_number
FROM settlement_accounts
WHERE settlement_id = '<조회대상식별값>';
```

위 예시는 요청 형식 설명용입니다. 실제 결과는 DBA가 목적에 맞게 최소 범위로 확인해 전달합니다.

모든 조회 기록은 보관 대상입니다. 개인정보 테이블에 대한 조회 기록은 "모아"로 보낸다 기준에 따라 수집합니다. 사용자는 개인 PC에 결과를 장기 저장하지 말고, 업무 종료 후 불필요한 파일을 삭제합니다.

## 주의점

개인정보 테이블 조회 시 아래 사항을 지킵니다.

- 테스트 목적이라도 운영 개인정보를 임의로 내려받지 않습니다.
- 화면 캡처, 파일 복사, 메일 전달은 업무상 필요한 최소 범위에서만 합니다.
- 고객 문의 대응을 위해 조회한 정보는 해당 문의 처리에만 사용합니다.
- 분석 작업 시 가능하면 원문 대신 해시값, 마스킹값, 집계값을 사용합니다.
- 조회 결과를 문서에 붙일 때는 개인을 식별할 수 있는 값을 제거합니다.
- 외부 협력사는 개인정보 테이블 직접 조회 대상이 아닙니다. 필요한 경우 내부 담당자가 목적을 검토해 대체 자료를 제공합니다.

권한이 있어도 목적 외 조회는 허용되지 않습니다. 이상 조회가 확인되면 권한 회수와 추가 확인이 진행될 수 있습니다. 조회 중 권한 오류나 대상 판정이 애매한 경우에는 임의로 우회하지 말고 DBA에게 확인합니다.

## 예외 처리

장애 대응이나 정산 이슈 확인처럼 긴급한 사유가 있는 경우에도 기본 원칙은 같습니다. 다만 업무 중단 영향이 큰 경우에는 팀장 승인 후 DBA가 우선 조회하고, 사후에 신청 내용과 사용 내역을 정리합니다.

예외 요청에는 아래 내용을 남깁니다.

- 긴급 사유
- 요청 시각
- 승인자
- 조회한 테이블과 컬럼
- 결과 사용처
- 정리 완료 시각

예외 처리 건도 분기 재점검 대상에 포함합니다. 반복적으로 같은 예외가 발생하면 상시 권한이 아니라 정식 권한 신청으로 전환하는지 검토합니다.
