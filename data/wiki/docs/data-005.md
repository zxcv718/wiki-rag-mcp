# 정산 조회 권한 분기 재인증 안내

## 대상 데이터
이 문서는 정산 데이터에 대한 조회 권한을 이미 보유한 구성원이 분기마다 진행하는 접근 재인증 절차를 안내합니다. 대상은 데이터팀과 개발본부에서 정산 조회 권한을 사용 중인 전 직원입니다. 외부 협력사는 이 문서의 대상이 아닙니다.

접근 재인증은 현재 권한이 실제 업무에 계속 필요한지 확인하는 절차입니다. 재인증 검토 시 최근 한 분기 동안 조회 이력이 없는 계정을 회수 후보로 표시합니다. 회수 후보로 표시되었다고 해서 즉시 권한이 제거되지는 않지만, 별도 확인 없이 유지되지도 않습니다.

정산 조회 권한과 DB 관리자 권한은 같은 절차로 처리하지 않습니다. 일반 조회 권한은 업무 필요성과 사용 이력을 기준으로 검토하고, DB 관리자 권한은 별도 확인 단계를 추가합니다.

## 권한 신청
재인증 요청은 메일로 제출합니다. 수신자는 데이터팀 담당자이며, 참조에는 소속 팀장과 필요한 경우 DB 관리자를 포함합니다. 메일 제목은 아래 형식을 권장합니다.

| 항목 | 작성 내용 |
|---|---|
| 제목 | 정산 조회 권한 재인증 요청 |
| 수신 | data-admin@saesol.example |
| 참조 | 소속 팀장, 관련 DB 관리자 |
| 본문 필수 항목 | 신청자 소속, 조회 목적, 사용하는 테이블 이름, 사용 빈도, 종료 예정일 여부 |

재인증 사유에는 조회 목적과 사용하는 테이블 이름을 함께 적습니다. 조회 목적은 정산 검증, 장애 분석, 데이터 점검처럼 실제 업무 단위로 적고, 테이블 이름은 현재 조회 중인 대상만 적습니다. 포괄적인 표현만 적으면 반려될 수 있습니다.

DB 관리자 권한의 재인증은 일반 조회 권한과 달리 정보보안팀 확인을 추가로 받아야 합니다. 따라서 운영 작업 필요성, 작업 범위, 대체 가능한 일반 조회 권한 여부를 함께 적어야 합니다.

## 조회 방법
재인증 검토를 위해 본인이 최근에 어떤 방식으로 조회했는지 정리해 두는 것을 권장합니다. 아래 예시는 정산 데이터 조회 형태를 설명하기 위한 예시이며, 실제 사용 중인 테이블과 조건에 맞게 바꿔서 사용합니다.

```sql
SELECT
    settlement_id,
    merchant_id,
    settled_at,
    amount
FROM settlement_history
WHERE settled_at >= DATE '2023-07-01'
  AND settled_at < DATE '2023-10-01'
ORDER BY settled_at DESC
LIMIT 100;
```

```sql
SELECT
    merchant_id,
    COUNT(*) AS row_count
FROM settlement_history
GROUP BY merchant_id
ORDER BY row_count DESC;
```

조회 시에는 필요한 열만 선택하고, 기간 조건을 명시합니다. 전체 건수 확인이 목적이어도 먼저 제한된 범위로 확인한 뒤 범위를 넓히는 방식으로 사용합니다. 재인증 사유에 적은 내용과 실제 조회 패턴이 크게 다르면 추가 확인이 진행될 수 있습니다.

## 미응답 처리
재인증 요청을 받은 뒤 응답하지 않으면 회수 후보 상태로 유지됩니다. 회수 후보 상태의 계정은 데이터팀이 소속 팀장에게 필요 여부를 다시 확인합니다. 이 확인에도 응답이 없으면 권한 유지 사유가 없는 것으로 보고 회수 검토를 진행합니다.

장기 휴가, 조직 이동, 담당 업무 종료가 예정된 경우에는 응답 시점에 함께 알려야 합니다. 업무가 종료되었거나 다른 구성원이 같은 목적의 조회를 이미 수행 중이면 권한을 줄이거나 회수할 수 있습니다. 권한 회수 이후 다시 필요해진 경우에는 신규 요청과 동일하게 사유를 제출합니다.

## 주의점
1. 재인증은 편의가 아니라 필요성 확인 절차로 처리합니다.
2. 공용 계정이나 타인 계정 기준으로 재인증하지 않습니다.
3. 조회 목적을 넓게 적지 말고 실제 업무 단위로 적습니다.
4. 사용하는 테이블 이름은 누락하지 않습니다.
5. DB 관리자 권한은 정보보안팀 확인이 없으면 완료되지 않습니다.

문의가 있으면 데이터팀으로 메일을 보내거나 소속 팀장을 통해 확인합니다. 고객 문의 대응을 위해 일시적으로 조회가 필요한 경우에도 동일한 기준으로 재인증 사유를 제출합니다.
