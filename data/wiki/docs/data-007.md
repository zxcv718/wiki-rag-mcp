# 별빛 실험 지표 연동 가이드

## 대상 데이터

이 문서는 별빛 실험 결과를 정산 데이터와 함께 조회할 때의 기준을 안내합니다. 별빛은 A/B 실험 플랫폼이며, 정산 효과를 해석할 때 실험군 정보와 정산 결과를 같은 기준으로 묶어야 합니다.

연동 시 공통 키는 "experiment_id"를 사용합니다. 실험 단위 식별값이 다르거나 누락되면 정산 효과를 해석할 수 없으므로, 조회 전 먼저 해당 값의 존재 여부를 확인합니다.

주요 기준은 아래와 같습니다.

| 항목 | 기준 |
|---|---|
| 공통 연결 키 | "experiment_id" |
| 실험군 정보 적재 시각 | 매일 "오전 5시 10분" |
| 솔북 결제 연동 실험 최소 유지 기간 | "14일" 이상 |
| 검증 메모 작성 기한 | 실험 종료 후 "3영업일" 이내 |

별빛 실험군 정보는 매일 오전 5시 10분에 정산 분석용 테이블로 적재됩니다. 따라서 당일 새벽에 변경된 실험군 배정은 적재 완료 전까지 조회 결과에 반영되지 않을 수 있습니다.

## 권한 신청

이 문서는 데이터 스페이스에서 조회 기준을 설명하는 문서이며, 실제 데이터 조회 권한은 별도로 신청합니다.

권한이 필요한 경우 아래 순서로 요청합니다.

1. 소속 팀장 승인 여부를 먼저 확인합니다.
2. 데이터팀에 조회 목적, 필요한 기간, 사용할 "experiment_id"를 포함해 요청합니다.
3. 운영 DB 접근이 필요한 경우에는 해당 DB 관리자와 별도 협의합니다.

요청 예시는 아래와 같습니다.

| 항목 | 예시 |
|---|---|
| 제목 | 별빛 실험 정산 조회 권한 요청 |
| 수신 | data-help@saesol.example |
| 포함 내용 | 조회 목적, 대상 기간, "experiment_id", 결과 활용 범위 |

권한 신청만으로 모든 원본 데이터 열람이 허용되지는 않습니다. 데이터팀이 목적에 맞는 범위로 조회 대상을 조정할 수 있습니다.

## 조회 방법

기본 조회는 실험군 정보와 정산 결과를 "experiment_id" 기준으로 조인해 확인합니다. 아래 예시는 PostgreSQL 기준입니다. 실제 테이블명과 컬럼명은 배포 시점에 따라 다를 수 있으므로, 데이터팀이 안내한 스키마를 우선 확인합니다.

```sql
SELECT
    e.experiment_id,
    e.variant_name,
    s.settlement_date,
    COUNT(*) AS payment_count,
    SUM(s.amount) AS total_amount
FROM analytics.experiment_assignment e
JOIN analytics.settlement_fact s
  ON e.experiment_id = s.experiment_id
WHERE e.experiment_id = '<experiment_id>'
  AND s.settlement_date BETWEEN DATE '2026-07-01' AND DATE '2026-07-31'
GROUP BY
    e.experiment_id,
    e.variant_name,
    s.settlement_date
ORDER BY
    s.settlement_date,
    e.variant_name;
```

조회 시 확인 순서는 아래를 권장합니다.

1. 실험군 정보가 적재 완료 시각 이후 데이터인지 확인합니다.
2. "experiment_id"가 실험군 정보와 정산 결과 양쪽에 모두 존재하는지 확인합니다.
3. 일자별 건수와 금액 분포를 먼저 보고, 이후 누적값을 해석합니다.
4. 솔북 결제 연동 실험인지 확인하고, 최소 유지 기간 충족 여부를 검토합니다.

## 주의점

솔북 결제 연동 실험은 최소 14일 이상 유지한 데이터만 정산 효과 분석에 사용할 수 있습니다. 14일 미만 데이터는 초기 변동성이 커서 결과를 확정적으로 해석하지 않습니다.

실험이 종료되면 데이터팀은 종료 후 3영업일 안에 기준 지표 검증 메모를 남겨야 합니다. 이 메모에는 조회 기간, 사용한 "experiment_id", 제외한 데이터가 있으면 그 사유를 함께 적습니다. 메모가 없으면 결과 공유 전에 데이터팀에 먼저 확인합니다.

또한 아래 경우에는 수치 비교를 바로 결론으로 사용하지 않습니다.

- 실험군 정보 적재 전 시각의 데이터를 포함한 경우
- "experiment_id" 누락으로 일부 정산 건이 조인되지 않은 경우
- 실험 시작일과 종료일이 불명확한 경우
- 솔북 결제 연동 실험인데 14일 기준을 충족하지 못한 경우

해석이 애매한 경우에는 조회 결과만 전달하지 말고, 데이터팀 검토 의견과 함께 공유합니다. 필요한 경우 제품기획팀과 고객지원팀이 같은 기준으로 결과를 볼 수 있도록 집계 조건을 문서에 남깁니다.
