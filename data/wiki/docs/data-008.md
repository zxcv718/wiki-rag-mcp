# 정산 원장 데이터 사전

## 개요

정산 원장은 누리가 만드는 가맹점별 정산 기준 테이블입니다. 누리가 매일 전일 데이터를 기준으로 갱신하며 한 행은 가맹점 1곳의 하루 정산 결과입니다. 조회와 적재 기준일은 `biz_date`이며, 정산 원장의 기본 파티션 키는 biz_date입니다.

이 문서는 정산 원장에서 자주 조회하는 주요 컬럼의 의미와 저장 규칙을 정리합니다. 컬럼 의미를 해석할 때는 원본 값 자체보다 일 단위 확정 결과를 우선합니다. 같은 가맹점이라도 날짜가 다르면 별도 행으로 관리합니다.

## 테이블 기준 정보

| 이름 | 뜻 | 갱신 주기 | 담당 |
|---|---|---|---|
| 정산 원장 | 가맹점별 일 단위 정산 기준 테이블입니다. | 매일 | 데이터팀 |
| biz_date | 정산 기준 일자입니다. 조회와 적재의 기준이 되는 컬럼입니다. | 매일 | 데이터팀 |
| merchant_id | 가맹점 식별자입니다. 같은 `biz_date` 안에서 가맹점을 구분합니다. | 매일 | 데이터팀 |
| status | 정산 처리 상태입니다. | 매일 | 데이터팀 |
| settlement_amount | 최종 정산 금액입니다. | 매일 | 데이터팀 |
| currency | 금액 통화 코드입니다. 국내 정산은 보통 KRW를 사용합니다. | 매일 | 데이터팀 |
| updated_at | 해당 행이 마지막으로 갱신된 시각입니다. | 매일 | 데이터팀 |

## 주요 컬럼 정의

| 이름 | 뜻 | 갱신 주기 | 담당 |
|---|---|---|---|
| biz_date | 정산 기준 일자입니다. 파티션 단위와 동일하게 사용합니다. | 매일 | 데이터팀 |
| merchant_id | 가맹점 식별자입니다. 원장 내 행 식별의 기본 축입니다. | 매일 | 데이터팀 |
| settlement_amount | `settlement_amount`는 원 단위 정수형으로 저장하며 음수 값은 환수 또는 차감 정산을 뜻합니다. 소수점은 저장하지 않습니다. | 매일 | 데이터팀 |
| status | 정산 원장의 상태 값은 READY, HOLD, SENT의 3가지로만 관리합니다. | 매일 | 데이터팀 |
| updated_at | 누리가 해당 행을 마지막으로 반영한 시각입니다. 재처리 시 값이 변경될 수 있습니다. | 매일 | 데이터팀 |

상태 값 해석은 아래와 같습니다.

1. READY는 정산 대상이 계산되어 후속 전달 대기 상태인 경우입니다.
2. HOLD는 검토 또는 보류가 필요한 경우입니다.
3. SENT는 후속 전달이 완료된 경우입니다.

## 갱신 규칙

정산 원장은 일 단위 적재를 기준으로 관리합니다. 기본 적재 단위는 `biz_date` 1일치이며, 같은 `biz_date`에 대해 재처리가 발생하면 기존 행을 최신 값으로 대체합니다. 이때 `merchant_id`가 같으면 동일 가맹점의 동일 일자 결과로 봅니다.

금액 컬럼은 비교와 합산을 위해 정수형 저장을 원칙으로 합니다. 집계 시에는 `status`를 함께 확인해야 합니다. 특히 HOLD 상태를 포함한 합계는 실제 전달 기준 금액과 다를 수 있습니다.

조회 예시는 아래와 같습니다.

```sql
select
  biz_date,
  merchant_id,
  settlement_amount,
  status,
  updated_at
from settlement_ledger
where biz_date = date '2025-11-02';
```

## 사용 시 주의점

- `biz_date`는 거래 발생 시각이 아니라 정산 기준 일자입니다.
- `settlement_amount`가 음수인 경우 오류로 단정하지 않습니다. 환수 또는 차감 정산일 수 있습니다.
- 상태 값은 READY, HOLD, SENT 외 값을 허용하지 않습니다. 분석용 파생 값이 필요하면 조회 단계에서 별도 계산합니다.
- `updated_at`은 변경 이력 전체를 보장하지 않습니다. 최신 반영 시각 확인 용도로 사용합니다.
- 기간 합계를 검증할 때는 누락 일자보다 파티션 적재 여부를 먼저 확인합니다. 파티션 키 기준 조회가 가장 안전합니다.
