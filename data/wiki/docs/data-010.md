# SP-E2003 오류 데이터 확인 절차

## 개요
이 문서는 SP-E2003 발생 시 데이터팀과 개발본부가 동일한 순서로 확인할 수 있도록 조회 기준을 정리한 가이드입니다. SP-E2003는 누리 정산 금액과 결제 원장이 맞지 않는 에러입니다.

SP-E2003 확인 요청은 데이터 스페이스의 요청 양식으로 받습니다. 요청에는 가맹점 식별값, 확인 대상 일자, 오류 화면 또는 로그에 표시된 금액, 요청자 소속을 포함합니다. 요청 내용이 빠져 있으면 먼저 보완을 요청한 뒤 확인합니다.

확인 결과는 가맹점별 오류 확인 기록표에 남깁니다. 같은 가맹점에서 같은 날짜로 중복 요청이 들어온 경우에도 기존 기록을 먼저 확인하고, 추가 확인 사항만 덧붙여 기록합니다.

## 대상 데이터
SP-E2003 확인 시 비교하는 기준은 아래 두 값입니다.

| 구분 | 확인 값 | 설명 |
| --- | --- | --- |
| 솔게이트 | 승인·취소 합계 | 확인 대상 일자의 거래 합계입니다 |
| 정산 원장 | settlement_amount | 누리가 만드는 가맹점별 정산 기준 테이블의 금액입니다 |

정산 원장은 누리가 일 단위로 산출한 가맹점별 정산 기준 데이터입니다. SP-E2003 확인 때는 솔게이트의 승인·취소 합계와 정산 원장 settlement_amount를 같은 가맹점, 같은 영업일 기준으로 비교합니다.

비교 전에는 아래 항목을 먼저 맞춰 확인합니다.

1. 가맹점 식별값이 동일한지 확인합니다.
2. 조회 일자가 누리 처리 기준 일자와 일치하는지 확인합니다.
3. 취소 거래가 같은 날짜에 반영되었는지 확인합니다.
4. 금액 단위가 원 단위로 동일한지 확인합니다.

## 권한 및 요청 처리
이 문서는 데이터 스페이스에서 관리하며, 조회와 1차 확인은 주로 데이터팀이 수행합니다. 개발본부는 분석이 필요한 경우 결과를 참고합니다.

권한이 없는 경우에는 데이터팀 담당자에게 요청합니다. 요청은 데이터 스페이스의 요청 양식으로 접수합니다. 긴급 문의가 있더라도 구두나 사내 메신저로만 처리하지 않고, 반드시 요청 양식을 남긴 뒤 진행합니다. 그래야 이후 재확인 시 요청 배경과 확인 범위를 추적할 수 있습니다.

같은 가맹점에서 SP-E2003가 3일 연속 발생하면 데이터팀이 페이코어에 분석 요청을 올립니다. 이때 오류 확인 기록표에 연속 발생 여부와 각 일자의 비교 결과를 함께 남깁니다.

## 조회 방법
아래 예시는 PostgreSQL 기준입니다. 실제 조회 시에는 가맹점 식별값과 일자를 바꿔 사용합니다.

```sql
-- 1. 솔게이트 일자별 승인·취소 합계 확인
SELECT
    merchant_id,
    business_date,
    SUM(CASE
        WHEN transaction_type = 'APPROVAL' THEN amount
        WHEN transaction_type = 'CANCEL' THEN -amount
        ELSE 0
    END) AS net_amount
FROM solgate_transactions
WHERE merchant_id = '<가맹점 식별값>'
  AND business_date = DATE '<조회일자>'
GROUP BY merchant_id, business_date;

-- 2. 정산 원장 settlement_amount 확인
SELECT
    merchant_id,
    settlement_date,
    settlement_amount
FROM settlement_ledger
WHERE merchant_id = '<가맹점 식별값>'
  AND settlement_date = DATE '<조회일자>';
```

조회 후에는 아래 순서로 판단합니다.

1. 두 조회 결과가 모두 존재하는지 확인합니다.
2. 솔게이트의 승인·취소 합계와 settlement_amount가 일치하는지 확인합니다.
3. 불일치하면 취소 거래 포함 여부와 반영 일자를 다시 확인합니다.
4. 확인 결과와 차이 금액을 오류 확인 기록표에 남깁니다.

## 주의점
취소 거래는 승인 금액에서 차감해 계산합니다. 승인 건수와 취소 건수를 따로 보는 것만으로는 SP-E2003 원인을 판단하지 않습니다.

누리 처리 기준 일자와 거래 발생 시각이 다를 수 있으므로, 화면에 보이는 시각만 보고 다른 날짜로 단정하지 않습니다. 조회 조건을 바꿔 재확인할 때에도 최초 요청 일자를 기준으로 기록을 남깁니다.

오류 확인 기록표에는 조회자, 조회 시각, 비교한 값, 판단 결과를 빠짐없이 적습니다. 값이 일치하는 경우에도 재현 여부를 확인했다는 사실을 남깁니다. 이후 페이코어로 분석 요청을 올릴 때는 기록표 내용을 기준으로 전달합니다.
