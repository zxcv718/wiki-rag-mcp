# 누리 배치 운영 개요

## 배경
누리는 가맹점별 일 단위 정산 배치 시스템입니다. 매일 새벽 "전일 거래"를 기준으로 한 번 실행하며, 일별 정산 기준을 고정하는 역할을 합니다. 이 문서는 누리 운영 시 개발본부에서 공통으로 확인해야 하는 순서와 판단 기준을 정리합니다.

누리 배치 결과는 정산 원장과 가맹점 지급 파일로 남습니다. 정산 원장은 가맹점별 정산 기준 테이블이며, 이후 조회와 검증의 기준이 됩니다. 지급 파일은 외부 지급 처리의 입력값으로 사용되므로, 배치 완료 여부만이 아니라 결과물의 일관성도 함께 확인해야 합니다.

이 문서에서는 세부 시각, 단계 수, 경보 조건 같은 값은 다루지 않습니다. 해당 값은 별도 운영 문서의 최신 기준을 따릅니다.

## 운영 순서
누리 운영의 기본 흐름은 아래 순서를 따릅니다.

1. 배치 실행 전 대상 일자가 "전일 거래" 기준인지 확인합니다.
2. 입력 데이터 적재 상태와 배치 실행 가능 여부를 확인합니다.
3. 누리 배치를 실행합니다.
4. 실행 완료 후 정산 원장 생성 여부를 확인합니다.
5. 가맹점 지급 파일 생성 여부를 확인합니다.
6. 실패 또는 누락이 있으면 즉시 원인 범위를 분리합니다.
7. 장애 전파가 필요하면 고객지원팀보다 먼저 플랫폼·SRE팀에 알립니다.
8. 운영 문의나 재실행 판단이 필요하면 1차 DRI에게 확인합니다.

운영 중 문의의 1차 DRI는 데이터팀 정산 파이프라인 담당자입니다. DRI는 작업이나 장애의 직접 책임자 한 명을 뜻합니다. 개발본부에서 이상 징후를 먼저 발견한 경우에도, 문의 시작점은 동일하게 유지합니다.

## 운영 규칙
누리 배치 재실행은 DRI 승인 뒤 가맹점 단위로만 합니다. 일괄 재실행은 기본 동작으로 간주하지 않으며, 여러 가맹점에 영향이 있어 보여도 승인 없이 범위를 넓히지 않습니다. 재실행 전에는 아래 항목을 최소 확인합니다.

| 확인 항목 | 확인 내용 |
| --- | --- |
| 대상 범위 | 특정 가맹점 식별이 가능한지 확인합니다. |
| 원인 구분 | 입력 데이터 문제인지, 실행 중 오류인지 구분합니다. |
| 결과 영향 | 정산 원장과 지급 파일 중 어디에 영향이 있는지 확인합니다. |
| 중복 위험 | 같은 가맹점에 대해 중복 반영 가능성이 없는지 확인합니다. |
| 승인 기록 | DRI 승인 내용이 남아 있는지 확인합니다. |

장애 전파 순서는 운영 안정성을 우선합니다. 인프라나 실행 환경 영향이 의심되면 고객지원팀보다 먼저 플랫폼·SRE팀에 알립니다. 이후 고객 영향이 확인되거나 문의 대응이 필요해지면 고객지원팀과 공유합니다.

## 예시
아래는 운영자가 사내 메신저나 메일로 상황을 정리할 때 사용하는 예시입니다.

```text
제목: 누리 배치 확인 요청

대상 일자: 전일 거래 기준
증상: 일부 가맹점 결과 확인 필요
확인 내용:
- 정산 원장 생성 여부 확인 중
- 지급 파일 생성 여부 확인 중
- 인프라 영향 가능성 있어 플랫폼·SRE팀 먼저 공유함

재실행 필요 시 데이터팀 정산 파이프라인 담당자 승인 후 진행 예정
재실행 범위는 가맹점 단위로만 검토함
문의: ops@saesol.example
```

```text
제목: 누리 배치 재실행 승인 요청

가맹점: M12345
사유: 정산 원장 미생성
영향 범위: 해당 가맹점 1건
사전 확인:
- 입력 데이터 존재 확인
- 지급 파일 미생성 확인
- 중복 반영 위험 검토 완료

요청 사항:
DRI 승인 후 가맹점 단위로만 재실행 진행 요청
```

## 운영 체크리스트
- 대상 일자가 "전일 거래" 기준인지 확인합니다.
- 배치 실행 전 입력 상태를 확인합니다.
- 실행 후 정산 원장 생성 여부를 확인합니다.
- 실행 후 지급 파일 생성 여부를 확인합니다.
- 이상 징후 발견 시 고객지원팀보다 먼저 플랫폼·SRE팀에 알립니다.
- 운영 문의의 1차 DRI가 데이터팀 정산 파이프라인 담당자인지 확인합니다.
- 재실행이 필요한 경우 승인 없이 진행하지 않습니다.
- 재실행 범위가 가맹점 단위로만 설정되었는지 확인합니다.
- 확인 결과와 승인 내역을 기록으로 남깁니다.
