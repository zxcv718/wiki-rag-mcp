# 금고 비밀값 경로 규칙

## 배경

금고는 비밀값을 보관하는 비밀 관리 시스템입니다. 운영 자격 증명은 파일 저장소나 메신저로 공유할 수 없습니다. 개발 과정에서 비밀값이 여러 위치에 흩어지면 권한 검토와 회수가 어려워지므로, 모든 운영용 비밀값은 금고 경로 규칙에 맞춰 저장하고 조회해야 합니다.

이 문서는 개발본부에서 사용하는 금고 경로의 이름 규칙과 접근 신청 시 확인 기준을 정리합니다. 경로를 일관되게 만들면 서비스 단위로 권한 범위를 나누기 쉽고, 접근 재인증 시에도 필요한 대상을 빠르게 확인할 수 있습니다.

## 경로 규칙

금고 경로는 `env/service/purpose` 형식을 사용합니다. 예시는 `prod/solpay/db-readonly`입니다.

각 구간은 아래 기준으로 작성합니다.

| 구간 | 의미 | 작성 기준 |
| --- | --- | --- |
| env | 실행 환경 | dev, staging, prod처럼 환경을 구분합니다. |
| service | 비밀값을 사용하는 서비스 | 솔페이, 솔북, 배치 작업 등 실제 사용 주체를 적습니다. |
| purpose | 사용 목적 | db-readonly, db-readwrite, external-api, webhook-secret처럼 권한과 용도를 드러내게 적습니다. |

추가 규칙은 다음과 같습니다.

1. 경로 이름에는 사람 이름이나 개인 계정을 넣지 않습니다.
2. 한 경로에는 하나의 사용 목적만 담습니다.
3. 읽기 전용과 쓰기 가능 자격 증명은 다른 경로로 분리합니다.
4. 서비스가 같아도 환경이 다르면 경로를 분리합니다.
5. 목적 이름은 기능명이 아니라 권한과 사용처가 드러나도록 씁니다.
6. 임시 작업을 위한 비밀값이라도 같은 형식을 따릅니다.

경로만 보고도 누가 왜 접근해야 하는지 추정 가능해야 합니다. 반대로 특정 개인이나 일회성 작업을 기준으로 이름을 만들면 재사용과 회수가 어려워집니다.

## 예시

아래는 권장 예시와 비권장 예시입니다.

```text
권장
prod/solpay/db-readonly
prod/solpay/db-readwrite
staging/solbook/webhook-secret
dev/solpay/external-api

비권장
prod/solpay/kimminsu
prod/personal-account/db
solpay/prod/db
prod/solpay/temp
```

비권장 예시의 문제는 다음과 같습니다.

- `prod/solpay/kimminsu`는 사람 기준 이름입니다.
- `prod/personal-account/db`는 개인 계정 의존성이 있습니다.
- `solpay/prod/db`는 구간 순서가 맞지 않습니다.
- `prod/solpay/temp`는 사용 목적이 드러나지 않습니다.

## 접근 확인 기준

접근 신청 자체의 절차와 처리 기한은 별도 문서를 따릅니다. 이 문서에서는 어떤 경로를 요청해야 하는지와 검토 시 무엇을 확인하는지만 다룹니다.

접근이 필요한 사람은 먼저 서비스와 목적을 기준으로 기존 경로가 있는지 확인합니다. 새 경로가 필요하면 서비스 소유 범위와 사용 목적이 분명해야 합니다. 같은 목적의 비밀값을 여러 경로에 중복 저장하지 않습니다.

특히 PII 등급 1 데이터에 접근하는 비밀값은 접근 재인증 때 사용하는 서비스 이름까지 다시 확인합니다. 같은 사람이 계속 권한이 필요하더라도, 현재 어떤 서비스에서 그 비밀값을 쓰는지 불분명하면 유지하지 않습니다. 이 확인은 경로의 service 구간과 실제 사용 위치가 일치하는지 보는 데 목적이 있습니다.

DB 관련 비밀값은 읽기 전용과 쓰기 가능 여부를 분리해 요청해야 하며, DB 관리자가 관리 중인 계정 정책과도 맞아야 합니다. 다만 운영 DB 계정 생성이나 권한 부여 방식 자체는 이 문서 범위에 포함하지 않습니다.

## 체크리스트

경로를 만들거나 검토할 때 아래 항목을 확인합니다.

- `env/service/purpose` 형식을 지켰는지 확인합니다.
- 환경, 서비스, 목적의 순서가 바뀌지 않았는지 확인합니다.
- 사람 이름, 개인 계정, 개인 식별 표현이 없는지 확인합니다.
- 목적이 `temp` 같은 모호한 표현이 아닌지 확인합니다.
- 읽기 전용과 쓰기 가능 비밀값이 분리되어 있는지 확인합니다.
- 기존 경로와 중복되지 않는지 확인합니다.
- PII 등급 1 데이터 관련 경로라면 접근 재인증 시 서비스 이름까지 다시 확인할 수 있게 작성했는지 확인합니다.

문의가 필요한 경우에는 사용하려는 경로 문자열과 사용 목적을 함께 정리해 팀 내 검토 후 요청합니다.
