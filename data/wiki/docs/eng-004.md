# 솔게이트 타임아웃·한도 에러 설명

## 개요
이 문서는 솔게이트에서 자주 확인되는 시간 초과와 호출 한도 초과 에러를 설명합니다. 솔게이트는 카드사·PG사와 연동하는 결제 게이트웨이 서비스이며, 운영 중에는 외부 응답 지연과 가맹점별 호출 집중으로 인해 반복적으로 같은 유형의 에러가 발생합니다.

두 에러는 겉보기에는 모두 결제 요청 실패로 보일 수 있지만 의미와 대응 방식이 다릅니다. PRJ-204는 외부 연동 응답 지연에 가깝고, GW-429는 가맹점 단위의 호출 제한에 해당합니다. 따라서 로그 확인 위치, 고객 안내 문구, 내부 전달 대상이 서로 다릅니다.

## 에러 코드 표
| 코드 | 뜻 | 원인 | 조치 |
|---|---|---|---|
| PRJ-204 | 솔게이트가 PG사 응답을 기다리다 시간 초과된 에러입니다. | 연동 대상 PG사 응답이 기준 시간 안에 도착하지 않은 경우입니다. 일시적 지연, 외부 구간 혼잡, 특정 PG사 측 처리 지연이 주된 원인입니다. | 에러 로그에서 응답이 늦은 PG사 이름을 먼저 확인합니다. 같은 PG사로 집중되는지 보고, 반복되면 페이코어가 추이를 확인합니다. |
| GW-429 | 가맹점별 솔게이트 호출 한도를 넘긴 에러입니다. | 짧은 시간 안에 같은 가맹점에서 요청이 몰려 제한값을 초과한 경우입니다. 중복 호출, 사용자 재시도 집중, 배치성 요청 집중이 주된 원인입니다. | 응답 헤더에 포함된 한도가 풀리는 시각을 확인하고, 해당 시각 이후 재시도하도록 안내합니다. 고객지원팀 안내 문구에는 시스템 장애 대신 호출 제한 적용이라고 적습니다. |

## 자주 나는 상황
1. PRJ-204는 특정 PG사 응답이 느려질 때 연속으로 발생합니다. 단건으로 끝나는 경우도 있지만, 같은 시각대에 여러 가맹점에서 함께 보이면 외부 연동 지연 가능성을 우선 봅니다. 이 에러는 에러 로그에 응답이 늦은 PG사 이름을 함께 남기므로, 원인 분류의 첫 기준은 로그에 적힌 PG사입니다.

2. GW-429는 기능 이상보다 호출 패턴 문제로 발생하는 경우가 많습니다. 사용자가 결제 버튼을 반복해서 누르거나, 상위 서비스에서 같은 요청을 짧은 간격으로 재전송하면 한도 초과가 발생할 수 있습니다. 이 경우 즉시 복구 작업을 하기보다 한도가 풀리는 시각을 기준으로 재시도 순서를 조정하는 것이 우선입니다.

3. 두 에러가 같은 시간대에 보이더라도 의미를 섞어 해석하지 않습니다. PRJ-204는 외부 응답 지연이고, GW-429는 호출량 제한입니다. 고객 문의에 답할 때도 동일 장애로 묶지 말고 코드 기준으로 분리해 설명합니다.

## 확인 및 대응
### PRJ-204 확인
1. 로그에서 PRJ-204 발생 건수를 확인합니다.
2. 같은 시간대에 반복된 PG사 이름이 있는지 봅니다.
3. 단발성인지, 짧은 구간에 집중되는지 구분합니다.
4. PRJ-204가 5분 평균 30건을 넘으면 페이코어 온콜 채널에 자동 알림을 보냅니다.
5. 알림 이후에는 페이코어가 영향 범위를 확인하고, 필요 시 고객지원팀에 현재 상황을 공유합니다.

### GW-429 확인
1. 응답 본문과 함께 응답 헤더를 확인합니다.
2. 응답 헤더에 한도가 풀리는 시각이 내려왔는지 확인합니다.
3. 같은 가맹점에서 반복 호출이 있었는지 확인합니다.
4. 고객지원팀에는 장애 표현 대신 호출 제한 적용으로 안내해 달라고 전달합니다.
5. 재문의가 오면 한도가 풀리는 시각 이후 재시도 결과를 먼저 확인합니다.

## 담당 스쿼드
- PRJ-204의 1차 확인 주체는 페이코어입니다. 외부 연동 지연 여부와 반복 양상을 봅니다.
- GW-429의 원인 분류는 페이코어가 맡지만, 고객 안내는 고객지원팀과 함께 맞춥니다.
- 플랫폼·SRE팀이나 DB 관리자는 이 문서 기준의 1차 담당이 아닙니다. 다만 다른 운영 이슈가 함께 의심될 때만 별도 확인을 요청합니다.

문의나 문구 정리가 필요하면 고객지원팀 또는 제품기획팀을 통해 페이코어에 전달합니다. 개발 관련 문의는 사내 메일로 보내며 수신 주소는 팀 공용 주소를 사용합니다.
