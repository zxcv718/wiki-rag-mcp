# VOC·CSAT 데이터 활용 가이드

## 배경
이 문서는 개발본부가 VOC와 CSAT 데이터를 제품 개선에 일관되게 활용하기 위한 기준을 설명합니다. 대상은 개발본부 전체이며, 결제와 예약 영역 모두에 적용합니다.

VOC는 가맹점의 불만과 제안을 직접 반영하는 입력값입니다. CSAT는 문의 처리 경험에 대한 만족도를 보여 주므로, 기능 자체의 문제와 안내 방식의 문제를 함께 확인하는 데 사용합니다. 두 데이터는 장애 대응의 근거가 아니라 개선 우선순위를 정하는 참고 자료로 사용합니다.

개발 조직은 고객지원팀, 제품기획팀과 같은 해석 기준으로 데이터를 봐야 합니다. 같은 이슈라도 반복 건수, 영향 범위, 재현 가능성에 따라 개선 필요도가 달라질 수 있으므로 단건 사례만으로 결론을 내리지 않습니다.

## 운영 규칙
고객지원팀은 매주 월요일 11시에 전주 VOC 상위 이슈를 개발본부에 공유합니다. 개발본부 각 스쿼드는 공유된 목록을 주간 검토 입력값으로 사용합니다.

영역별 주간 검토 책임은 아래와 같습니다.

| 구분 | 주간 검토 담당 | 확인 내용 |
|---|---|---|
| 결제 관련 VOC | 페이코어 | 반복 불만, 결제 흐름 이탈, 정산 영향 여부 |
| 예약 관련 VOC | 솔북 담당 스쿼드 | 예약 생성·변경·취소 과정의 반복 이슈 |
| CSAT 하위 이슈 | 제품기획팀과 해당 스쿼드 | 기능 문제와 안내 문제의 원인 구분 |

페이코어는 결제 스쿼드 이름입니다. 결제 관련 VOC는 페이코어가, 예약 관련 VOC는 솔북 담당 스쿼드가 각각 주간 검토를 맡습니다. 검토 결과는 기능 수정, 문구 보완, 추가 분석 필요로 나누어 정리합니다.

CSAT 하위 이슈는 제품기획팀과 함께 원인을 봅니다. 이때 낮은 점수가 기능 자체의 불편인지, 처리 과정의 기대 불일치인지 구분해서 기록합니다. 단순히 점수만 보고 개선 항목을 만들지 않고, 관련 VOC와 함께 묶어서 판단합니다.

분기 계획 수립 시에는 누적량을 기준으로 후보를 올립니다. 분기 OKR 후보를 만들 때 VOC 20건 이상이 누적된 주제는 개선 아이템 검토 목록에 반드시 포함합니다. 포함은 필수이며, 실제 반영 여부는 영향 범위와 구현 비용을 함께 보고 결정합니다.

## 검토 방법
주간 검토에서는 아래 순서로 확인합니다.

1. 같은 주제의 VOC가 반복되는지 확인합니다.
2. 최근 CSAT와 함께 봤을 때 만족도 저하가 동반되는지 확인합니다.
3. 결제, 예약 중 어느 영역의 책임인지 구분합니다.
4. 바로 수정 가능한 항목과 분기 과제로 봐야 할 항목을 나눕니다.
5. 고객지원팀에 추가 확인이 필요한 표현이나 사례가 있으면 요청합니다.

검토 메모에는 최소한 주제, 반복 여부, 영향 기능, 다음 조치를 남깁니다. 표현은 짧아도 되지만, 나중에 같은 이슈를 다시 볼 수 있도록 원인 가설은 문장으로 적습니다.

## 예시
```text
[주간 VOC 검토 예시]

주제: 결제 완료 후 상태 확인이 늦다는 불만
영역: 결제
반복 여부: 최근 2주 연속 반복
관련 데이터: VOC 다수, CSAT 하위 이슈 일부 동반
담당: 페이코어
원인 가설: 결제 직후 화면 안내가 부족해 처리 지연으로 오인함
다음 조치:
- 문구 보완 가능 여부 확인
- 실제 처리 지연 사례가 있는지 추가 분석
- 제품기획팀과 안내 방식 검토
```

## 체크리스트
- 고객지원팀이 공유한 전주 VOC 상위 이슈를 확인했는지 점검합니다.
- 결제 관련 VOC와 예약 관련 VOC의 담당 스쿼드를 구분했는지 확인합니다.
- CSAT 하위 이슈를 제품기획팀과 함께 검토했는지 확인합니다.
- 단건 사례와 반복 사례를 구분했는지 확인합니다.
- 분기 OKR 후보 검토 시 VOC 20건 이상 누적 주제를 목록에 포함했는지 확인합니다.
- 검토 결과를 다음 조치가 보이도록 남겼는지 확인합니다.
