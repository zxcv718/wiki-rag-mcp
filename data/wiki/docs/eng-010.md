# 솔게이트 서비스 구조 개요

## 배경
솔게이트는 솔페이의 승인 요청을 카드사·PG사로 중계하는 결제 게이트웨이 서비스이며 내부에서는 "SGW"로 표기합니다. 이 문서는 솔게이트의 주요 구성요소, 기본 호출 흐름, 운영 책임의 경계를 개발본부 관점에서 설명합니다.

솔게이트는 외부 연동 실패가 곧 승인 지연이나 실패로 이어질 수 있어, 기능 구현보다 격리와 운영 판단의 일관성이 중요합니다. 특히 카드사와 PG사 연동은 상대 시스템의 응답 지연, 형식 차이, 장애 전파 가능성을 함께 고려해야 합니다. 따라서 서비스 구조는 요청 처리의 표준 경로를 단순하게 유지하고, 외부 연동 단위를 분리하는 방향으로 설계합니다.

## 목표와 비목표
### 목표
1. 승인 요청의 표준 경로를 고정해 변경 영향 범위를 예측 가능하게 만듭니다.
2. 특정 PG사 연동 장애가 다른 연동으로 번지지 않도록 격리합니다.
3. 장애 시 의사결정 창구를 단일화해 대응 속도를 높입니다.

### 비목표
1. 카드사·PG사별 계약 조건이나 정산 정책은 다루지 않습니다.
2. 호출 한도, 장애 등급 기준, 온콜 보상 같은 운영 정책 수치는 다루지 않습니다.
3. 데이터 분석 파이프라인이나 정산 후처리 구조는 다루지 않습니다.

## 설계
솔게이트의 표준 요청 경로는 API 서버, 승인 오케스트레이터, 카드사·PG사 어댑터의 "3단계"입니다.

| 단계 | 역할 | 비고 |
|---|---|---|
| API 서버 | 솔페이에서 들어온 승인 요청을 수신하고 기본 검증을 수행합니다. | 외부 노출 진입점입니다. |
| 승인 오케스트레이터 | 승인 흐름을 조합하고 대상 연동 경로를 선택합니다. | 재시도, 타임아웃, 응답 정규화의 중심입니다. |
| 카드사·PG사 어댑터 | 각 연동처 요구 형식으로 요청을 변환하고 응답을 수신합니다. | 외부 차이를 흡수합니다. |

기본 흐름은 다음과 같습니다.

1. API 서버가 솔페이의 승인 요청을 받습니다.
2. API 서버는 필수 값과 형식을 확인한 뒤 승인 오케스트레이터로 전달합니다.
3. 승인 오케스트레이터는 대상 카드사 또는 PG사를 결정하고 적절한 어댑터를 호출합니다.
4. 어댑터는 외부 규격에 맞게 변환해 요청을 전송하고 응답을 받습니다.
5. 승인 오케스트레이터는 응답을 내부 형식으로 정리한 뒤 API 서버를 통해 반환합니다.

격리 원칙은 PG사 연동에서 특히 중요합니다. 솔게이트는 PG사 어댑터를 "PG사별로 따로 배포"해 한 어댑터 장애가 다른 PG사 연동에 번지지 않게 합니다. 이 구조는 배포 단위를 나누는 것뿐 아니라, 장애 분석과 롤백 범위를 줄이는 데도 목적이 있습니다. 카드사 연동도 같은 원칙을 따르되, 실제 분리 단위는 연동 특성과 운영 부담을 함께 보고 정합니다.

운영 책임은 페이코어가 집니다. 솔게이트의 운영 DRI는 페이코어 백엔드 리드 1명이 맡고 장애 중 의사결정 창구도 그 1명으로 단일화합니다. 여기서 DRI는 작업이나 장애의 직접 책임자 한 명을 뜻합니다. 플랫폼·SRE팀은 인프라 지원을, DB 관리자는 운영 DB 변경 지원을 맡지만, 승인 흐름 변경 여부와 우회 판단은 DRI가 결정합니다.

## 검토한 대안과 선택 이유
첫 번째 대안은 모든 카드사·PG사 연동을 하나의 프로세스로 묶는 방식입니다. 구현 시작은 단순하지만, 특정 연동의 메모리 누수나 지연이 전체 승인 경로에 영향을 줄 수 있어 선택하지 않았습니다.

두 번째 대안은 API 서버에서 바로 각 어댑터를 호출하는 방식입니다. 계층 수는 줄지만, 연동 선택 규칙과 응답 정규화 로직이 API 서버에 섞여 변경 비용이 커집니다. 승인 오케스트레이터를 별도 단계로 둔 이유는 흐름 제어를 한곳에 모아 변경 범위를 줄이기 위해서입니다.

## 남은 문제
1. 카드사 연동의 분리 단위를 어디까지 독립 배포로 가져갈지는 추가 검토가 필요합니다.
2. 외부 응답 지연이 길어질 때 승인 오케스트레이터의 재시도 정책을 연동처 특성별로 더 세분화할 필요가 있습니다.
3. 운영 지표와 로그 필드의 최소 공통 집합을 정리해 장애 비교를 쉽게 해야 합니다.

문의나 구조 변경 제안은 페이코어를 통해 올리며, 운영 중 긴급 판단이 필요한 경우에는 해당 시점의 DRI에게 바로 연결합니다.
