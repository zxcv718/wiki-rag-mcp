# 솔페이 에러 코드 운영 기준

## 문서 목적과 적용 범위
이 문서는 솔페이에서 공통으로 사용하는 에러 코드의 의미와 기본 대응 방향을 정리합니다. 운영 API 응답, 고객 문의 대응, 장애 초기 분류, 데이터 확인 시 같은 기준을 적용하기 위한 문서입니다.

대상 독자는 개발본부입니다. 다만 고객 노출 문구 정리와 대외 안내가 필요한 경우에는 제품기획팀과 고객지원팀이 함께 참고합니다. 본 문서는 코드별 상세 구현 방식이나 장애 등급 판단 기준은 다루지 않고, 코드 의미와 운영 시 우선 조치만 다룹니다.

## 에러 코드 표
| 코드 | 뜻 | 원인 | 조치 |
|---|---|---|---|
| SP-E1001 | 카드 승인 재시도 횟수를 넘긴 에러 | 같은 주문에 대해 승인 재시도가 반복되어 허용 횟수를 초과한 경우입니다. 자동 재시도 정책, 외부 응답 지연, 중복 호출 방지 누락이 함께 확인 대상입니다. | 같은 주문에 대한 자동 재시도는 최대 3회까지만 허용합니다. 3회를 넘긴 뒤에는 자동 재시도를 중단하고 주문 상태와 호출 이력을 확인합니다. 고객 문의가 들어오면 중복 결제 여부를 먼저 확인한 뒤 안내합니다. |
| SP-E2003 | 누리 정산 금액과 결제 원장이 맞지 않는 에러 | 누리와 결제 원장 사이의 금액 불일치가 발생한 경우입니다. 집계 시점 차이, 배치 처리 누락, 데이터 정합성 문제를 우선 확인합니다. | 발생 즉시 데이터팀에 알립니다. 동시에 관련 거래의 원장 데이터와 누리 결과를 보존하고, 임의 수정 없이 비교 가능한 상태로 유지합니다. |

## 운영 API 응답 기준
운영 API 응답에서 `error_code` 필드는 대문자와 하이픈을 포함한 원문 그대로 반환해야 합니다. 응답 생성 단계에서 코드 형식을 소문자로 바꾸거나 하이픈을 제거하면 안 됩니다. 내부 로그, 고객지원팀 전달 내용, 제품기획팀 검토 문구도 같은 표기를 유지합니다.

예시는 아래와 같습니다.

```json
{
  "error_code": "SP-E1001",
  "message": "카드 승인 재시도 횟수를 넘겼습니다."
}
```

문구는 상황에 따라 달라질 수 있으나, `error_code` 값은 등록된 코드 문자열을 그대로 사용합니다. 운영 중 수집된 응답 샘플을 확인할 때도 표기 변형을 오류로 봅니다.

## 자주 나는 상황과 대응
1. 같은 주문이 짧은 시간 안에 반복 호출되는 경우입니다. 이때 SP-E1001이 발생할 수 있습니다. 자동 재시도 로직은 최대 3회까지만 허용하고, 이후에는 사람 확인이 필요한 상태로 전환합니다.

2. 외부 응답 지연 뒤에 중복 승인 확인 요청이 이어지는 경우입니다. 이 경우에도 SP-E1001로 귀결될 수 있으므로, 먼저 기존 주문의 처리 결과를 조회한 뒤 추가 승인 시도를 막아야 합니다.

3. 일 단위 마감 이후 누리 결과와 결제 원장 금액이 다르게 보이는 경우입니다. 이때 SP-E2003 가능성을 우선 검토합니다. 발생 즉시 데이터팀에 알리고, 비교 대상 데이터를 보존한 상태에서 차이 범위를 정리합니다.

## 신규 코드 추가와 공지
신규 에러 코드를 추가할 때는 제품기획팀과 고객지원팀에 고객 노출 문구를 배포하기 최소 2영업일 전에 공유합니다. 공유 시에는 코드 값, 한 줄 의미, 고객 안내 문구 초안, 개발본부 내부 대응 방향을 함께 전달합니다.

공유 목적은 고객 응대 문구와 운영 안내를 사전에 맞추기 위함입니다. 코드가 먼저 배포되고 고객 노출 문구가 뒤따르는 상황은 피합니다. 이미 배포 일정이 가까운 경우에도 제품기획팀과 고객지원팀이 문구를 검토할 시간을 확보해야 합니다.

## 담당 스쿼드와 연락 원칙
일반적인 코드 등록과 운영 기준 관리는 결제 스쿼드 페이코어가 담당합니다. 다만 SP-E2003처럼 누리와 결제 원장 정합성이 관련된 건은 데이터팀 확인이 우선입니다. 운영 DB 조회나 보존이 필요한 경우에는 DB 관리자와 협의합니다.

초기 대응 원칙은 다음과 같습니다.

1. 코드 의미를 먼저 확인합니다.
2. API 응답과 로그에서 `error_code` 표기가 원문 그대로인지 확인합니다.
3. SP-E1001은 같은 주문의 반복 시도 여부를 확인합니다.
4. SP-E2003은 즉시 데이터팀에 알립니다.
5. 고객 안내가 필요한 경우 제품기획팀, 고객지원팀과 같은 표현을 사용합니다.
