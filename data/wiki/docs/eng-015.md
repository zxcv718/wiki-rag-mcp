# 하늘 배포 파이프라인 사용법

## 문서 목적과 대상
이 문서는 개발본부 구성원이 운영 배포를 처음 맡을 때 따라야 하는 기본 절차를 정리한 온보딩 문서입니다. 하늘은 카나리 배포와 롤백을 지원하는 사내 배포 도구이며 개발본부 서비스의 운영 배포에 기본으로 사용합니다.

페이코어는 결제 기능을 담당하는 스쿼드입니다. 이 문서는 페이코어를 포함한 개발본부 구성원이 하늘에서 배포 요청을 만들고, 진행 상태를 확인하고, 필요 시 롤백하는 흐름을 이해하는 데 목적이 있습니다.

운영 배포는 빌드, 스테이징 검증, 카나리, 전체 전환 순서로 진행합니다. 세부 비율, 대기 시간, 롤백 판단 기준은 별도 운영 기준 문서를 따릅니다.

## 첫날에 할 일
첫날에는 본인 계정으로 하늘에 접속 가능한지 확인합니다. 접속이 되지 않으면 팀장 또는 플랫폼·SRE팀에 권한 확인을 요청합니다.

권한 정책은 아래와 같습니다.

| 구분 | 권한 |
|---|---|
| 페이코어 소속 정규직 | 운영 권한 |
| 플랫폼·SRE팀 소속 정규직 | 운영 권한 |
| 외부 협력사 | 읽기 권한 |

하늘 운영 권한은 페이코어와 플랫폼·SRE팀 소속 정규직에게만 주고 외부 협력사는 읽기 권한만 부여합니다. 읽기 권한만 있는 경우 배포 이력과 상태는 확인할 수 있지만 운영 배포 실행이나 롤백 실행은 할 수 없습니다.

첫날에는 아래 항목도 함께 확인합니다.

1. 본인이 담당하는 서비스 저장소와 배포 대상이 무엇인지 확인합니다.
2. 최근 배포 이력에서 성공 사례 2건 이상을 읽어 흐름을 익힙니다.
3. 변경 티켓이 어떤 형식으로 관리되는지 팀 내에서 확인합니다.
4. 스테이징 검증 결과를 어디에 남기는지 팀장 또는 선임에게 확인합니다.

## 첫 주에 할 일
첫 주에는 선임과 함께 실제 배포 요청을 한 번 따라 해보는 것을 권장합니다. 운영 배포를 직접 실행하지 않더라도 요청 생성과 검토 단계까지는 경험해 두는 것이 좋습니다.

배포 요청 시 기본 입력 항목은 아래와 같습니다.

- 배포 대상 서비스
- 배포할 버전 또는 이미지 식별자
- 변경 내용 요약
- 변경 티켓 번호
- 배포 담당자
- 롤백 대상 버전 확인 결과

하늘 배포 요청에는 변경 티켓 번호를 반드시 연결합니다. 변경 티켓 번호가 없는 요청은 운영 배포 검토 대상에서 제외합니다. 티켓에는 변경 목적, 영향 범위, 확인이 필요한 항목이 정리되어 있어야 합니다.

첫 주에는 아래 순서로 화면 흐름을 익힙니다.

1. 빌드 결과를 확인합니다.
2. 스테이징 검증 결과를 확인합니다.
3. 카나리 시작 전 현재 운영 버전을 기록합니다.
4. 카나리 진행 중 상태와 지표를 확인합니다.
5. 이상이 없으면 전체 전환을 진행합니다.
6. 배포 완료 후 결과를 변경 티켓에 남깁니다.

## 둘째 주에 할 일
둘째 주에는 낮은 위험도의 변경을 기준으로 선임 참관 하에 직접 운영 배포를 진행합니다. 배포 전에는 변경 내용이 운영 반영 가능한 상태인지 다시 확인합니다. 특히 스테이징 검증이 누락되지 않았는지 확인합니다.

기본 절차는 아래와 같습니다.

```text
1. 배포 요청 생성
2. 변경 티켓 번호 연결
3. 빌드 확인
4. 스테이징 검증 확인
5. 카나리 진행
6. 전체 전환
7. 배포 후 확인
```

배포 중 문제가 보이면 즉시 롤백 가능 여부를 확인합니다. 하늘은 이전 운영 버전을 기준으로 롤백을 지원합니다. 롤백을 실행할 때는 단순히 되돌리는 데 그치지 말고, 어떤 증상 때문에 되돌렸는지 변경 티켓과 배포 기록에 함께 남깁니다. 그래야 다음 배포에서 같은 문제가 반복되지 않습니다.

롤백 후에는 아래를 정리합니다.

- 문제가 확인된 시점
- 영향이 있었던 기능 범위
- 롤백한 버전
- 추가 확인이 필요한 항목
- 후속 수정 담당자

## 도움받을 곳
하늘 사용 중 막히는 경우에는 상황에 따라 문의 대상을 구분합니다.

| 상황 | 문의 대상 |
|---|---|
| 권한이 없거나 화면 접근이 안 됨 | 플랫폼·SRE팀 |
| 배포 순서나 운영 판단이 어려움 | 소속 팀장 또는 선임 |
| 변경 티켓 연결 기준이 모호함 | 제품기획팀 또는 소속 팀장 |
| 배포 후 고객 영향이 의심됨 | 고객지원팀과 소속 팀장 |

긴급하지 않은 사용 문의는 사내 메신저로 남기고, 운영 영향이 있는 경우에는 바로 팀장과 플랫폼·SRE팀에 알립니다. 문서 내용이 실제 화면과 다르면 이 문서의 최종 수정일을 먼저 확인한 뒤, 차이가 계속되면 개발 스페이스에 수정 요청을 남깁니다.
