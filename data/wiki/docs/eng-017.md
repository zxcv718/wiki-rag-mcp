# 9월 솔게이트 한도 조정 안내

## 개요
솔게이트는 카드사·PG사와 연동하는 결제 게이트웨이 서비스이며, 본 문서는 가맹점별 호출 제한 기준과 초과 시 응답 동작을 정리합니다.

이번 달 변경으로 솔게이트의 가맹점별 기본 호출 제한이 1분당 600건에서 1분당 800건으로 상향되었습니다. 현재 기본 기준은 "1분당 800건"입니다. 본 기준은 가맹점 단위로 적용하며, 동일 가맹점으로 들어오는 요청 수를 합산해 판단합니다.

GW-429는 가맹점별 솔게이트 호출 한도를 넘긴 에러를 뜻합니다. GW-429는 기본 호출 제한을 넘긴 요청에만 반환하며, "내부 배치 계정"에는 적용하지 않습니다. 따라서 배치성 정산 작업이나 운영성 내부 처리 계정은 본 제한 계산 대상에서 제외합니다.

호출 제한 예외가 필요한 경우에는 제품기획팀의 사전 확인이 필요합니다. 확인이 끝나면 페이코어가 최대 "14일"짜리 임시 상향으로 처리합니다. 임시 상향은 상시 기준 변경이 아니며, 종료 시점 이후에는 기본 기준으로 자동 복귀하는 것을 원칙으로 합니다.

## 엔드포인트
아래 엔드포인트는 가맹점별 호출 제한이 적용되는 대표 예시입니다. 실제 적용 여부는 가맹점 식별 정보가 포함된 솔게이트 요청인지 기준으로 판단합니다.

| 메서드 | 경로 | 설명 | 제한 적용 |
| --- | --- | --- | --- |
| POST | /v1/payments/approve | 결제 승인 요청 | 적용 |
| POST | /v1/payments/cancel | 결제 취소 요청 | 적용 |
| GET | /v1/payments/{paymentId} | 결제 조회 요청 | 적용 |
| POST | /v1/payments/status | 결제 상태 확인 요청 | 적용 |

추가 안내는 다음과 같습니다.

1. 제한은 인증 사용자 단위가 아니라 가맹점 단위로 계산합니다.
2. 여러 서버 인스턴스에서 동시에 호출해도 동일 가맹점이면 하나의 한도로 집계합니다.
3. 예외 적용이 승인된 경우에도 적용 기간과 대상 가맹점을 명확히 지정해야 합니다.

## 요청·응답 예시
기본 요청 예시는 아래와 같습니다.

```http
POST /v1/payments/approve HTTP/1.1
Host: api.saesol.example
Content-Type: application/json
Authorization: Bearer <토큰>

{
  "merchantId": "M123456",
  "orderId": "ORD-20260913-001",
  "amount": 15000
}
```

정상 응답 예시는 아래와 같습니다.

```json
{
  "result": "success",
  "paymentId": "P202609130001",
  "status": "approved"
}
```

임시 상향이 필요한 경우 요청자는 제품기획팀 확인 내역을 첨부해 페이코어에 전달합니다. 전달 시에는 대상 가맹점, 필요 사유, 적용 시작 희망일, 종료 희망일을 함께 적습니다.

## 오류 응답
호출 수가 기본 기준을 초과하면 GW-429를 반환합니다. 이 응답은 초과한 시점의 요청에만 적용하며, 정상 범위 안의 요청에는 반환하지 않습니다.

```http
HTTP/1.1 429 Too Many Requests
Content-Type: application/json
```

```json
{
  "errorCode": "GW-429",
  "message": "merchant rate limit exceeded"
}
```

처리 기준은 아래와 같습니다.

1. 초과 여부는 가맹점별 집계 기준으로 판단합니다.
2. GW-429 수신 시 호출 측에서는 즉시 재시도만 반복하지 말고 호출 간격을 조정해야 합니다.
3. "내부 배치 계정"은 GW-429 적용 대상이 아닙니다.
4. 반복 초과가 예상되면 제품기획팀 사전 확인 후 페이코어에 임시 상향을 요청합니다.
