# 코드 프리즈와 핫픽스 창구

## 배경

코드 프리즈는 분기 마지막 주의 배포 동결 기간을 뜻합니다. 분기 말에는 결제·정산과 예약 운영에 영향이 큰 변경을 줄이고, 운영 안정성을 우선하기 위해 이 기간을 둡니다.

적용 시간은 각 분기 마지막 주 월요일 10시부터 금요일 18시까지입니다. 이 시간에는 운영 환경 기준으로 일반 기능 배포를 멈추고, 꼭 필요한 변경만 예외 절차로 처리합니다.

코드 프리즈 일정은 분기 시작 첫 주에 개발 스페이스 공지로 미리 알립니다. 공지에는 해당 분기의 적용 주간과 문의 경로를 함께 적습니다.

## 적용 규칙

코드 프리즈 기간의 기본 규칙은 아래와 같습니다.

| 구분 | 처리 원칙 |
|---|---|
| 일반 기능 배포 | 금지합니다 |
| 긴급 배포 | 핫픽스 창구로만 접수합니다 |
| 스테이징 환경 배포 | 평소처럼 진행할 수 있습니다 |

운영 환경에 반영되는 변경은 배포 목적과 범위를 먼저 확인해야 합니다. 일반 기능, 개선, 리팩터링, 성능 조정처럼 긴급하지 않은 변경은 코드 프리즈가 끝난 뒤에 배포합니다.

긴급 배포가 필요한 경우에는 임의로 배포 일정을 잡지 말고 핫픽스 창구를 사용합니다. 접수 대상, 양식, 승인 절차는 별도 문서를 따릅니다. 이 문서에서는 창구 사용 원칙만 설명합니다.

스테이징 환경 배포는 코드 프리즈 기간에도 제한하지 않습니다. 따라서 운영 배포가 막혀 있는 동안에도 검증, 재현, 사전 확인은 계속 진행할 수 있습니다. 다만 스테이징 환경 검증 결과만으로 운영 배포 가능 여부를 자체 판단하지 말고, 긴급 배포가 필요하면 반드시 정해진 절차로 접수합니다.

## 운영 방법

개발본부 각 스쿼드는 분기 말 일정이 예상되는 작업을 미리 정리하는 것이 좋습니다. 운영 반영이 필요한 변경은 가능하면 코드 프리즈 시작 전에 마치고, 남은 작업은 스테이징 환경에서 검증 중심으로 진행합니다.

플랫폼·SRE팀과 DB 관리자는 코드 프리즈 기간에 운영 변경 요청이 들어오면 먼저 긴급 여부와 접수 경로를 확인합니다. 제품기획팀, 고객지원팀 등 다른 조직에서 운영 반영을 요청하더라도 일반 기능 배포는 예외 없이 보류합니다.

외부 협력사가 참여한 변경도 동일하게 적용합니다. 코드 프리즈 기간에는 협력 개발자가 직접 운영 반영 일정을 조정하지 않고, 내부 담당자와 함께 절차를 맞춰야 합니다.

## 예시

아래는 판단 예시입니다.

```text
예시 1
상황: 분기 마지막 주 화요일에 신규 화면 문구 수정과 작은 기능 개선을 함께 배포하려고 합니다.
판단: 일반 기능 배포에 해당하므로 금지합니다.

예시 2
상황: 운영 장애를 막기 위해 즉시 수정이 필요한 변경이 생겼습니다.
판단: 핫픽스 창구로만 접수합니다.

예시 3
상황: 운영 배포는 하지 않고 검증용 빌드를 스테이징 환경에 올리려 합니다.
판단: 평소처럼 진행할 수 있습니다.
```

## 체크리스트

- 현재 시점이 분기 마지막 주 월요일 10시부터 금요일 18시까지인지 확인합니다.
- 이번 변경이 운영 환경 대상인지 확인합니다.
- 일반 기능 배포라면 코드 프리즈 종료 후로 일정을 옮깁니다.
- 긴급 배포라면 핫픽스 창구로 접수합니다.
- 운영 반영 전 검증이 필요하면 스테이징 환경에서 계속 진행합니다.
- 일정 공지가 필요한 경우 개발 스페이스의 분기 공지를 다시 확인합니다.
