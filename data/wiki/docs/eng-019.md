# L2 에스컬레이션 개발 대응 규칙

## 배경
이 문서는 고객지원팀이 넘긴 L2 에스컬레이션을 개발본부가 일관되게 처리하기 위한 기준을 정합니다. 여기서 L2 에스컬레이션은 상담원이 풀지 못한 문의를 담당 스쿼드로 넘기는 단계입니다. 개발본부는 접수 직후의 소통 방식, 담당자 지정, 회신 기준, 반복 문의의 정리 방식을 통일해야 합니다.

대상은 개발본부 전체이며, 실제 처리는 각 담당 스쿼드가 맡습니다. 플랫폼·SRE팀, DB 관리자, 데이터팀의 확인이 필요할 수 있으나, 고객지원팀과의 1차 창구는 담당 스쿼드가 유지합니다.

## 기본 규칙
1. 개발본부로 넘어온 L2 에스컬레이션은 담당 스쿼드 채널의 스레드 하나에서만 논의합니다. 같은 문의를 새 메시지나 다른 채널로 나누어 올리지 않습니다.
2. 개발본부는 영업일 기준 접수 후 2시간 안에 L2 에스컬레이션의 담당 DRI를 지정해야 합니다. DRI는 작업이나 장애의 직접 책임자 한 명을 뜻합니다.
3. DRI가 정해지면 스레드 첫 답글에 담당자, 현재 확인 범위, 다음 갱신 시점을 남깁니다.
4. 고객지원팀 회신 문안이 필요할 때는 스레드 안에서 확정한 내용만 전달합니다. 추정이나 개인 의견은 회신 문안으로 사용하지 않습니다.
5. 다른 팀 확인이 필요한 경우에도 고객지원팀과의 소통 창구는 담당 스쿼드 DRI가 유지합니다.

## 상세 처리 기준
### 접수와 분류
- 문의 내용이 불명확하면 고객지원팀에 필요한 사실만 다시 요청합니다.
- 재현 여부, 결제 시점, 영향 범위를 먼저 확인합니다.
- DB 조회나 로그 확인이 필요하면 관련 담당자에게 요청하되, 진행 상황은 같은 스레드에 이어서 남깁니다.

### 회신 기준
결제 실패 문의에 PRJ-204나 SP-E1001이 보이면 고객지원팀 템플릿 대신 원인 코드와 재시도 가능 여부를 함께 회신합니다.

- PRJ-204는 솔게이트가 PG사 응답을 기다리다 시간 초과된 에러입니다.
- SP-E1001은 카드 승인 재시도 횟수를 넘긴 에러입니다.

이 경우 고객지원팀이 가맹점에 전달할 수 있도록 아래 두 항목을 반드시 포함합니다.

| 항목 | 작성 기준 |
| --- | --- |
| 원인 코드 | 확인된 코드 그대로 적습니다 |
| 재시도 가능 여부 | 가능, 불가, 추가 확인 필요 중 하나로 적습니다 |

## 예시
```text
[고객지원팀 전달용]
확인 결과 원인 코드는 SP-E1001입니다.
재시도 가능 여부는 불가입니다.
동일 조건으로 반복 승인 시도가 누적된 경우에 발생할 수 있어, 가맹점에는 결제 수단 또는 입력 정보를 다시 확인한 뒤 재진행이 필요한지 안내합니다.

[스레드 기록]
DRI: 김가온
현재 확인 범위: 결제 시점 로그, 응답 지연 여부, 동일 문의 반복 여부
다음 갱신 시점: 금일 오후
```

## VOC 리뷰와 마감 체크리스트
주간 VOC 리뷰에는 각 스쿼드가 반복 문의 상위 3건과 재발 방지 항목 1개를 제출합니다. VOC는 가맹점 불만·제안 기록을 뜻합니다. 제출 내용은 고객지원팀이 체감하는 반복성 기준과 개발본부가 확인한 원인을 함께 반영합니다.

처리 마감 전에는 아래 항목을 확인합니다.

- 스레드 하나에서 논의가 끝까지 이어졌는지 확인합니다.
- DRI가 지정되었는지 확인합니다.
- 고객지원팀에 전달한 회신 문안이 스레드 기록과 일치하는지 확인합니다.
- PRJ-204 또는 SP-E1001 문의라면 원인 코드와 재시도 가능 여부가 포함되었는지 확인합니다.
- 반복 문의로 볼 수 있는 건은 주간 VOC 리뷰 후보로 표시합니다.
