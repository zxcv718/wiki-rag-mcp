# 페이코어 스쿼드 온보딩 메모

## 대상과 목표
이 문서는 개발본부에 새로 합류한 페이코어 구성원이 첫 2주 안에 알아야 할 서비스와 업무 흐름을 정리한 메모입니다. 페이코어는 개발본부의 결제 스쿼드 이름이며 솔페이 승인, 취소, 매입 연동을 주로 담당합니다.

첫 2주의 목표는 크게 두 가지입니다. 첫째, 현재 담당 서비스의 호출 흐름과 배포 흐름을 말로 설명할 수 있어야 합니다. 둘째, 장애나 문의가 들어왔을 때 누구에게 어떤 순서로 확인을 요청해야 하는지 알아야 합니다. 특히 신규 합류자는 첫 10영업일 안에 솔게이트와 누리의 호출 흐름을 그림 1장으로 설명할 수 있어야 합니다.

## 첫날에 할 일
첫날에는 개발 환경을 바로 완성하려 하기보다, 접근 권한과 연락 경로를 먼저 정리합니다.

1. 팀장 또는 온보딩 담당자와 첫 미팅을 진행합니다.
2. 저장소 읽기 권한, 배포 이력 조회 권한, 로그 조회 권한이 열렸는지 확인합니다.
3. 사내 메신저와 메일에서 아래 채널을 찾고 읽기 상태를 맞춥니다.
4. 최근 배포 공지와 최근 장애 공지를 각각 3건 이상 읽어 서비스 이름과 영향 범위를 익힙니다.
5. 고객지원팀에서 올라온 최근 결제 문의 사례를 읽고 어떤 정보가 있어야 재현과 확인이 가능한지 봅니다.

첫날에는 코드를 많이 보기보다, 승인과 취소가 어떤 순서로 처리되고 누리가 어떤 시점에 정산 배치를 수행하는지 큰 흐름을 먼저 잡는 편이 좋습니다.

## 첫 주에 할 일
첫 주 필수 구독 채널은 배포 공지, 장애 공지, 페이코어 데일리의 3개입니다. 알림을 켜 두고, 읽지 못한 공지는 당일 안에 확인합니다.

첫 주에는 아래 순서로 업무를 익힙니다.

| 항목 | 확인 내용 | 도움받을 곳 |
|---|---|---|
| 서비스 흐름 | 솔페이 승인, 취소, 매입 연동의 기본 흐름 | 페이코어 선임 |
| 외부 연동 | 솔게이트가 카드사·PG사와 연동하는 위치와 책임 범위 | 페이코어 선임 |
| 정산 배치 | 누리가 가맹점별 일 단위 정산을 만드는 흐름 | 데이터팀, DB 관리자 |
| 운영 관점 | 배포 전 확인 항목, 장애 시 공지 순서 | 팀장, 플랫폼·SRE팀 |

첫 주 안에는 최근 변경 건 하나를 골라 코드와 로그를 같이 읽어 봅니다. 이때 혼자 결론을 내리기보다, 왜 그렇게 구현했는지 작성자나 리뷰 참여자에게 묻는 것이 좋습니다.

외부 협력사인 레드브릭소프트 파견 개발자는 운영 배포 승인자가 될 수 없고 페어 작업으로만 첫 배포를 진행합니다. 해당 조건은 첫 주부터 동일하게 적용합니다.

## 둘째 주에 할 일
둘째 주에는 설명 가능한 수준으로 정리하는 데 집중합니다.

1. 솔게이트와 누리의 호출 흐름을 한 장짜리 그림으로 정리합니다.
2. 승인과 취소 각각에 대해 입력, 저장, 외부 연동, 후속 처리 순서를 말로 설명합니다.
3. 최근 장애 사례 1건을 골라 원인, 감지 시점, 공지 방식, 재발 방지 항목을 정리합니다.
4. 작은 수정 1건 이상을 맡아 개발부터 배포 확인까지 따라갑니다.

그림에는 최소한 아래 내용이 들어가야 합니다.

- 솔페이 요청이 들어오는 지점
- 솔게이트 호출이 발생하는 지점
- 결과 저장 또는 후속 처리 지점
- 누리로 이어지는 정산 관련 데이터 흐름

둘째 주 말에는 온보딩 담당자 앞에서 10분 정도 설명해 봅니다. 설명 중 막히는 부분이 있으면, 모르는 상태로 넘기지 말고 바로 확인할 목록으로 남깁니다.

## 도움받을 곳
업무 중 막히는 지점에 따라 문의 대상을 구분합니다.

- 코드 흐름, 리뷰 기준, 작업 우선순위는 페이코어 선임 또는 팀장에게 문의합니다.
- 배포 이력, 로그 조회, 실행 환경 문제는 플랫폼·SRE팀에 문의합니다.
- 운영 DB 조회나 데이터 확인이 필요하면 DB 관리자에게 문의합니다.
- 정산 배치 결과와 분석 데이터 기준은 데이터팀에 문의합니다.
- 보안 정책 해석이 필요한 경우 정보보안팀에 문의합니다.
- 릴리스 일정이나 요구사항 배경은 제품기획팀에 문의합니다.
- 가맹점 문의 원문과 재현 단서는 고객지원팀을 통해 확인합니다.

연락이 급하지 않은 내용은 메일로 남기고, 서비스 영향이 있는 이슈는 사내 메신저로 먼저 알립니다. 메일 주소가 필요한 경우 팀 대표 메일이나 담당자 메일의 saesol.example 주소를 사용합니다.
