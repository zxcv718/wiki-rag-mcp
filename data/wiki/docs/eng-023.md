# 정산 원장 스키마 변경 절차

## 배경

정산 원장은 누리가 만드는 가맹점별 정산 기준 테이블입니다. 이 테이블은 정산 결과의 기준이 되므로, 작은 구조 변경도 집계 결과와 운영 배치에 직접 영향을 줄 수 있습니다. 따라서 정산 원장은 컬럼 추가와 삭제 모두 사전 검토 대상입니다.

이 문서는 정산 원장 스키마를 변경할 때 개발본부가 따라야 할 절차와 검증 규칙을 정의합니다. 여기서 RFC는 구조 변경 전에 쓰는 설계 제안서이며, 리뷰를 거쳐 승인받아야 합니다. 승인 없는 직접 변경은 허용하지 않습니다.

## 변경 원칙

정산 원장 스키마 변경은 RFC 승인 후 개발, 백필, 이중 기록, 전환의 4단계로 진행합니다. 각 단계는 앞 단계의 확인이 끝난 뒤에만 진행합니다.

| 항목 | 원칙 |
|---|---|
| 변경 대상 | 정산 원장 전체 |
| 사전 검토 | 컬럼 추가, 컬럼 삭제 모두 필수 |
| 시작 조건 | RFC 승인 완료 |
| 진행 방식 | 개발, 백필, 이중 기록, 전환 순서 준수 |
| 운영 반영 준비 | 변경 SQL은 운영 반영 2영업일 전에 운영 DB 관리자에게 전달 |
| 배포 중단 기준 | 합계 검증에서 기존 결과와 신규 결과 차이가 1원이라도 발생 |

다음 경우에는 특히 영향 범위를 명시해야 합니다.

1. 기존 컬럼의 의미가 바뀌는 경우
2. 기본값 추가로 누리의 기록 방식이 달라지는 경우
3. NULL 허용 여부가 바뀌는 경우
4. 인덱스 변경으로 배치 성능 영향이 예상되는 경우

## 단계별 절차

1. RFC 작성 및 승인  
   변경 목적, 대상 컬럼, 호환성, 백필 방법, 검증 방법을 RFC에 작성합니다. 개발본부 내부 리뷰 후 관련 담당자 의견을 반영하고 승인받습니다.

2. 개발  
   애플리케이션과 SQL 변경을 분리 가능하게 작성합니다. 삭제 예정 컬럼은 즉시 제거하지 않고, 전환 전까지 읽기 경로와 쓰기 경로 영향을 분리해 둡니다.

3. 백필  
   신규 컬럼이 기존 데이터로 채워져야 하는 경우 백필을 수행합니다. 백필 SQL은 재실행 가능하게 작성하고, 중간 실패 시 재개 기준을 RFC에 포함합니다.

4. 이중 기록  
   전환 전 일정 기간 동안 기존 컬럼과 신규 컬럼에 동시에 기록합니다. 이 기간에는 읽기 기준은 기존 결과를 유지하고, 신규 결과는 비교 검증용으로만 사용합니다.

5. 전환  
   검증이 통과하면 읽기 기준을 신규 컬럼으로 전환합니다. 전환 직후에는 정산 원장 합계 검증을 다시 수행합니다. 기존 결과와 신규 결과 차이가 1원이라도 나면 배포를 중단합니다.

## 검증 및 운영 반영

운영 반영 전에는 아래 검증을 완료해야 합니다.

- 스키마 적용 전후로 누리 배치가 정상 종료되는지 확인합니다.
- 백필 대상 건수가 예상 범위와 일치하는지 확인합니다.
- 가맹점별 합계, 일자별 합계, 전체 합계를 각각 비교합니다.
- NULL, 기본값, 음수 금액, 취소 데이터가 포함된 사례를 확인합니다.

운영 반영 일정이 정해지면 변경 SQL은 운영 반영 2영업일 전에 운영 DB 관리자에게 전달해야 합니다. 전달 시에는 다음 내용을 함께 보냅니다.

- 적용 SQL과 되돌리기 SQL
- 예상 잠금 영향
- 백필 수행 여부
- 검증 쿼리
- 담당자 이름과 연락처
- 문의 메일 주소: ledger-change@saesol.example

## 예시 및 체크리스트

```sql
ALTER TABLE settlement_ledger
ADD COLUMN settlement_base_amount NUMERIC(18,2);

UPDATE settlement_ledger
SET settlement_base_amount = approved_amount
WHERE settlement_base_amount IS NULL;

SELECT merchant_id, business_date,
       SUM(approved_amount) AS old_sum,
       SUM(settlement_base_amount) AS new_sum
FROM settlement_ledger
GROUP BY merchant_id, business_date
HAVING SUM(approved_amount) <> SUM(settlement_base_amount);
```

체크리스트는 아래 순서로 확인합니다.

- [ ] RFC가 승인되었습니다.
- [ ] 컬럼 추가 또는 삭제 사유가 문서화되었습니다.
- [ ] 개발, 백필, 이중 기록, 전환 계획이 준비되었습니다.
- [ ] 운영 DB 관리자에게 변경 SQL을 2영업일 전에 전달했습니다.
- [ ] 되돌리기 SQL을 검토했습니다.
- [ ] 정산 원장 합계 검증 쿼리를 준비했습니다.
- [ ] 기존 결과와 신규 결과 차이가 1원도 없음을 확인했습니다.
- [ ] 전환 후 재검증 계획을 공유했습니다.
