# 결제 암호화 키 순환 절차

## 배경

이 문서는 카드 정보 암호화 키를 운영 환경에서 안전하게 교체하는 절차를 정리합니다. 카드 정보 암호화 키는 "1년마다" 순환합니다. 정기 순환 외에도 유출 의심, 접근 권한 오남용, 운영 환경 변경 등으로 보안팀이 필요하다고 판단한 경우에는 별도 일정으로 순환할 수 있습니다.

순환 작업은 보안팀과 "페이코어 DRI"가 함께 합니다. 여기서 페이코어는 결제 스쿼드 이름이며, DRI는 작업의 직접 책임자 한 명을 뜻합니다. 작업 중 의사결정과 진행 상황 정리는 페이코어 DRI가 맡고, 키 생성 기준과 보관 정책 확인은 보안팀이 맡습니다.

## 적용 범위와 기본 규칙

이 절차는 카드 정보를 암호화하거나 복호화하는 애플리케이션과 배치 작업에 적용합니다. 로그, 테스트 데이터, 문서 본문에는 실제 키 값을 남기지 않습니다.

기본 규칙은 아래와 같습니다.

| 항목 | 규칙 |
|---|---|
| 주기 | 카드 정보 암호화 키는 1년마다 순환합니다 |
| 참여자 | 보안팀과 페이코어 DRI가 함께 수행합니다 |
| 등록 순서 | 새 키는 "금고"에 먼저 등록합니다 |
| 반영 방식 | 새 데이터는 새 키로 암호화하고, 기존 데이터는 계획에 따라 재암호화합니다 |
| 검증 | 등록, 배포, 읽기/쓰기, 재암호화 결과를 단계별로 확인합니다 |
| 기록 | 작업 일시, 담당자, 영향 범위, 검증 결과를 문서와 메일로 남깁니다 |

금고는 비밀값을 보관하는 비밀 관리 시스템을 뜻합니다. 키 파일을 개인 PC나 공유 폴더에 보관하지 않습니다.

## 절차

1. 페이코어 DRI가 작업 일정을 제안하고 보안팀과 합의합니다.
2. 보안팀이 새 키를 생성하고 식별 가능한 버전을 정합니다. 실제 키 값은 문서나 메일 본문에 적지 않습니다.
3. 새 키는 금고에 먼저 등록합니다. 등록 후 접근 권한과 읽기 가능 여부를 확인합니다.
4. 애플리케이션이 기존 키와 새 키를 함께 인식하도록 설정을 반영합니다. 이 단계에서는 쓰기 기본값만 새 키로 바꾸고, 기존 데이터 읽기는 계속 가능해야 합니다.
5. 운영 배포 후 신규 저장 데이터가 새 키로 암호화되는지 확인합니다.
6. 기존 데이터 재암호화를 실행합니다. 재암호화는 서비스 영향이 낮은 시간대에 나누어 진행합니다.
7. 표본 데이터를 기준으로 복호화 성공 여부, 정산 처리 영향, 오류 로그 증가 여부를 확인합니다.
8. 모든 대상의 재암호화가 끝나면 기존 키를 쓰기 경로에서 제거합니다.
9. 최종 확인 후 기존 키를 비활성화하고, 결과를 개발 스페이스 문서와 관련자 메일로 남깁니다.

## 실행 예시

아래 예시는 절차 설명용입니다. 실제 값은 넣지 않습니다.

```bash
# 1) 새 키를 금고에 등록
vault kv put secret/payment/card-encryption \
  active_key_version="2026-04" \
  key_2026_04="<비밀번호>"

# 2) 애플리케이션 설정 반영 후 배포
export CARD_ACTIVE_KEY_VERSION="2026-04"
export CARD_LEGACY_KEY_VERSIONS="2025-04"

# 3) 재암호화 작업 실행
./run-reencrypt.sh --target card_data --from 2025-04 --to 2026-04

# 4) 검증
./verify-card-encryption.sh --sample 100
```

## 체크리스트

- [ ] 페이코어 DRI를 지정했습니다
- [ ] 보안팀과 작업 일정 및 영향 범위를 합의했습니다
- [ ] 새 키를 생성했습니다
- [ ] 새 키를 금고에 먼저 등록했습니다
- [ ] 접근 권한과 읽기 가능 여부를 확인했습니다
- [ ] 배포 전후로 읽기와 쓰기 동작을 확인했습니다
- [ ] 신규 데이터가 새 키로 저장되는 것을 확인했습니다
- [ ] 기존 데이터 재암호화를 완료했습니다
- [ ] 복호화 실패, 처리 지연, 오류 로그 증가가 없는지 확인했습니다
- [ ] 기존 키를 비활성화했습니다
- [ ] 작업 결과를 문서화하고 관련자에게 공유했습니다

문제가 발생하면 즉시 재암호화를 중지하고, 쓰기 기본값을 이전 상태로 되돌린 뒤 보안팀과 페이코어 DRI가 원인을 확인합니다. 복구 중에도 실제 키 값은 노출하지 않습니다.
