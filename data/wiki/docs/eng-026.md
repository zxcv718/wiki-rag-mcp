# 9월 릴리스 라벨 운영 규칙

## 배경

이 문서는 개발본부에서 운영 릴리스 라벨과 배포 묶음을 일관되게 관리하기 위한 최신 기준을 정리합니다. 대상은 솔페이 운영 배포를 준비하는 개발자와 검토자입니다.

이번 달부터 운영 릴리스 라벨 예시는 기존 월 단위 표기에서 주차 표기 형식으로 변경했습니다. 문서와 커밋 설명, 배포 요청 본문, 릴리스 노트 초안에 적는 라벨도 같은 기준을 사용합니다. 운영 릴리스 라벨은 제품명-주차 형식을 쓰며 예시는 "solpay-w39"입니다.

하늘은 사내 배포 도구이며 카나리 배포와 롤백을 지원합니다. 이 문서에서는 하늘에 등록하는 배포 묶음의 범위와 라벨 작성 방식을 함께 설명합니다.

## 운영 규칙

### 1. 릴리스 라벨 형식

운영 릴리스 라벨은 `제품명-w주차` 형식으로 작성합니다. 솔페이의 예시는 `solpay-w39`입니다. 주차는 해당 운영 배포가 실제로 진행되는 주를 기준으로 정합니다.

월 단위 표기나 임의 접미사는 운영 라벨에 사용하지 않습니다. 같은 주에 같은 제품으로 여러 차례 운영 배포를 하더라도 운영 라벨 자체는 동일하게 유지하고, 배포 묶음 설명에서 차이를 구분합니다.

### 2. 배포 묶음 포함 범위

하늘 배포 묶음에는 기본적으로 최대 12개 변경만 포함할 수 있습니다. 여기서 변경은 운영 배포에 포함되는 기능 수정, 버그 수정, 설정 수정 단위를 뜻합니다. "12개 변경"을 넘기면 검토와 롤백 판단이 어려워지므로 다음 배포 묶음으로 나눕니다.

하나의 변경이 크더라도 운영 판단 단위가 하나이면 1건으로 셉니다. 반대로 서로 독립적으로 되돌릴 수 있어야 하는 수정은 작은 작업이라도 각각 별도 변경으로 셉니다.

### 3. 릴리스 노트 마감

제품기획팀이 릴리스 노트를 확정하는 마감 시각은 배포 전일 17시입니다. 개발자는 이 시각 전에 배포 묶음에 포함될 변경 제목과 사용자 영향 여부를 정리해 전달합니다. 17시 이후에 운영 반영이 꼭 필요한 변경이 생기면 해당 배포 묶음에 자동 포함하지 않고, 제품기획팀과 다시 범위를 확인합니다.

## 작성 예시

아래 예시는 운영 배포 요청이나 문서에 그대로 참고할 수 있는 최소 형식입니다.

```text
운영 릴리스 라벨: solpay-w39
제품: 솔페이
배포 묶음 포함 변경:
1. 결제 취소 처리 오류 수정
2. 정산 금액 표시 문구 수정
3. 운영 설정 기본값 보정

비고:
- 하늘 배포 묶음 기준 충족
- 총 3개 변경 포함
- 릴리스 노트 확정 전 검토 완료
```

잘못된 예시는 다음과 같습니다.

```text
운영 릴리스 라벨: solpay-09
사유:
- 월 단위 표기 사용
- 이번 달 기준부터 주차 표기 사용
```

## 체크리스트

- 운영 릴리스 라벨을 `제품명-주차` 형식으로 작성했는지 확인합니다.
- 솔페이 운영 배포 문서의 예시가 `solpay-w39` 형식과 일치하는지 확인합니다.
- 하늘 배포 묶음에 포함된 항목 수가 "12개 변경" 이내인지 확인합니다.
- 변경 간 의존성이 커서 한 번에 되돌리기 어려운 항목이 섞여 있지 않은지 확인합니다.
- 제품기획팀 전달용 변경 목록을 배포 전일 17시 전에 정리했는지 확인합니다.
- 릴리스 노트 확정 후 추가된 변경이 있으면 같은 묶음에 넣지 말고 범위를 다시 협의합니다.
