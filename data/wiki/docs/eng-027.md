# 접근 재인증 운영 절차

## 배경

접근 재인증은 분기마다 권한 보유자가 계속 필요한지 확인하는 절차입니다. 권한이 업무 범위를 넘어 오래 유지되면 운영 실수와 정보 노출 가능성이 커지므로, 분기 단위로 현재 담당 업무와 권한의 일치 여부를 다시 확인합니다.

이 문서의 기본 대상은 운영 DB 접근 권한과 금고 읽기 권한입니다. 추가로 데이터팀이 가진 정산 원장 조회 권한도 접근 재인증 대상에 포함합니다. 정산 원장은 누리가 만드는 가맹점별 정산 기준 테이블을 뜻합니다.

이 절차는 권한을 신청하는 방법이 아니라, 이미 부여된 민감 권한을 유지할지 중단할지 판단하는 운영 절차입니다.

## 적용 범위와 원칙

다음 권한은 원칙적으로 모두 검토합니다.

| 구분 | 대상 | 확인 항목 |
| --- | --- | --- |
| 운영 권한 | 운영 DB 접근 권한 | 현재 담당 업무상 필요한지 확인합니다. |
| 비밀값 접근 | 금고 읽기 권한 | 실제 운영 또는 배포 업무에 필요한지 확인합니다. |
| 데이터 조회 | 데이터팀의 정산 원장 조회 권한 | 담당 업무와 조회 범위가 맞는지 확인합니다. |

다음 원칙을 함께 적용합니다.

1. 권한 유지는 현재 담당 업무로 설명 가능해야 합니다.
2. 퇴사 예정자, 조직 이동 예정자, 장기 미사용 권한은 유지보다 회수를 우선 검토합니다.
3. 분석 목적의 읽기 전용 계정도 예외 없이 유지 사유를 적어야 합니다.
4. 한 사람이 여러 권한을 가진 경우 권한별로 판단합니다.
5. 외부 협력사의 권한도 동일하게 검토합니다. 다만 해당 인력의 사실 확인은 소속 협업 담당자가 함께 확인합니다.

## 운영 절차

재인증 대상 목록은 분기 종료 5영업일 전에 플랫폼·SRE팀이 배포합니다. 배포 대상은 각 조직의 DRI입니다. DRI는 작업이나 장애의 직접 책임자 한 명을 뜻합니다.

절차는 아래 순서로 진행합니다.

1. 플랫폼·SRE팀이 대상 목록을 배포합니다.
2. 각 조직 DRI가 대상자, 권한 종류, 현재 업무를 확인합니다.
3. 유지가 필요한 경우 유지 사유를 적습니다.
4. 회수가 필요한 경우 회수로 표시합니다.
5. 플랫폼·SRE팀이 회신 결과를 기준으로 권한 유지 또는 회수를 반영합니다.

각 조직의 확인 책임은 다음과 같습니다.

- 개발본부 권한은 해당 스쿼드 DRI가 확인합니다.
- 데이터팀 권한은 데이터팀 DRI가 확인합니다.
- 운영 DB를 직접 관리하는 권한은 해당 DB 관리자와 조직 DRI가 함께 확인합니다.
- 금고 읽기 권한은 실제 사용 주체와 업무 목적이 일치하는지 다시 확인합니다.

응답이 없는 권한은 분기 마지막 영업일 18시에 자동 회수합니다. 자동 회수는 예외 승인 대기 상태에도 동일하게 적용합니다. 회수 후 다시 필요해지면 일반 권한 부여 절차로 재신청합니다.

## 작성 예시

아래 형식으로 회신합니다.

```text
[접근 재인증 회신]
조직: 데이터팀
DRI: 김하린
대상자: 박도윤
권한: 정산 원장 조회
판단: 유지
사유: 월 정산 검증 업무 수행 중이며 가맹점 단위 대사 확인이 필요합니다.

조직: 페이코어
DRI: 이서준
대상자: 최민아
권한: 금고 읽기 권한
판단: 회수
사유: 담당 업무 변경으로 더 이상 사용하지 않습니다.

조직: 데이터팀
DRI: 김하린
대상자: 오세린
권한: 읽기 전용 계정
판단: 유지
사유: 분기 분석 보고서 산출을 위해 정산 원장 조회가 지속적으로 필요합니다.
```

회신은 표나 문장형 목록으로 작성해도 되지만, 대상자별로 권한과 유지 사유가 분리되어 보여야 합니다.

## 체크리스트

- 대상 목록을 받으면 누락된 대상자나 이미 권한이 없는 대상자가 없는지 확인합니다.
- 조직 DRI가 직접 사실 여부를 확인합니다.
- 유지 사유는 현재 업무 기준으로 구체적으로 적습니다.
- 데이터팀의 정산 원장 조회 권한은 분석 목적 여부와 관계없이 모두 확인합니다.
- 읽기 전용 계정은 유지 사유를 반드시 적습니다.
- 회신하지 않은 권한은 분기 마지막 영업일 18시에 자동 회수됨을 대상자에게 미리 안내합니다.
- 회수 결정 권한은 실제 사용 중인 작업이 없는지 다시 확인한 뒤 제출합니다.
