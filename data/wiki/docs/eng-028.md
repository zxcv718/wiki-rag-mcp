# 솔북-솔페이 예약 결제 연동

## 개요

이 문서는 솔북 예약 생성 시 솔페이 결제를 연결하는 서버 간 API 흐름을 정의합니다. 대상은 예약 생성 직후 결제 승인을 함께 처리하는 경우입니다.

기본 흐름은 다음과 같습니다.

1. 솔북이 예약 가능 여부를 확인하고 예약 생성을 시도합니다.
2. 예약이 생성되면 솔북이 솔페이에 결제 승인 요청을 보냅니다.
3. 솔페이가 승인 결과를 반환하면 솔북이 예약 상태와 결제 연결 상태를 함께 저장합니다.

같은 사용자 세션으로 인정하려면 예약 생성 후 30초 안에 솔페이 승인 요청을 시작해야 합니다. 이 조건을 넘기면 결제는 별도 재시도로 취급해야 하며, 본 연동 흐름의 정상 케이스로 보지 않습니다.

예약 슬롯 중복이 감지되면 솔북은 BK-4010을 반환하고 결제 승인 요청을 보내지 않습니다. 따라서 호출 순서는 항상 예약 생성 성공 이후 결제 승인 요청입니다.

연동 변경이 필요한 경우에는 제품기획팀 릴리스 캘린더에 최소 3영업일 전에 등록해야 합니다. 스키마 변경, 필수 필드 추가, 응답 코드 변경은 모두 등록 대상입니다.

## 엔드포인트

| 구분 | 메서드 | 경로 | 설명 |
|---|---|---|---|
| 예약 생성 | POST | `/api/bookings` | 솔북에서 예약을 생성합니다. |
| 결제 승인 | POST | `/api/payments/authorizations` | 솔북이 솔페이에 승인 요청을 보냅니다. |

결제 승인 요청 헤더에는 `Idempotency-Key`를 포함해야 합니다. idempotency-key 보존 시간은 24시간이며 같은 키의 중복 승인 요청은 첫 결과를 재사용합니다. 네트워크 재시도나 응답 수신 실패가 있어도 동일한 키를 유지해야 합니다.

필수 처리 원칙은 다음과 같습니다.

- 예약 생성 실패 시 결제 승인 요청을 보내지 않습니다.
- 예약 생성 성공 후 결제 승인 요청 시작 시각이 30초를 넘지 않도록 합니다.
- 중복 호출 방지를 위해 예약 1건당 승인 요청 키 1개를 사용합니다.

## 요청·응답 예시

```http
POST /api/bookings
Content-Type: application/json

{
  "storeId": "store-100",
  "serviceDate": "2025-10-08",
  "serviceTime": "14:00",
  "customerName": "홍가온",
  "customerPhone": "010-0000-0000"
}
```

```json
{
  "bookingId": "bkg_20251008_0001",
  "status": "created"
}
```

```http
POST /api/payments/authorizations
Content-Type: application/json
Idempotency-Key: <idempotency-key>

{
  "bookingId": "bkg_20251008_0001",
  "amount": 35000,
  "currency": "KRW",
  "orderName": "예약 결제"
}
```

```json
{
  "bookingId": "bkg_20251008_0001",
  "paymentStatus": "approved"
}
```

동일한 `Idempotency-Key`로 같은 요청이 다시 들어오면 솔페이는 새 승인을 만들지 않고 첫 결과를 그대로 반환합니다. 솔북은 이 응답을 성공으로 처리하고 예약 상태를 다시 변경하지 않아야 합니다.

## 오류 응답

예약 단계 오류와 결제 단계 오류를 분리해서 처리합니다.

| 구분 | 조건 | 응답 | 처리 |
|---|---|---|---|
| 예약 오류 | 같은 예약 슬롯 중복 | `BK-4010` | 사용자에게 예약 불가를 반환하고 결제 승인 요청을 보내지 않습니다. |
| 결제 오류 | 승인 요청 실패 | 오류 응답 반환 | 예약과 결제 연결 상태를 실패로 기록하고 재시도 여부를 별도 판단합니다. |
| 중복 승인 요청 | 같은 `Idempotency-Key` 재전송 | 첫 결과 재사용 | 새 승인 생성 없이 기존 결과를 반환합니다. |

`BK-4010`은 솔북에서 같은 예약 슬롯이 두 번 잡힌 에러입니다. 이 경우 예약이 확정되지 않았으므로 후속 결제 처리는 없어야 합니다.

결제 승인 요청이 전송되었으나 응답 확인에 실패한 경우에는 같은 `Idempotency-Key`로만 재시도합니다. 다른 키로 다시 호출하면 중복 승인 위험이 생기므로 허용하지 않습니다. 운영 중 연동 변경이 필요한 경우에는 제품기획팀과 일정 확인 후 등록 절차를 먼저 진행합니다.
