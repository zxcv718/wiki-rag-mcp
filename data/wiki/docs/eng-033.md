# PII 등급별 개발 데이터 처리

## 배경

이 문서는 개발 과정에서 개인정보를 PII 등급에 따라 어떻게 다뤄야 하는지 정리한 가이드입니다. 대상은 개발본부이며, 개발 환경에서 생성하는 테스트 데이터, 운영 데이터의 샘플 추출, 반출 데이터 가공에 공통으로 적용합니다.

PII 등급은 개인정보 민감도를 1부터 3까지 나눈 기준이며, 1등급이 가장 민감합니다. 개발자는 데이터 설계와 조회, 저장, 공유 단계마다 등급을 먼저 확인해야 합니다. 등급이 불명확하면 임의로 판단하지 말고 정보보안팀 검토를 요청합니다.

## 분류 기준

개발 환경에서 사용하는 테스트 데이터는 테이블 또는 파일 단위가 아니라 컬럼 기준으로 분류합니다. 개발 환경 테스트 데이터에는 PII 등급을 컬럼 주석으로 표시합니다. 주석에는 등급과 처리 원칙을 함께 적어, 조회하는 사람이 별도 문의 없이 판단할 수 있게 합니다.

다음 항목은 기본 분류 기준으로 사용합니다.

| 데이터 항목 | 분류 |
|---|---|
| 이름 | PII 등급 2 |
| 휴대전화 번호 | PII 등급 2 |
| 카드번호 전체값 | PII 등급 1 |

위 기준에 없는 항목이라도 다른 데이터와 결합해 개인 식별 가능성이 높으면 더 높은 등급으로 취급합니다. 반대로 테스트 편의를 이유로 등급을 낮춰 표기하면 안 됩니다.

## 처리 규칙

개발 환경 반출 데이터는 PII 등급 1 값을 포함할 수 없습니다. 카드번호 전체값과 같이 직접 유출 위험이 큰 값은 일부 구간만 필요하더라도 원문 형태로 저장하거나 전달하지 않습니다.

개발 환경 반출 데이터에서 PII 등급 2 값은 해시 또는 마스킹 후에만 허용합니다. 이름과 휴대전화 번호는 원문 그대로 파일, 쿼리 결과, 화면 캡처에 남기지 않습니다. 해시는 동일 입력에 동일 결과가 나오도록 적용해 비교 용도로만 사용하고, 마스킹은 개인을 바로 식별할 수 없도록 충분한 길이로 가립니다.

PII 등급 데이터 샘플 추출 요청은 정보보안팀 검토를 거쳐 최대 7일 동안만 유효한 접근 권한으로 발급합니다. 요청 시에는 사용 목적, 필요한 컬럼, 보관 위치, 폐기 시점을 함께 적습니다. 기간이 끝나면 같은 목적이라도 다시 검토를 받아야 합니다.

샘플 데이터는 필요한 범위만 최소로 추출합니다. 추출 후에는 개발자가 로컬 저장소, 공유 폴더, 문서 첨부 파일에 불필요하게 복제하지 않도록 합니다. 작업이 끝난 파일은 즉시 삭제하고, 재사용이 필요하면 다시 승인 절차를 진행합니다.

## 예시

```sql
CREATE TABLE merchant_test_user (
    user_id BIGINT PRIMARY KEY,
    user_name VARCHAR(50),      -- 컬럼 주석: PII 등급 2, 반출 시 해시 또는 마스킹
    phone_number VARCHAR(20),   -- 컬럼 주석: PII 등급 2, 반출 시 해시 또는 마스킹
    card_number VARCHAR(20)     -- 컬럼 주석: PII 등급 1, 개발 환경 반출 금지
);
```

```text
반출 가능 예시
- user_name: 김*수
- phone_number: 010****1234

반출 불가 예시
- user_name: 김민수
- phone_number: 01012341234
- card_number: 1234123412341234
```

## 체크리스트

- 데이터 설계 시 각 개인정보 컬럼에 등급을 지정했는지 확인합니다.
- 테스트 데이터 정의서나 스키마에 컬럼 주석을 남겼는지 확인합니다.
- 이름, 휴대전화 번호를 PII 등급 2로 표기했는지 확인합니다.
- 카드번호 전체값을 PII 등급 1로 표기했는지 확인합니다.
- 반출 데이터에 PII 등급 1 값이 없는지 확인합니다.
- PII 등급 2 값이 있다면 해시 또는 마스킹 처리했는지 확인합니다.
- 샘플 추출이 필요한 경우 정보보안팀 검토와 유효 기간을 확인합니다.
- 승인 기간 종료 후 파일과 권한을 정리했는지 확인합니다.
