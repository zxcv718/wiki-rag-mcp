# 소프트웨어 라이선스 구매 승인 기준

## 목적
이 문서는 업무 수행을 위해 사용하는 소프트웨어 라이선스의 구매 승인 단계와 검토 기준을 정합니다. 대상은 업무용 SaaS, 개발 도구, 분석 도구, 협업 보조 도구를 포함한 유료 또는 무료 제공 소프트웨어입니다. 구매 전 검토를 통해 보안 위험, 중복 구매, 예산 집행의 적정성을 함께 확인합니다.

## 적용 대상
전 직원이 회사 비용으로 신규 구매, 갱신, 좌석 추가를 요청하는 경우에 적용합니다. 개인 카드로 먼저 결제한 뒤 비용 처리하는 경우도 동일하게 적용합니다. 외부 협력사가 사용하는 도구라도 회사 계정, 회사 데이터, 회사 비용이 관련되면 이 기준을 따릅니다.

다음 경우는 특히 본 문서의 사전 승인이 필요합니다.

- 회사 데이터 업로드 또는 연동이 필요한 도구
- 소스 코드, 로그, 고객 정보, 정산 데이터에 접근하는 도구
- 브라우저 확장, 에이전트 설치형 프로그램, 관리자 권한이 필요한 프로그램
- 자동 갱신이 설정된 구독형 라이선스

## 승인 기준
라이선스 요청자는 아래 항목을 신청서에 포함해야 합니다.

| 항목 | 필수 내용 |
| --- | --- |
| 사용 목적 | 업무 목적, 사용 부서, 예상 사용자 수 |
| 비용 정보 | 과금 방식, 연간 총액, 자동 갱신 여부 |
| 데이터 범위 | 업로드·조회·가공되는 데이터 종류 |
| 계정 관리 | 다온 연동 가능 여부, 퇴사자 계정 회수 방법 |
| 대체 가능성 | 기존 사용 도구로 대체 가능한지 여부 |

연간 총액이 "100만원 이상"인 소프트웨어 라이선스는 팀장 승인 뒤 정보보안팀과 재무팀의 순차 검토를 받아야 합니다. 100만원 미만이라도 회사 데이터에 접근하거나 설치 권한이 큰 도구는 정보보안팀 검토를 요청할 수 있습니다.

"PII 등급 1" 데이터에 접근할 수 있는 도구는 무료 체험판이라도 정보보안팀의 보안성 검토 없이는 사용할 수 없습니다. 체험 목적의 계정 생성, 샘플 데이터 업로드, 외부 연동 테스트도 사용으로 봅니다.

"다온" SSO 연동이 불가능한 도구는 예외 사유와 계정 종료 방법을 함께 제출해야 하며 승인 유효기간은 최대 1년입니다. 이 경우 요청 부서는 계정 발급, 권한 변경, 퇴사자 회수 책임자를 지정해야 합니다.

개발본부가 요청한 로그 분석 도구가 "모아"와 기능이 겹치면 플랫폼·SRE팀의 대체 가능성 검토 의견을 첨부해야 합니다. 기능 중복이 확인되면 원칙적으로 기존 도구 우선 사용을 검토합니다.

## 신청·처리 절차
1. 요청자는 구매 전에 신청서를 작성해 팀장에게 승인 요청합니다.
2. 팀장은 업무 필요성, 사용자 범위, 기존 도구 대체 가능성을 확인합니다.
3. 정보보안팀은 데이터 접근 범위, 인증 방식, 권한 회수 가능성, 외부 전송 여부를 검토합니다.
4. 재무팀은 예산 사용 가능 여부, 결제 방식, 자동 갱신 위험, 비용 적정성을 검토합니다.
5. 구매 확정 후 요청자는 실제 관리자 계정과 결제 계정을 기록하고, 갱신일 전에 재검토 일정을 관리합니다.

개발본부의 로그 분석 도구 요청은 팀장 승인 전에 플랫폼·SRE팀 의견을 먼저 받아 첨부하는 것을 권장합니다. 보안 검토 중 추가 자료가 필요하면 제품 소개서, 보안 문서, 처리 데이터 예시를 제출해야 합니다.

## 예외
긴급 장애 대응, 고객 문의 재현, 단기 검증 등으로 즉시 사용이 필요한 경우에도 사후 정산을 전제로 선사용해서는 안 됩니다. 다만 무료 체험판 중 회사 데이터를 넣지 않고 공개 자료만으로 기능을 확인하는 수준은 팀장 판단으로 가능할 수 있습니다. 이 경우에도 "PII 등급 1" 데이터 접근 가능성이 있으면 정보보안팀 검토가 먼저입니다.

승인 후 사용 목적이 바뀌거나 사용자 수가 크게 늘어나면 재승인을 받아야 합니다. 다온 미연동 예외 승인 건은 유효기간이 끝나기 전에 연장 여부를 다시 검토합니다.
