# 운영 DB 읽기 복제본 사용 기준

## 목적

이 문서는 운영 DB의 조회 부하를 분산하면서도 고객 화면 조사와 정산 검증의 정확성을 유지하기 위해 읽기 복제본 사용 범위를 정합니다. 적용 대상은 플랫폼·SRE팀과 개발본부이며, 운영 DB에 접근하는 DB 관리자와 조회성 작업 작성자도 함께 따릅니다.

이 문서에서 모아는 로그·지표·트레이스를 모으는 사내 관측 플랫폼을 뜻합니다. 정산 원장은 누리가 만드는 가맹점별 정산 기준 테이블을 뜻합니다.

## 사용 규칙

운영 DB의 읽기 복제본은 아래 조회 작업에만 사용할 수 있습니다.

| 허용 작업 | 사용 기준 |
| --- | --- |
| 모아 대시보드 조회 | 서비스 상태 확인, 추세 확인, 장애 후속 분석용 조회에 사용합니다. |
| 고객지원팀 사실 확인 조회 | 고객 문의에 대한 사실 확인 목적의 읽기 전용 조회에 사용합니다. |
| 배치 검증 조회 | 배치 실행 결과를 점검하는 읽기 전용 조회에 사용합니다. |

위 범위를 벗어나는 조회는 읽기 복제본 사용 대상이 아닙니다. 특히 쓰기와 결합된 작업, 운영 판단을 즉시 바꾸는 조회, 고객 화면에 노출된 최신 상태를 단건 기준으로 확정해야 하는 조회는 원본 기준으로 검토합니다.

고객 화면 문제를 조사할 때 운영 DB 복제 지연이 3초를 넘으면 원본 조회를 우선합니다. 복제 지연이 있는 상태에서 읽기 복제본 결과만으로 고객에게 상태를 안내하거나 원인을 단정하지 않습니다.

읽기 복제본 조회는 읽기 전용 세션으로 실행합니다. 조회 실행 전에는 대상 테이블, 예상 범위, 정렬과 집계 여부를 확인하고, 장기 실행 가능성이 있으면 DB 관리자와 먼저 협의합니다.

## 역할과 책임

플랫폼팀 DB 관리자는 읽기 복제본의 상태를 운영 관점에서 관리합니다. 플랫폼팀 DB 관리자는 월요일 10시에 복제 지연 상위 5개 테이블을 점검합니다. 점검 결과 반복 지연이 확인되면 원인 테이블의 접근 패턴과 인덱스 상태를 검토하고, 필요한 경우 개발본부에 조회 방식 조정을 요청합니다.

데이터팀 DB 관리자는 정산 원장 검증용 장기 조회를 복제본에서만 실행해야 하며 단일 쿼리 제한 시간은 20분입니다. 제한 시간을 넘길 가능성이 있으면 조회를 분할하거나 실행 계획을 다시 검토합니다. 정산 원장 검증을 원본에서 직접 수행하지 않습니다.

개발본부는 기능 개발 또는 장애 분석 중 조회가 허용 범위에 해당하는지 먼저 판단해야 합니다. 판단이 어려우면 플랫폼팀 DB 관리자에게 사용 목적과 쿼리 개요를 공유하고 확인받습니다.

고객지원팀은 사실 확인 조회가 필요한 경우 읽기 복제본 기준으로 요청할 수 있습니다. 다만 고객 화면의 최신 상태와 불일치 가능성이 있는 상황에서는 원본 우선 원칙을 전제로 개발본부 또는 플랫폼팀에 재확인을 요청합니다.

## 예외

장애 대응, 데이터 정합성 확인, 고객 영향이 큰 화면 문제 조사처럼 최신성이 우선인 경우에는 읽기 복제본보다 원본 조회를 우선할 수 있습니다. 이 경우에도 조회 범위는 필요한 최소 수준으로 제한합니다.

읽기 복제본에서 장기 조회가 반복되어 복제 지연을 키우는 경우 플랫폼팀 DB 관리자는 해당 조회의 중단이나 시간대 조정을 요청할 수 있습니다. 요청을 받은 팀은 같은 목적의 조회를 더 작은 단위로 나누거나 배치 검증 절차를 조정합니다.

이 기준에 없는 사용 사례는 임의로 확대 해석하지 않습니다. 적용 여부가 불명확하면 플랫폼·SRE 스페이스에 문의 내용을 남기고 DB 관리자 확인 후 진행합니다.
