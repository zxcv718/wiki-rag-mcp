# 하늘 카나리 배포 운영 기준

## 목적
이 문서는 하늘을 사용해 운영 배포를 진행할 때 카나리 단계의 적용 대상, 승인 절차, 관찰 항목, 롤백 기준을 통일하기 위한 운영 정책입니다. 하늘은 사내 배포 도구로, 카나리 배포와 롤백을 지원합니다. 본 문서는 플랫폼·SRE팀과 개발본부가 동일한 기준으로 배포 판단을 하도록 정리합니다.

적용 대상은 운영 환경의 애플리케이션 배포이며, 개발본부가 수행하는 변경과 플랫폼·SRE팀이 지원하는 배포를 모두 포함합니다. 데이터 적재나 분석 작업 자체는 대상이 아니지만, 운영 서비스 동작에 직접 영향을 주는 배포는 본 기준을 따릅니다.

## 운영 규칙
하늘 카나리 배포는 운영 트래픽의 10%로 15분간 먼저 배포한 뒤 이상이 없을 때 전체 배포로 전환합니다. 카나리 단계에서는 기능 정상 동작 여부뿐 아니라 오류율, 지연, 외부 연동 실패를 함께 확인합니다.

배포 시작 전에는 변경 티켓을 준비해야 하며, 솔게이트와 누리의 운영 배포는 하늘 배포 시작 전에 모아 대시보드 링크 2개를 변경 티켓에 첨부해야 합니다. 모아는 로그·지표·트레이스를 모으는 사내 관측 플랫폼입니다. 첨부한 링크는 배포 중 즉시 열람 가능한 상태여야 하며, 배포 담당자와 승인자가 동일한 화면을 기준으로 판단할 수 있어야 합니다.

카나리 단계 중에는 다음 항목을 우선 확인합니다.

| 항목 | 확인 기준 |
| --- | --- |
| 기본 상태 | 애플리케이션 기동, 헬스체크, 주요 요청 성공 여부를 확인합니다. |
| 오류 추이 | 오류가 급격히 증가하지 않는지 확인합니다. |
| 연동 지연 | 외부 연동 대기 증가와 응답 지연을 확인합니다. |
| PRJ-204 | 솔게이트가 PG사 응답을 기다리다 시간 초과된 에러의 비율을 확인합니다. |

하늘에서 카나리 단계 중 PRJ-204 비율이 0.8%를 넘기면 DRI가 즉시 롤백을 실행해야 합니다. DRI는 작업이나 장애의 직접 책임자 한 명을 뜻합니다. 이 기준은 추가 승인 없이 즉시 적용합니다.

하늘 롤백은 최근 성공 릴리스 1개만 즉시 복귀 대상으로 선택할 수 있습니다. 따라서 배포 전 DRI는 직전 성공 릴리스가 복귀 가능한 상태인지 반드시 확인합니다.

## 역할과 책임
1. DRI는 배포 계획 수립, 변경 티켓 작성, 카나리 진행 판단, 롤백 실행을 담당합니다.
2. 플랫폼·SRE팀은 하늘 배포 수행을 지원하고, 관찰 지표 확인과 롤백 시 기술 지원을 제공합니다.
3. 개발본부의 배포 요청자는 변경 내용, 영향 범위, 확인 방법을 변경 티켓에 명확히 남깁니다.
4. 승인자는 변경 티켓의 준비 상태와 관찰 링크 첨부 여부를 확인한 뒤 배포 시작을 승인합니다.

승인은 최소한 DRI와 승인자 간 상호 확인으로 진행합니다. 승인 기록은 변경 티켓 또는 사내 메신저의 배포 스레드에 남깁니다. 배포 중 판단이 필요한 경우 최종 실행 책임은 DRI에게 있습니다.

## 예외 및 후속 조치
긴급 장애 대응으로 즉시 배포가 필요한 경우에도 카나리 단계 자체는 생략하지 않습니다. 다만 승인 대기 시간을 줄일 수 있으며, 이 경우 DRI는 사후에 변경 티켓에 사유와 결과를 보완합니다.

카나리 단계에서 이상이 없더라도 전체 배포 전환 직후 오류가 증가하면 DRI는 지체 없이 롤백을 검토합니다. 롤백 후에는 원인 분석 전까지 동일 변경의 재배포를 진행하지 않습니다. 고객 영향이 확인되면 고객지원팀이 응대할 수 있도록 변경 티켓에 영향 범위와 현재 상태를 업데이트합니다.

예외 적용이나 판단 이견이 반복되면 플랫폼·SRE팀은 본 문서 개정이 필요한지 검토합니다. 문서 해석이 모호한 경우에는 보수적으로 판단하고 롤백 가능성을 우선 확보합니다.
