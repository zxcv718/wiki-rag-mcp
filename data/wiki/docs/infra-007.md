# 운영 DB 비밀번호 교체 절차

## 언제 사용하는가
이 문서는 운영 DB 관리자 계정 비밀번호를 정기 교체하거나, 기존 비밀번호 노출 가능성이 있어 즉시 교체가 필요한 경우에 사용합니다. 운영 DB 관리자 계정 비밀번호는 60일마다 교체합니다. 정기 교체와 긴급 교체 모두 동일한 절차를 따르되, 긴급 교체인 경우 영향 확인과 공유를 더 빠르게 진행합니다.

교체 작업은 반드시 DBA 두 명이 함께 수행합니다. 한 명은 실제 변경을 수행하고, 다른 한 명은 대상 계정과 접속 대상, 적용 순서를 교차 확인합니다. 단독 작업은 진행하지 않습니다.

## 사전 확인
작업 시작 전에 아래 항목을 확인합니다.

| 확인 항목 | 내용 |
|---|---|
| 작업 인원 | DBA 두 명이 동시에 참여하는지 확인합니다. |
| 대상 식별 | 변경할 운영 DB 관리자 계정과 대상 DB 인스턴스를 확인합니다. |
| 접근 권한 | 두 작업자 모두 운영 DB와 금고 접근 권한이 있는지 확인합니다. |
| 영향 범위 | 해당 계정을 사용하는 운영 배치, 관리 스크립트, 수동 점검 절차가 있는지 확인합니다. |
| 공지 필요 여부 | 작업 중 접속 재시도가 발생할 수 있으므로 관련 담당자에게 사전 공유가 필요한지 확인합니다. |
| 복구 수단 | 기존 접속 세션이 유지되는지, 다른 관리자 계정으로 복구 가능한지 확인합니다. |

새 비밀번호는 금고에서 발급합니다. 사람이 임의로 정하거나 메모장, 메일 본문, 채팅방에 기록하지 않습니다. 비밀번호 평문은 화면 공유 없이 최소 인원만 확인합니다.

## 단계별 절차
아래 예시는 PostgreSQL 기준입니다. 다른 DB 엔진도 같은 순서로 진행하되, 비밀번호 변경 구문만 해당 엔진에 맞게 사용합니다.

1. 기존 관리자 세션으로 운영 DB에 접속합니다.
2. 금고에서 새 비밀번호를 발급합니다.
3. 두 작업자가 대상 계정명을 다시 확인합니다.
4. 운영 DB에서 비밀번호를 변경합니다.
5. 금고의 해당 항목을 새 값으로 갱신합니다.
6. 새 비밀번호로 재접속하여 정상 동작을 확인합니다.
7. 기존 비밀번호를 참조하던 수동 절차 문서가 있으면 값이 아닌 참조 위치만 점검합니다.

```sql
-- 운영 DB 접속 후 대상 계정 비밀번호 변경
ALTER ROLE <관리자계정명> WITH PASSWORD '<새비밀번호>';
```

```bash
# 새 비밀번호로 재접속 확인
psql "host=<DB호스트> port=<포트> dbname=<DB명> user=<관리자계정명> password=<새비밀번호>"
```

```sql
-- 접속 후 기본 확인
SELECT current_user;
SELECT now();
```

작업 중에는 비밀번호를 터미널 기록, 셸 이력, 임시 파일에 남기지 않도록 주의합니다. 가능하면 프롬프트 입력 방식을 사용합니다.

## 결과 확인
아래 기준을 모두 만족하면 교체 완료로 판단합니다.

- 새 비밀번호로 운영 DB 관리자 계정 로그인에 성공합니다.
- 기본 조회 문장이 정상 수행됩니다.
- 금고에 저장된 값이 방금 적용한 값과 일치합니다.
- 작업 전 열어 둔 기존 세션 외에, 새 세션 기준으로 관리자 작업이 가능한 것을 확인합니다.
- 관련 담당자 문의가 들어올 경우 변경 완료 시각과 영향 여부를 설명할 수 있습니다.

완료 후에는 작업 일시, 대상 계정, 수행자 2인, 확인 결과만 남깁니다. 비밀번호 자체는 어떤 기록에도 남기지 않습니다.

## 되돌리기 및 에스컬레이션
새 비밀번호 적용 후 로그인에 실패하면 먼저 계정명 오입력, 대상 DB 오접속, 금고 갱신 순서 누락 여부를 확인합니다. 기존 관리자 세션이 살아 있으면 그 세션으로 즉시 비밀번호를 다시 변경합니다. 복구 시에도 새 비밀번호는 다시 금고에서 발급합니다.

기존 세션이 모두 끊겼고 관리자 접근이 불가능하면 플랫폼·SRE팀과 운영 DB를 관리하는 다른 DBA에게 즉시 알립니다. 데이터팀 소속 DBA가 대상인 경우에도 동일하게 DBA 두 명 체계를 유지합니다. 비밀번호 노출이 의심되는 긴급 상황이면 정보보안팀에 즉시 공유하고, 서비스 영향이 보이면 개발본부 담당자에게 현재 상태와 임시 대응 필요 여부를 전달합니다. 작업 중 판단이 어려우면 변경 지속보다 접근 복구와 영향 최소화를 우선합니다.
