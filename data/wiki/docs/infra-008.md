# NR-503 경보 대응 런북

## 언제 쓰는가
NR-503는 누리 배치가 정상 마감 시각까지 끝나지 않았을 때 모아에서 뜨는 경보입니다. 이 문서는 온콜 DRI가 NR-503를 처음 확인한 시점부터 배치 지연 원인을 좁히고, 고객 영향 가능성을 판단하고, 필요한 합류 요청을 진행할 때 사용합니다.

NR-503는 단독으로 열릴 수도 있고 다른 오류 증가와 함께 나타날 수도 있습니다. 이 문서의 목적은 초기 확인 순서를 고정해 불필요한 추측을 줄이는 데 있습니다.

## 사전 확인
경보를 열면 먼저 아래 항목을 확인합니다.

1. 같은 시각대에 NR-503 외 경보가 함께 증가하는지 확인합니다.
2. 최근 배포, 설정 변경, 수동 재실행 여부를 확인합니다.
3. 누리 작업 큐 길이와 정산 원장 적재 속도를 확인합니다.

특히 NR-503가 열리면 온콜 DRI는 5분 안에 누리 작업 큐 길이와 정산 원장 적재 속도를 먼저 확인해야 합니다. 이 두 값으로 지연이 대기 적체인지, 처리 성능 저하인지, 적재 정지인지 빠르게 구분합니다.

| 확인 항목 | 정상에 가까운 상태 | 이상 징후 |
|---|---|---|
| 누리 작업 큐 길이 | 감소하거나 정체 없음 | 계속 증가하거나 감소하지 않음 |
| 정산 원장 적재 속도 | 평소 수준으로 유지 | 급감하거나 0에 가까움 |
| 동반 오류 | 없음 또는 일시적 | 같은 시각부터 지속 증가 |

## 단계별 조치
초기 조치는 아래 순서로 진행합니다.

```bash
# 1) 모아에서 NR-503 발생 시각과 지속 시간을 확인합니다.
# 2) 누리 작업 큐 길이 추이를 확인합니다.
# 3) 정산 원장 적재 속도 추이를 확인합니다.
# 4) 작업 처리 로그에서 최근 실패 반복 여부를 확인합니다.
# 5) 배치 프로세스가 실행 중인지, 재시작 반복이 있는지 확인합니다.
# 6) 데이터베이스 대기, 잠금, 장시간 실행 쿼리 유무를 확인합니다.
```

판단 기준은 아래와 같습니다.

- 큐 길이가 증가하고 적재 속도가 유지되면 입력량 급증 또는 처리량 부족 가능성을 먼저 봅니다.
- 큐 길이가 증가하고 적재 속도가 급감하면 처리 병목 또는 데이터베이스 지연 가능성을 먼저 봅니다.
- 큐 길이는 크지 않은데 적재 속도가 0에 가까우면 작업 정지, 반복 실패, 잠금 문제를 우선 확인합니다.
- NR-503 대응 중 SP-E2003가 함께 증가하면 데이터팀 DB 관리자에게 즉시 합류를 요청합니다. 이 경우 단순 지연이 아니라 정산 데이터 정합성 문제로 이어질 수 있으므로 원인 분리를 늦추지 않습니다.

## 에스컬레이션과 커뮤니케이션
초기 확인 후 온콜 DRI가 상황을 정리해 사내 메신저에 공유합니다. 공유에는 발생 시각, 현재 지속 시간, 큐 길이 추세, 정산 원장 적재 속도, 즉시 조치 여부를 포함합니다.

NR-503가 30분 이상 지속되면 고객지원팀에 공지 초안을 전달하고 L2 에스컬레이션 전용 방을 엽니다. 공지 초안에는 장애 원인 단정 표현을 쓰지 않고, 정산 지연 가능성과 다음 업데이트 예정만 적습니다.

추가 합류 기준은 아래와 같습니다.

- 데이터베이스 대기나 잠금이 의심되면 해당 영역 DB 관리자에게 합류를 요청합니다.
- SP-E2003 동반 증가 시 데이터팀 DB 관리자를 우선 호출합니다.
- 처리 프로세스 반복 실패가 확인되면 페이코어 담당자에게 합류를 요청합니다.

## 결과 확인과 되돌리기
조치 후에는 다음 순서로 회복 여부를 확인합니다.

1. 누리 작업 큐 길이가 감소하는지 확인합니다.
2. 정산 원장 적재 속도가 회복되는지 확인합니다.
3. 실패 로그가 멈추었는지 확인합니다.
4. NR-503가 해제되었는지 확인합니다.

임시 조치로 프로세스를 재기동했거나 중단 작업을 다시 시작한 경우, 같은 증상이 반복되지 않는지 짧은 간격으로 재확인합니다. 조치가 효과 없으면 이전 상태로 되돌릴 수 있는 변경만 되돌립니다. 데이터 수정이 필요한 경우에는 단독으로 진행하지 말고 해당 DB 관리자와 함께 범위를 확정합니다.

경보 해제 후에는 원인, 조치, 고객 영향 여부를 운영 기록에 남기고, 고객지원팀에 종료 메시지를 전달합니다.
