# 코드 프리즈 중 핫픽스 창구 운영

## 목적
이 문서는 코드 프리즈 기간에만 운영하는 "핫픽스 창구"의 접수, 승인, 배포 후 확인 절차를 정리합니다. 핫픽스 창구는 코드 프리즈 중에도 긴급 배포를 받는 절차를 뜻합니다. 일반 기능 변경이나 일정 맞춤 배포는 이 절차의 대상이 아닙니다.

코드 프리즈는 분기 마지막 주의 배포 동결 기간을 뜻합니다. 이 기간에는 변경을 최소화해야 하므로, 예외 배포는 사유와 영향 범위를 명확히 남겨야 합니다. 본 문서는 플랫폼·SRE팀과 개발본부가 공통으로 따르는 운영 기준으로 사용합니다.

## 운영 규칙
핫픽스 창구는 코드 프리즈 기간에만 열리며 접수 대상은 운영 장애 수정, 보안 패치, 법적 의무 대응 배포로 한정합니다. 다음에 해당하지 않으면 접수하지 않습니다.

- 신규 기능 추가
- 성능 개선만을 목적으로 한 변경
- 운영 중 장애나 보안 이슈와 직접 관련이 없는 설정 변경
- 다음 분기 일반 배포로 처리 가능한 수정

접수는 이슈 티켓 1건당 배포 1건을 원칙으로 합니다. 하나의 티켓에 여러 서비스를 함께 묶지 않습니다. 서비스 영향이 분리되면 티켓도 분리합니다.

접수자는 아래 6개 항목을 반드시 작성합니다.

1. 영향 서비스
2. 장애 또는 변경 사유
3. 사용자 영향 범위
4. 복구 목표 시각
5. 하늘 롤백 방법
6. 검증 방법

하늘은 사내 배포 도구로, 카나리 배포와 롤백을 지원합니다. 접수자는 하늘에서 실제로 수행할 롤백 절차를 문장으로 적어야 하며, "문제 시 롤백"처럼 추상적으로 쓰지 않습니다. 검증 방법에는 배포 직후 확인할 로그, 지표, 주요 기능 점검 항목을 포함합니다.

## 승인과 역할
승인자는 제품기획팀의 릴리스 담당 1명과 플랫폼·SRE팀 온콜 1명입니다. 두 사람 모두 승인해야 배포를 진행합니다. 한쪽 승인만으로는 배포하지 않습니다.

| 역할 | 책임 |
|---|---|
| 접수자 | 티켓 작성, 변경 범위 설명, 배포 및 롤백 계획 기재, 배포 후 결과 기록 |
| 제품기획팀 승인자 | 릴리스 일정 영향과 대외 공지 필요 여부 확인 |
| 플랫폼·SRE팀 승인자 | 운영 위험, 롤백 가능성, 배포 순서와 검증 계획 확인 |
| 개발본부 구현 담당 | 수정 사항 준비, 배포 중 기술 지원, 이상 징후 대응 |

승인 과정에서 내용이 불충분하면 승인자는 보완을 요청합니다. 복구 목표 시각이 없거나 하늘 롤백 방법이 실행 불가능한 경우에는 반려할 수 있습니다. 보안 패치인 경우 정보보안팀 의견이 필요할 수 있으나, 최종 승인자는 위 두 역할로 유지합니다.

## 배포 후 확인과 예외
배포가 끝나면 접수자는 24시간 안에 모아 지표 확인 결과를 같은 티켓에 추가해야 합니다. 모아는 로그, 지표, 트레이스를 모으는 사내 관측 플랫폼입니다. 확인 결과에는 최소한 배포 전후 오류 추이, 주요 요청 성공 여부, 추가 조치 필요 여부를 포함합니다. 이상이 있으면 같은 티켓에 후속 대응 계획을 이어서 기록합니다.

긴급도가 매우 높아 사전 논의 시간이 짧은 경우에도 티켓 생성과 승인 절차는 생략하지 않습니다. 다만 접수자가 먼저 티켓을 만들고 필수 항목을 채운 뒤, 승인자 확인과 병행하여 준비할 수 있습니다. 코드 프리즈 종료 후에는 이 문서의 절차를 사용하지 않고 일반 배포 절차를 따릅니다.
