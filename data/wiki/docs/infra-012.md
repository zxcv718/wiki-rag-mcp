# 금고 비밀값 접근 승인 매트릭스

## 목적

이 문서는 금고의 운영 경로에 저장된 비밀값에 대해 누가 조회와 갱신을 요청할 수 있는지, 어떤 승인과 기록이 필요한지 정합니다. 금고는 비밀값을 보관하는 비밀 관리 시스템을 뜻합니다. 대상은 플랫폼·SRE팀과 개발본부가 운영 과정에서 사용하는 운영 비밀값이며, 제품 개발용 예시 값이나 문서용 자리표시자는 대상에 포함하지 않습니다.

이 문서의 목적은 운영 비밀값 노출을 최소화하고, 필요한 작업은 중단 없이 진행하되 접근 사유와 승인 내역이 남도록 하는 데 있습니다.

## 접근 규칙

운영 경로의 비밀값은 업무상 필요가 확인된 경우에만 최소 권한으로 부여합니다. 상시 권한은 역할상 지속적으로 운영을 담당하는 인원에게만 허용합니다.

| 대상 | 조회 권한 | 갱신 권한 | 승인 조건 | 비고 |
|---|---|---|---|---|
| 플랫폼·SRE팀 | 가능 | 가능 | 팀 내 검토 후 부여합니다 | 운영 담당 범위 내에서 상시 권한을 둘 수 있습니다 |
| DB 관리자 | 가능 | 가능 | 담당 DB 범위로 제한합니다 | 운영 DB 관련 경로에 한합니다 |
| 개발본부 일반 개발자 | 상시 불가 | 상시 불가 | 사유 확인 후 임시 권한만 부여합니다 | 최대 8시간까지 요청할 수 있습니다 |
| 데이터팀 | 가능 여부를 건별 판단합니다 | 건별 판단합니다 | 정산 데이터 처리 필요 시 검토합니다 | 운영 영향 범위를 함께 확인합니다 |
| 정보보안팀 | 감사 목적 조회를 요청할 수 있습니다 | 불가 | 플랫폼·SRE팀 확인이 필요합니다 | 직접 운영 변경은 하지 않습니다 |
| 레드브릭소프트 인력 | 불가 | 불가 | 부여하지 않습니다 | 운영 비밀값 조회 권한을 받을 수 없습니다 |

다음 경로는 민감 경로로 분류합니다.

1. 결제 인증서 관련 경로
2. DB 접속 비밀값 관련 경로

위 두 경로는 플랫폼·SRE팀 2명 승인 없이는 읽기 권한을 부여할 수 없습니다. 이 규칙은 상시 권한, 임시 권한, 감사 목적 조회 요청에 모두 동일하게 적용합니다.

개발본부 일반 개발자는 장애 분석, 배포 확인, 운영 데이터 연계 점검 등 명확한 사유가 있을 때만 임시 권한을 요청합니다. 임시 권한은 요청한 작업 범위로만 제한하며, 종료 시 즉시 회수합니다.

## 역할과 책임

플랫폼·SRE팀은 금고 운영 경로의 권한 부여와 회수를 집행하고, 요청 사유와 승인자를 확인합니다. 민감 경로는 승인자 2명이 모두 플랫폼·SRE팀 소속인지 확인합니다. 권한 부여 내역은 누가, 언제, 어떤 경로에, 어떤 사유로 접근했는지 남겨야 합니다.

개발본부와 데이터팀은 작업 전에 필요한 경로와 예상 사용 시간을 구체적으로 제출합니다. 요청자는 작업 종료 후 권한 회수 여부를 확인해야 합니다. DB 관리자는 자신이 담당하는 운영 DB 범위를 벗어나는 경로를 직접 요청하거나 부여하지 않습니다.

정보보안팀은 정기 점검 또는 사고 확인이 필요한 경우 조회를 요청할 수 있습니다. 다만 직접 비밀값을 변경하는 권한은 갖지 않습니다.

금고 운영 경로 권한 부여 내역은 매주 월요일 플랫폼·SRE팀 운영 채널에 요약해 올립니다. 요약에는 개인 비밀값 자체를 포함하지 않고, 권한 종류와 기간, 승인 여부만 적습니다.

## 예외 및 금지 사항

긴급 장애 대응 중이라도 민감 경로의 읽기 권한은 승인 없이 열지 않습니다. 승인 절차를 생략할 수 없으며, 요청과 승인 기록은 사후에 보완하는 방식이 아니라 작업 전에 남겨야 합니다.

다음 행위는 금지합니다.

1. 운영 비밀값을 개인 문서나 로컬 파일에 복사해 보관하는 행위
2. 승인된 범위를 넘어 다른 경로를 함께 조회하는 행위
3. 임시 권한 종료 후 재승인 없이 계속 사용하는 행위
4. 레드브릭소프트 인력에게 화면 공유, 메신저, 파일 전달 등으로 운영 비밀값을 우회 제공하는 행위

예외가 필요한 경우에는 플랫폼·SRE팀과 정보보안팀이 함께 검토합니다. 다만 외부 협력사에 대한 운영 비밀값 조회 금지 원칙은 예외 대상이 아닙니다.
