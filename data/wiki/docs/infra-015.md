# DB 관리자 긴급 작업 권한 절차

## 목적
이 문서는 운영 환경에서 즉시 대응이 필요한 상황에 한해 DB 관리자가 한시적으로 권한을 요청하고 사용 후 반납하는 절차를 정합니다. 대상은 플랫폼·SRE팀과 개발본부가 함께 보는 운영 정책이며, 운영 DB에 대한 직접 접근을 최소 범위로 통제하는 것을 목적으로 합니다.

긴급 권한은 상시 보유하지 않고, 필요한 시점에만 승인 후 발급합니다. 권한 사용 전에는 작업 범위와 목적을 명확히 남기고, 사용 후에는 조회 기록과 결과를 남겨 추적 가능해야 합니다.

## 적용 범위와 기본 규칙
적용 대상은 운영 DB를 관리하는 플랫폼팀과 데이터팀 소속 DB 관리자입니다. 외부 협력사와 일반 개발자는 이 절차의 대상이 아닙니다.

권한 요청 가능 범위는 다음과 같습니다.

| 구분 | 요청 가능 목적 | 비고 |
|---|---|---|
| 플랫폼팀 DB 관리자 | 인프라 장애 복구 목적의 운영 DB 권한 | 장애 대응과 복구에 한정합니다 |
| 데이터팀 DB 관리자 | 정산 검증 목적 권한만 요청할 수 있습니다 | 데이터팀의 일반 분석, 개발, 임시 조회 용도로는 요청할 수 없습니다 |

긴급 권한은 기본 "2시간" 동안 발급합니다. 작업이 끝나지 않아 연장이 필요하면 팀장 이상 관리자 1명의 승인을 다시 받아야 합니다. 최초 승인과 연장 승인은 각각 기록으로 남겨야 합니다.

권한 요청에는 아래 항목을 반드시 포함합니다.

1. 작업 대상
2. 실행 쿼리 요약
3. 금고 사용 여부

여기서 금고는 비밀값을 보관하는 비밀 관리 시스템을 뜻합니다. 금고를 사용한 경우에는 어떤 종류의 비밀값을 사용했는지 범주만 적고 실제 값은 남기지 않습니다.

## 요청 및 승인 절차
긴급 작업이 필요하면 요청자는 사내 메신저의 운영 채널 또는 지정된 운영 연락 수단에 요청을 남깁니다. 요청 본문에는 작업 목적, 영향 범위, 필수 기재 항목, 예상 소요 시간을 함께 적습니다. 팀장 이상 관리자는 요청 내용이 목적에 맞는지 확인한 뒤 승인 여부를 남깁니다.

권장 작성 형식은 아래와 같습니다.

```text
[긴급 권한 요청]
요청자: 홍길동
소속: 플랫폼팀 또는 데이터팀
목적: 인프라 장애 복구 / 정산 검증
작업 대상: 운영 DB명, 스키마, 테이블 또는 계정
실행 쿼리 요약: 조회 / 수정 / 잠금 확인 / 세션 종료 등
금고 사용 여부: 사용 / 미사용
예상 소요 시간: 30분
사유: 현재 서비스 영향 또는 검증 필요 내용
```

승인 후에는 필요한 최소 권한만 부여합니다. 요청 범위를 벗어나는 추가 작업이 필요하면 기존 승인에 포함되지 않은 것으로 보고 다시 요청합니다. 승인 없이 선조치 후보고 방식으로 운영 DB에 접근해서는 안 됩니다.

## 작업 수행과 반납
작업자는 승인된 범위 안에서만 작업합니다. 조회 위주 작업이라도 운영 영향이 예상되면 먼저 영향 범위를 확인하고, 수정 쿼리는 가능하면 재실행 가능성과 롤백 방법을 함께 검토합니다.

작업이 끝나면 즉시 권한을 반납합니다. 반납 후에는 "12시간 안"에 모아 조회 기록과 작업 결과를 운영 채널에 남겨야 합니다. 모아는 로그·지표·트레이스를 모으는 사내 관측 플랫폼을 뜻합니다. 보고에는 최소한 아래 내용을 포함합니다.

- 작업 시작 및 종료 시각
- 실제 실행한 작업 요약
- 모아 조회 기록 위치 또는 식별 정보
- 결과와 영향 범위
- 후속 확인 필요 사항

운영 채널 보고는 승인자와 관련 담당자가 사후 검토할 수 있을 정도로 구체적으로 작성합니다. 실제 비밀값, 개인 정보, 불필요한 원문 전체 쿼리는 남기지 않습니다.

## 역할과 책임
플랫폼팀 DB 관리자는 장애 복구에 필요한 범위에서 요청, 수행, 반납, 사후 보고를 책임집니다. 데이터팀 DB 관리자는 정산 검증 목적에 한해서만 동일한 절차를 따릅니다.

팀장 이상 관리자는 요청 목적의 적정성, 범위의 최소성, 연장 필요성을 검토하고 승인 기록을 남깁니다. 플랫폼·SRE팀은 권한 부여와 회수 상태를 확인하고, 절차 위반이 있으면 정보보안팀과 함께 재발 방지 조치를 검토합니다.
