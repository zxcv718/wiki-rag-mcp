# 누리 마감 전 점검 체크리스트

## 언제 쓰는가
이 문서는 누리 일일 정산 배치를 열기 전에 DRI가 수행하는 사전 점검용 런북입니다. 누리 마감 전 점검은 매일 22시 30분부터 시작하며 DRI가 체크리스트를 완료해야 배치를 열 수 있습니다.

점검 목적은 배치 시작 전에 데이터 이상 징후, 저장 공간 부족, 미해결 경보를 먼저 확인해 배치 지연과 재처리를 줄이는 것입니다. 점검 중 이상이 확인되면 배치를 바로 열지 말고 아래 에스컬레이션 절차에 따라 공유합니다.

## 사전 확인
점검 시작 전에 아래 항목을 확인합니다.

| 항목 | 확인 내용 | 조치 기준 |
|---|---|---|
| DRI 지정 | 당일 직접 책임자 1명이 정해졌는지 확인합니다. | 미지정 시 배치를 열지 않습니다. |
| 정산 원장 적재 대상 건수 | 당일 적재 대상 건수를 전일과 비교합니다. | 전일 대비 25% 이상 증가하면 데이터팀에 사전 확인을 요청합니다. |
| NR-503 경보 | 모아에서 NR-503 관련 미해결 경보를 조회합니다. NR-503은 누리 배치가 제시간에 끝나지 않을 때 뜨는 경보입니다. | 누리 마감 전에는 미해결 경보가 0건인지 확인합니다. |
| SP-E2003 잔존 여부 | 전날 배치에서 SP-E2003가 남아 있는지 확인합니다. | 해소되지 않은 채 남아 있으면 배치 시작 전에 원인 분류 메모를 남깁니다. |
| 저장 공간 | 배치가 쓰는 데이터 저장소와 로그 저장소의 여유 공간을 확인합니다. | 공간 부족 징후가 있으면 플랫폼·SRE팀에 공유합니다. |

## 단계별 점검 명령
아래 명령은 예시입니다. 실제 접속 정보와 비밀번호는 운영 환경 기준값을 사용합니다.

```bash
# 1) 정산 원장 적재 대상 건수 확인
psql -h <DB_HOST> -U <DB_USER> -d <DB_NAME> -c "
select biz_date, count(*) as target_count
from settlement_ledger_source
where biz_date in (current_date - interval '1 day', current_date)
group by biz_date
order by biz_date;
"

# 2) 저장 공간 확인
df -h
du -sh /var/log/* | sort -h | tail

# 3) 전날 SP-E2003 잔존 건 조회
psql -h <DB_HOST> -U <DB_USER> -d <DB_NAME> -c "
select biz_date, merchant_id, error_code
from settlement_error_history
where biz_date = current_date - interval '1 day'
  and error_code = 'SP-E2003'
  and resolved_at is null
limit 50;
"
```

모아에서는 누리 관련 대시보드에서 미해결 NR-503 경보 목록을 확인합니다. 모아는 로그, 지표, 트레이스를 모으는 사내 관측 플랫폼입니다. 조회 시 현재 시점에 열린 경보만 보지 말고, 당일 점검 시각까지 자동 해제되지 않고 남아 있는 항목이 있는지 함께 확인합니다.

SP-E2003가 남아 있으면 DRI는 배치 시작 전에 작업 기록에 원인 분류 메모를 남깁니다. 메모에는 데이터 이상, 입력 지연, 원장 불일치 재현 여부 정도만 간단히 적고 추정 원인을 단정하지 않습니다.

## 결과 확인
아래 조건을 모두 만족하면 배치를 열 수 있습니다.

1. DRI가 당일 점검 완료를 선언했습니다.
2. 정산 원장 적재 대상 건수 증가폭이 허용 범위이거나, 증가폭이 큰 경우 데이터팀 확인이 끝났습니다.
3. 모아에서 NR-503 관련 미해결 경보가 0건입니다.
4. SP-E2003 잔존 건이 없거나, 남아 있는 경우 원인 분류 메모가 기록되었습니다.
5. 저장 공간 부족 징후가 없습니다.

점검 결과는 사내 메신저 운영 채널에 아래 형식으로 남깁니다.

```text
[누리 마감 전 점검 완료]
- DRI: <이름>
- 대상 건수: 전일 대비 <증감률>
- NR-503 미해결: 0건 여부
- SP-E2003 잔존: 없음 / 있음(메모 기록 완료)
- 저장 공간: 정상 / 확인 필요
- 배치 시작 가능 여부: 가능 / 보류
```

## 에스컬레이션
다음 경우에는 배치를 바로 열지 않고 공유합니다.

- 정산 원장 적재 대상 건수가 전일 대비 25% 이상 증가했고 데이터팀 확인이 끝나지 않은 경우
- NR-503 미해결 경보가 0건이 아닌 경우
- 저장 공간 부족으로 배치 중단 가능성이 있는 경우
- SP-E2003가 반복 발생하고 원인 분류가 어려운 경우

연락 순서는 다음과 같습니다.

1. 플랫폼·SRE팀 당직자 또는 담당자에게 현재 상태를 공유합니다.
2. 데이터 이상 징후가 있으면 데이터팀에 사전 확인을 요청합니다.
3. 배치 시작 지연이 예상되면 개발본부 내 관련 담당자에게 알립니다.

공유 메시지에는 발생 시각, 현재 영향, 이미 확인한 항목, 배치 시작 가능 여부만 적습니다. 확인되지 않은 원인은 추정으로 쓰지 않습니다.
