# 결제 승인 재시도 초과 장애 PIR

## 요약
2026-04에 결제 승인 실패가 비정상적으로 증가한 장애에 대한 PIR 문서입니다. 이번 장애에서는 카드 승인 재시도 횟수를 넘긴 에러인 SP-E1001이 42분 동안 평시 대비 6배까지 증가했습니다. 증가 양상은 솔게이트의 재시도 동작이 의도와 다르게 바뀌었음을 바로 보여 주는 신호였습니다.

직접 원인은 하늘 배포 중 솔게이트 재시도 제한값이 잘못 적용된 것입니다. 이 값 변경으로 일부 승인 요청이 정상적인 재시도 여지를 갖지 못했고, 일시적인 승인 실패가 최종 실패로 빠르게 확정되었습니다. 장애 인지 후 하늘에서 직전 정상 설정으로 되돌려 지표를 안정화했습니다.

## 영향
고객 영향은 결제 시도 18,240건 중 913건 실패였습니다. 실패 건은 특정 카드사나 특정 가맹점군에만 한정되지 않고 여러 구간에 분산되어 나타났습니다. 대부분 1회 재시도로 복구되지 않았으며, 사용자는 결제 화면에서 반복 실패를 경험하거나 다른 결제 수단으로 전환해야 했습니다.

고객지원팀에는 결제 실패 문의가 평시보다 빠르게 유입되었고, 제품기획팀은 공지 문안 초안을 준비했습니다. 개발본부와 플랫폼·SRE팀은 영향 범위를 확인하면서 복구를 우선 진행했습니다. 데이터팀은 사후 집계 기준을 맞추는 데 협조했습니다.

## 원인
직접 원인은 솔게이트 재시도 제한값이 하늘 배포 중 잘못 적용된 것입니다. 코드 자체의 승인 처리 로직보다 배포 시 반영된 설정값이 문제였습니다. 그 결과 일시적 실패를 흡수해야 하는 요청도 허용 횟수에 빨리 도달했고, SP-E1001이 급증했습니다.

배경 원인은 두 가지입니다.
1. 핫픽스와 일반 배포에서 공통으로 확인해야 하는 설정 검증 항목이 문서상 분리되어 있지 않았습니다.
2. 모아 대시보드에는 승인 실패율과 전체 오류율은 있었지만, SP-E1001만 따로 보는 전용 시야가 부족했습니다.

## 잘한 점과 아쉬운 점
잘한 점은 다음과 같습니다.
- SP-E1001 증가를 초기에 포착해 원인 범위를 빠르게 좁혔습니다.
- 하늘의 롤백 절차가 정리되어 있어 복구 자체는 지연 없이 수행했습니다.
- 고객지원팀 공유가 비교적 빨라 현장 응대 문구를 빠르게 맞출 수 있었습니다.

아쉬운 점은 다음과 같습니다.
- 재시도 관련 설정이 승인 품질에 미치는 영향도에 비해 배포 전 확인이 약했습니다.
- 모아에서 에러 코드별 추세를 바로 보지 못해 초동 판단에 몇 분의 우회가 있었습니다.
- 대부분 1회 재시도로 복구되지 않았다는 사실을 초기에 정량화하지 못해 영향 설명이 다소 늦었습니다.

## 재발 방지 작업
| 작업 | 내용 | 담당 | 상태 |
|---|---|---|---|
| 관측 보강 | 모아에 SP-E1001 전용 패널을 추가합니다. 에러 건수, 비율, 최근 배포 시각을 함께 보이도록 구성합니다. | 플랫폼·SRE팀 | 완료 |
| 배포 점검 강화 | 핫픽스 창구 승인 템플릿에 재시도 설정 확인란을 넣습니다. 설정 변경 여부와 검토자를 함께 남기도록 합니다. | 제품기획팀, 플랫폼·SRE팀 | 완료 |
| 설정 검토 절차 정리 | 솔게이트 배포 시 재시도 관련 설정을 별도 항목으로 검토합니다. | 개발본부 | 진행 |
| 사후 검증 추가 | 배포 직후 승인 실패율과 SP-E1001 추세를 확인하는 체크리스트를 운영합니다. | 플랫폼·SRE팀 | 진행 |

이번 PIR의 결론은 장애 징후 자체는 비교적 빨리 보였지만, 재시도 설정을 배포 안전장치로 다루는 수준이 부족했다는 점입니다. 이후 동일 유형의 장애는 배포 전 확인과 배포 직후 관측만 강화해도 상당 부분 예방 가능하다고 판단합니다.
