# 솔게이트 장애 우회 라우팅 런북

## 언제 사용합니까
이 문서는 솔게이트에서 특정 PG사 구간 장애가 발생해 결제 실패가 늘어날 때 임시로 우회 라우팅을 적용하는 절차를 안내합니다. 시작 조건은 PRJ-204가 5분 평균 3%를 넘을 때입니다. 이 수치를 넘으면 즉시 전체 전환을 하지 않고, 원인과 영향 범위를 먼저 확인한 뒤 제한적으로 적용합니다.

우회 라우팅은 PG사 응답 지연이나 시간 초과가 주된 문제일 때 사용합니다. 반대로 같은 시점에 GW-429가 함께 증가하는 경우 우회 라우팅보다 가맹점별 호출 제한 완화를 먼저 검토해야 합니다. 호출 제한 문제를 해소하지 않으면 우회 후에도 실패가 계속될 수 있습니다.

## 사전 확인
아래 항목을 순서대로 확인합니다.

1. PRJ-204 증가가 특정 PG사에 집중되는지 확인합니다.
2. 증가 시점이 배포, 네트워크 작업, 데이터베이스 작업과 겹치지 않는지 확인합니다.
3. GW-429 동반 증가 여부를 확인합니다.
4. 고객지원팀에서 동일 시간대 가맹점 문의가 늘었는지 확인합니다.
5. 제품기획팀에 외부 공지 필요 가능성을 알립니다.

판단 기준은 아래와 같습니다.

| 확인 항목 | 우회 진행 | 우회 보류 |
|---|---|---|
| PRJ-204만 주로 증가 | 진행 검토 |  |
| GW-429도 함께 증가 |  | 호출 제한 완화 우선 검토 |
| 특정 PG사로 영향이 모임 | 진행 적합 |  |
| 원인이 내부 변경으로 의심됨 |  | 원인 확인 우선 |

## 단계별 절차
전체 전환 전에는 하늘에서 대상 가맹점 20곳만 먼저 변경해 10분간 결과를 봅니다. 하늘은 사내 배포 도구로 카나리 배포와 롤백을 지원합니다.

1. 온콜 채널에 우회 검토 시작을 알립니다.
2. 대상 PG사와 영향 가맹점 목록을 정리합니다.
3. 하늘에서 대상 가맹점 20곳만 카나리로 변경합니다.
4. 10분 동안 PRJ-204, 승인 성공률, 취소 요청 증가 여부를 관찰합니다.
5. 문제가 완화되면 대상 범위를 확대합니다.
6. 확대 후에도 동일 지표를 계속 확인합니다.

```bash
# 1) 현재 상태 확인
kubectl logs deploy/solgate -n prod --since=10m | grep 'PRJ-204'

# 2) 설정 백업
kubectl get configmap solgate-routing -n prod -o yaml > solgate-routing-backup.yaml

# 3) 카나리 적용
kubectl edit configmap solgate-routing -n prod

# 4) 반영 확인
kubectl rollout restart deploy/solgate -n prod
kubectl rollout status deploy/solgate -n prod
```

설정 편집 시에는 대상 가맹점만 우회 대상으로 넣고, 나머지는 유지합니다. 한 번에 전체를 바꾸지 않습니다.

## 결과 확인과 되돌리기
카나리 10분 동안 아래 항목을 확인합니다.

- 대상 가맹점의 PRJ-204 감소
- 승인 성공률 회복
- GW-429 추가 증가 없음
- 고객지원팀 문의 급증 없음

카나리 결과가 나쁘면 즉시 되돌립니다.

```bash
# 백업으로 복구
kubectl apply -f solgate-routing-backup.yaml -n prod
kubectl rollout restart deploy/solgate -n prod
kubectl rollout status deploy/solgate -n prod
```

전체 적용 후에도 효과가 없거나 다른 PG사 실패가 늘면 같은 절차로 원복합니다. 원복 후에는 장애 원인이 우회 대상 PG사 자체인지, 호출량 분산 실패인지 다시 구분합니다.

## 에스컬레이션과 종료
아래 경우에는 즉시 에스컬레이션합니다.

- 카나리 10분 내 실패율이 개선되지 않습니다.
- 우회 후 GW-429가 빠르게 증가합니다.
- 두 개 이상 PG사에서 동시에 유사 증상이 보입니다.
- 고객지원팀에서 다수 가맹점의 결제 불가 문의를 전달합니다.

에스컬레이션 대상은 플랫폼·SRE팀 온콜, 페이코어 온콜, 필요 시 DB 관리자와 정보보안팀입니다. 대외 안내 문구가 필요하면 제품기획팀과 고객지원팀이 함께 정리합니다.

우회 종료는 대상 PG사의 응답이 안정화되고 우회 없이도 PRJ-204가 다시 기준 아래로 유지될 때 진행합니다. 종료 후에는 온콜 채널에 적용 시간, 영향 범위, 전환 결과를 남깁니다. PIR은 장애 사후 검토 회의와 그 문서를 뜻합니다. 우회 종료 후 2시간 안에 PIR 필요 여부를 온콜 채널에서 결정합니다.
