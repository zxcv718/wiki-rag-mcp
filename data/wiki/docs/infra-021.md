# CAB 운영 변경 심의 기준

## 목적
이 문서는 운영 변경을 승인하는 변경 승인 위원회인 CAB에 올려야 하는 변경 범위와 제출 시한, 승인 조건, 예외 처리 기준을 정리합니다. 대상 독자는 플랫폼·SRE팀과 개발본부입니다. 본 기준은 운영 환경의 안정성과 변경 이력의 추적 가능성을 확보하는 데 목적이 있습니다.

CAB 심의는 변경 자체를 지연시키기 위한 절차가 아니라, 운영 영향이 있는 변경에 대해 사전 검토와 책임 소재를 분명히 하기 위한 절차로 운영합니다. 따라서 심의 대상 여부가 불명확한 경우에는 미제출보다 사전 문의를 우선합니다.

## 심의 대상과 제출 기준
다음 변경은 CAB 심의 대상입니다.

- 운영 트래픽에 영향이 있는 인프라 변경
- 운영 DB 스키마 변경
- 네트워크 정책 변경

위 항목에 해당하지 않더라도, 변경 수행자가 운영 영향 가능성을 배제하기 어렵다고 판단하면 CAB 안건으로 제출합니다. 반대로 개발 환경이나 개인 검증 환경에 한정되고 운영 경로와 분리된 변경은 본 문서의 심의 대상이 아닙니다.

CAB 안건은 정기 회의 시작 24시간 전까지 제출해야 합니다. 제출 시에는 아래 항목을 함께 포함합니다.

1. RFC 링크
2. 변경 목적과 예상 영향
3. 작업 예정 시간
4. 롤백 계획
5. 변경 수행 담당자와 연락 수단

RFC는 구조 변경 전에 작성하는 설계 제안서이며, 리뷰를 거쳐 승인된 문서를 기준으로 합니다. RFC 링크가 없거나 롤백 계획이 누락된 안건은 원칙적으로 심의하지 않습니다.

## 정기 CAB 운영
정기 CAB는 매주 목요일 16시에 진행합니다. 참석자는 플랫폼·SRE팀, 정보보안팀, 제품기획팀에서 각 1명입니다. 필요 시 안건 제출자나 관련 작업 담당자가 설명을 위해 참석할 수 있으나, 정기 참석자로 간주하지는 않습니다.

정기 CAB에서는 다음 항목을 확인합니다.

| 확인 항목 | 내용 |
|---|---|
| 운영 영향 | 사용자 요청 처리, 데이터 정합성, 네트워크 통신에 미치는 영향 |
| 사전 검토 | RFC 승인 여부와 관련 팀 검토 반영 여부 |
| 실행 가능성 | 작업 절차의 구체성, 담당자 지정 여부 |
| 복구 가능성 | 롤백 계획의 현실성, 실패 시 중단 기준 |
| 커뮤니케이션 | 변경 공지 필요 여부와 영향 대상 확인 |

승인 조건은 참석자 간 이견이 없고, 운영 영향과 복구 방안이 문서로 확인 가능한 상태여야 합니다. 보완이 필요한 안건은 수정 후 다음 정기 CAB에 재제출합니다. 다만 제출 시한을 넘긴 안건은 긴급 변경 사유가 없는 한 같은 주 회의에서 다루지 않습니다.

## 역할과 책임
플랫폼·SRE팀은 CAB 운영 주관과 회의 진행, 변경 기록 보관을 담당합니다. 개발본부의 변경 수행자는 심의 대상 여부를 확인하고, 기한 내에 RFC 링크와 롤백 계획을 포함한 안건을 제출합니다.

정보보안팀은 네트워크 정책 변경과 보안 영향이 있는 항목을 검토합니다. 제품기획팀은 사용자 공지나 배포 시점 조정이 필요한 변경의 일정 영향을 검토합니다. 운영 DB 관련 변경은 실제 작업 주체가 누구인지와 무관하게 변경 내용과 복구 절차를 명확히 적어야 하며, DB 관리자가 검토에 참여할 수 있습니다.

회의 결과와 후속 조치는 문서로 남깁니다. 변경 수행자는 승인된 범위를 벗어나지 않도록 작업해야 하며, 작업 중 계획과 다른 영향이 확인되면 즉시 중단 여부를 판단하고 관련자에게 공유합니다.

## 예외와 사후 보고
장애 대응, 보안 이슈 차단, 서비스 지속성 확보를 위한 긴급 변경은 CAB 사후 보고가 가능합니다. 이 경우에도 변경 수행자는 가능한 범위에서 최소한의 영향 검토와 복구 방안을 먼저 정리해야 합니다.

긴급 변경은 배포 후 1영업일 안에 기록을 남겨야 합니다. 사후 기록에는 다음 내용을 포함합니다.

- 긴급 변경 사유
- 실제 작업 시각
- 수행 내용
- 운영 영향 여부
- 롤백 실행 여부 또는 불필요 판단 근거
- 후속 조치

사후 보고가 반복되거나 긴급 사유가 불명확한 경우, 플랫폼·SRE팀은 해당 변경 유형을 정기 CAB 선심의 대상으로 재분류할 수 있습니다. 운영 안정성에 직접 영향을 주는 변경은 예외 적용을 최소화합니다.
