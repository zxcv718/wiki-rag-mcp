# 운영 서버 접근 기록 감사

## 목적
이 문서는 운영 서버에 대한 접근 기록을 일관되게 수집, 보관, 검토하기 위한 기준을 정합니다. 접근 기록 감사의 목적은 운영 변경의 추적 가능성을 확보하고, 승인되지 않은 계정 사용이나 비정상 접근을 조기에 발견하는 데 있습니다.

이 문서에서 금고는 비밀값을 보관하는 비밀 관리 시스템을 뜻합니다. 운영 서버 접근에 사용되는 계정과 인증 정보는 금고를 기준으로 관리하며, 접근 기록 감사도 이를 기준으로 판단합니다.

## 적용 범위와 보관 기준
적용 대상은 플랫폼·SRE팀이 관리하는 운영 서버와, 개발본부가 운영 목적으로 접속하는 서버 접근 행위 전체입니다. 여기에는 대화형 로그인, 점검을 위한 원격 접속, 자동화 도구를 통한 서버 세션 시작 기록이 포함됩니다.

접근 기록에는 최소한 아래 항목이 남아야 합니다.

| 항목 | 내용 |
| --- | --- |
| 접속 시각 | 서버에 접근한 시각 |
| 접속 주체 | 개인 계정 또는 서비스 계정 식별값 |
| 대상 서버 | 호스트명 또는 식별 가능한 서버 정보 |
| 접속 방식 | SSH 등 사용한 접근 방식 |
| 수행 결과 | 성공, 실패 여부 |
| 출처 정보 | 접속한 원격 주소 등 확인 가능한 정보 |

접근 기록은 삭제나 임의 수정이 불가능한 위치에 저장하며, "1년 보관"합니다. 보관 중인 기록은 감사 목적의 조회가 가능해야 하며, 장애 대응 과정에서 생성된 관련 기록도 동일 기준으로 취급합니다.

## 검토 절차
플랫폼·SRE팀은 매월 "첫 영업일"에 전월 기록을 검토합니다. 검토는 최소 1명의 담당자가 수행하고, 필요 시 다른 담당자가 교차 확인합니다. 검토 시 아래 항목을 우선 확인합니다.

1. 등록된 운영 계정 외 계정의 접근 여부를 확인합니다.
2. 퇴사자, 권한 변경자, 사용 중지 예정 계정의 접근 여부를 확인합니다.
3. 평소 사용 시간대와 다른 접근이나 반복 실패 기록을 확인합니다.
4. 동일 계정의 다중 서버 연속 접근 등 비정상 패턴을 확인합니다.
5. 금고에 등록되지 않은 인증 정보 사용 정황을 확인합니다.

특히 금고 밖에서 발급된 계정이 보이면 "즉시 차단"합니다. 차단 후에는 해당 계정의 사용 이력을 확인하고, 관련 서버의 추가 접근 여부를 점검합니다. 검토 결과 이상이 없더라도 검토 일시, 검토자, 확인 범위, 후속 조치 유무를 문서로 남깁니다.

## 역할과 책임
플랫폼·SRE팀은 접근 기록 수집 설정 유지, 보관 상태 점검, 월간 검토 수행을 담당합니다. 운영 서버에서 기록이 누락되지 않도록 설정 변경 시 함께 확인합니다.

개발본부는 운영 서버 접근 시 승인된 계정만 사용해야 하며, 개인 편의를 위한 임시 계정 생성이나 인증 정보 공유를 해서는 안 됩니다. 접근 목적이 끝난 계정은 계속 사용하지 않도록 플랫폼·SRE팀과 정리합니다.

DB 관리자는 운영 DB가 설치된 서버 또는 관련 운영 서버 접근 기록이 누락되지 않도록 플랫폼·SRE팀과 협조합니다. 데이터팀 소속 DB 관리자도 운영 DB 접근 시 동일 기준을 따릅니다.

정보보안팀은 감사 기준의 적정성을 검토하고, 이상 징후 발생 시 조사에 참여할 수 있습니다. 제품기획팀과 고객지원팀은 직접 운영 서버에 접근하지 않으며, 필요한 경우 정식 요청 절차를 통해 플랫폼·SRE팀에 전달합니다.

## 예외와 보고
긴급 장애 대응으로 평소와 다른 시간대 또는 방식의 접근이 필요한 경우가 있습니다. 이 경우에도 승인된 계정을 사용해야 하며, 사후에 접근 사유와 조치 내용을 남겨야 합니다. 기록 수집 자체가 실패한 경우에는 복구 전까지의 공백 구간, 영향 범위, 재발 방지 조치를 함께 기록합니다.

외부 협력사는 원칙적으로 운영 서버에 직접 접근하지 않습니다. 업무상 불가피한 경우에도 플랫폼·SRE팀 책임자 확인 없이 계정을 발급하지 않습니다. 예외 접근이 허용된 경우에도 접근 기록은 동일하게 남겨야 하며, 검토 대상에서 제외하지 않습니다.

이상 징후나 무단 계정 사용이 확인되면 플랫폼·SRE팀은 정보보안팀에 즉시 공유하고, 필요 시 경영진·팀장에 보고합니다. 문의는 플랫폼·SRE팀 메일 sresupport@saesol.example로 접수합니다.
