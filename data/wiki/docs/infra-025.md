# 관측성 경보 소유자 매핑표

## 목적
이 문서는 주요 운영 경보의 소유 팀과 역할을 일관되게 확인하기 위한 기준입니다. 경보가 발생했을 때 누가 먼저 확인하고, 누가 서비스 영향과 업무 영향을 판단하며, 누가 후속 조치를 이어받는지 빠르게 정하는 데 목적이 있습니다.

이 문서는 플랫폼·SRE팀과 개발본부가 공통으로 참고하는 운영 정책입니다. 경보 자체의 생성 조건이나 임계값을 설명하는 문서가 아니라, 이미 발생한 경보에 대해 소유자를 정하는 문서로 사용합니다.

## 적용 규칙
1. 각 경보에는 운영 대응을 시작하는 1차 소유자와 필요 시 인계받는 2차 소유자를 둡니다.
2. 서비스 동작 확인이 필요한 경보는 서비스 소유자를 함께 지정합니다.
3. 업무 의미 확인이 필요한 경보는 업무 확인 소유자와 기술 소유자를 구분합니다.
4. 모든 P1 경보는 15분 안에 DRI 이름이 온콜 채널에 명시되지 않으면 팀장 이상 관리자에게 자동 알림이 갑니다.
5. DRI는 해당 시점의 직접 책임자 한 명만 지정합니다. 공동 대응자는 있을 수 있으나 온콜 채널에는 대표 DRI 한 명을 먼저 적습니다.
6. 소유자가 둘 이상인 경우에도 초기 상황 공유는 1차 소유자가 시작합니다.

## 경보별 소유자 매핑
| 경보 | 설명 | 1차 소유자 | 2차 소유자 | 서비스 소유자 | 업무 확인 소유자 | 기술 소유자 |
|---|---|---|---|---|---|---|
| NR-503 | 누리 배치가 제시간에 끝나지 않을 때 뜨는 경보 | 플랫폼·SRE팀 온콜 | 데이터팀 DB 관리자 |  |  |  |
| PRJ-204 | 솔게이트가 PG사 응답을 기다리다 시간 초과된 에러 | 플랫폼·SRE팀 온콜 |  | 개발본부 페이코어 스쿼드 |  |  |
| GW-429 | 가맹점별 솔게이트 호출 한도를 넘긴 에러 | 플랫폼·SRE팀 온콜 |  | 개발본부 페이코어 스쿼드 |  |  |
| BK-4010 | 솔북에서 같은 예약 슬롯이 두 번 잡힌 에러 | 플랫폼·SRE팀 온콜 |  |  | 제품기획팀 솔북 담당자 | 개발본부 |

위 표에서 빈 칸은 소유자가 없다는 뜻이 아니라, 이 문서에서 별도 역할로 분리하지 않는다는 뜻입니다. 실제 대응 중 추가 협조가 필요하면 관련 팀에 즉시 공유합니다.

## 역할과 책임
플랫폼·SRE팀 온콜은 경보 수신, 중복 여부 확인, 초기 영향 범위 파악, DRI 지정 여부 확인을 담당합니다. NR-503처럼 배치 지연이 확인된 경우에는 데이터팀 DB 관리자에게 운영 관점의 후속 확인을 요청합니다.

개발본부 페이코어 스쿼드는 PRJ-204와 GW-429 경보에서 서비스 소유자입니다. 서비스 소유자는 재현 가능성, 사용자 영향, 코드 또는 설정 변경 필요성을 판단합니다. 플랫폼·SRE팀은 인프라 관점의 상태를 함께 확인하지만, 서비스 동작 판단은 페이코어가 맡습니다.

BK-4010은 기술 문제와 업무 판단이 함께 필요한 경보입니다. 제품기획팀 솔북 담당자는 실제 예약 정책상 어떤 조치가 필요한지 확인합니다. 개발본부는 원인 분석과 수정 방향을 책임집니다. 두 역할 중 어느 한쪽 판단만으로 종결하지 않습니다.

## 예외와 운영 메모
정규 근무시간 밖이라도 P1 경보의 DRI 지정 규칙은 동일하게 적용합니다. 자동 알림이 발송된 뒤에는 팀장 이상 관리자가 직접 DRI를 지정하거나 지정 여부를 확인할 수 있습니다.

경보가 둘 이상 동시에 발생해 동일 원인으로 보이는 경우에도, 온콜 채널에는 경보별 DRI 또는 대표 DRI 적용 여부를 분명히 남깁니다. 다만 소유자 매핑 자체는 이 문서의 표를 우선합니다.

표에 없는 신규 경보는 임시로 플랫폼·SRE팀 온콜이 접수하고, 사후에 이 문서를 갱신합니다. 문서 수정 제안은 플랫폼·SRE 스페이스에서 받고, 업무 확인 소유자가 필요한 항목은 제품기획팀과 사전 합의 후 반영합니다.
