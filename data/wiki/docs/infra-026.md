# 모아 서비스별 대시보드 표준

## 목적과 적용 범위
이 문서는 모아에서 서비스 공통으로 사용하는 기본 대시보드 구성을 정의합니다. 모아는 로그·지표·트레이스를 모으는 사내 관측 플랫폼입니다. 플랫폼·SRE팀이 기본 틀을 관리하고, 개발본부 각 서비스 담당자는 서비스별 세부 패널을 보완합니다.

적용 대상은 운영 환경에 배포되는 서비스입니다. 신규 서비스와 기존 서비스 모두 동일한 기준을 따릅니다. 개별 서비스 특성에 따라 패널을 추가할 수 있으나, 공통 영역의 순서와 포함 항목은 변경하지 않습니다.

## 기본 구성 요소
모아의 서비스 기본 대시보드는 지연 시간, 오류율, 처리량, 포화도 4개 섹션을 같은 순서로 둡니다. 이 순서는 서비스 상태를 빠르게 해석하기 위한 공통 기준이며, 상단 요약 카드와 상세 그래프 모두 같은 흐름을 유지합니다.

대시보드 상단에는 아래 항목을 고정합니다.

| 항목 | 내용 |
| --- | --- |
| 서비스명 | 운영 중인 서비스의 표시 이름 |
| 담당 조직 | 서비스 담당 스쿼드 |
| 연락 정보 | 온콜 채널 링크 |
| 관련 문서 | 운영 절차 문서, PIR 문서 링크 |

각 섹션은 최소한 다음 정보를 포함합니다.

1. 지연 시간  
   대표 요청의 응답 시간 분포와 상위 구간 추이를 표시합니다.

2. 오류율  
   전체 요청 대비 실패 비율과 주요 오류 유형의 변화를 표시합니다.

3. 처리량  
   단위 시간당 요청 수, 작업 수, 메시지 처리량 등 서비스의 핵심 처리 규모를 표시합니다.

4. 포화도  
   CPU, 메모리, 디스크, 연결 수, 작업 대기열 등 자원 압박 상태를 표시합니다.

로그 패널은 각 섹션 하단 또는 우측에 배치해 같은 시간 범위에서 바로 비교할 수 있게 합니다. 트레이스 패널은 최근 오류와 고지연 요청을 바로 열 수 있는 형태로 둡니다.

## 데이터 흐름과 조회 기준
서비스는 애플리케이션 로그, 시스템 지표, 분산 트레이스를 모아로 전송합니다. 하나의 장애 징후를 볼 때는 지표에서 이상 구간을 찾고, 같은 시간 범위의 로그와 트레이스로 원인을 좁히는 흐름을 기본으로 합니다.

트레이스 조회 기준은 다음과 같습니다.

- 운영 환경의 모아 트레이스 보존 기간은 14일입니다.
- 그 이후의 장애 분석 이력은 장기 보존을 위해 트레이스를 별도로 남기지 않고, PIR 링크로 대체합니다.
- 대시보드에서 최근 장애와 관련된 PIR 문서가 있으면 관련 문서 영역에 함께 연결합니다.

서비스 간 호출이 있는 경우에는 같은 요청을 한 번에 추적할 수 있어야 합니다. 특히 솔북과 솔페이 연동 구간은 모아에서 동일한 trace_id로 조회되도록 배포 전 검증해야 합니다. 검증 시에는 연동 요청 1건 이상을 실제 흐름으로 실행해 양쪽 서비스의 로그와 트레이스에서 같은 trace_id가 이어지는지 확인합니다.

## 의존 서비스와 책임
대시보드 운영에는 여러 조직이 관여합니다.

| 조직 | 책임 |
| --- | --- |
| 플랫폼·SRE팀 | 공통 템플릿 제공, 수집 파이프라인 운영, 조회 성능 점검 |
| 개발본부 서비스 담당자 | 서비스 패널 정의, 경보와 대시보드 정합성 유지 |
| DB 관리자 | 운영 DB 관련 지표와 로그 노출 기준 검토 |
| 정보보안팀 | 로그와 트레이스에 포함되는 민감 정보 검토 |
| 제품기획팀 | 릴리스 전 관측 가능성 확인이 필요한 변경 공유 |

DB 관련 패널은 애플리케이션 상태를 설명하는 범위에서만 포함합니다. 운영 DB의 상세 관리 화면을 대체하려는 목적의 과도한 패널 추가는 지양합니다.

## 운영 시 주의점
대시보드는 장애 대응과 일상 점검에 모두 쓰이므로, 서비스 담당자는 릴리스마다 패널 유효성을 확인합니다. 새 엔드포인트, 비동기 작업, 외부 연동이 추가되면 지연 시간과 오류율 패널이 실제 사용자 영향 구간을 반영하는지 먼저 봅니다.

주의 사항은 다음과 같습니다.

- 상단의 담당 조직과 온콜 채널 링크가 최신인지 확인합니다.
- 로그 패널에는 개인정보, 결제 수단 원문, 비밀번호, 토큰을 노출하지 않습니다.
- 패널 이름은 기능명보다 사용자 영향이 드러나는 표현을 우선합니다.
- 지표, 로그, 트레이스의 시간대와 필터 기준을 맞춰 동일 사건을 비교할 수 있게 합니다.
- 장애 종료 후 PIR이 작성되면 관련 대시보드에서 바로 접근할 수 있게 링크를 추가합니다.

대시보드는 많을수록 좋은 것이 아니라, 장애 시 바로 판단 가능한 구성이 중요합니다. 공통 구조를 유지한 상태에서 서비스 특성을 드러내는 보조 패널만 추가하는 것을 원칙으로 합니다.
