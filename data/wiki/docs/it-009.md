# 솔넷 VPN 접속 불가 점검 체크리스트

## 문서 목적과 적용 범위
이 문서는 솔패스 연결 실패 시 사용자가 먼저 확인할 항목과, IT 헬프데스크 또는 관련 팀으로 전달해야 하는 기준을 정리한 문제 해결 문서입니다.

여기서 말하는 솔넷 VPN은 2026년 6월까지 쓰던 옛 VPN을 뜻합니다. 접속 주소, 설치 파일, 클라이언트 종류 자체는 다른 문서 기준을 따릅니다. 이 문서는 접속 불가 상황의 1차 점검과 에스컬레이션 판단만 다룹니다.

## 먼저 확인할 공통 사항
아래 항목은 증상과 관계없이 먼저 확인합니다.

1. 사내 계정으로 로그인한 상태인지 확인합니다.
2. 인터넷 연결이 정상인지 확인합니다.
3. 다른 웹사이트 접속이 가능한지 확인합니다.
4. 이미 실행 중인 VPN 클라이언트 창이 멈춰 있지 않은지 확인합니다.
5. 같은 시각에 주변 동료도 유사한 증상을 겪는지 확인합니다.

다음 표를 기준으로 증상을 나눠서 확인합니다.

| 증상 | 우선 확인 | 다음 조치 |
|---|---|---|
| 연결 버튼을 눌러도 실패함 | 클라이언트 상태 | 완전 종료 후 재실행 |
| 인증은 되었으나 내부 서비스가 열리지 않음 | 최근 장애 공지 | 공지 없으면 티켓 등록 |
| VPN과 모아가 함께 안 열림 | 네트워크 범위 | 플랫폼·SRE팀 온듀티로 전달 |

## 증상 1. 연결 시도가 반복해서 실패합니다
### 원인
클라이언트 프로세스가 비정상 상태이거나, 이전 연결 세션이 남아 있을 수 있습니다.

### 조치
솔넷 VPN 접속 실패가 3회 연속 발생하면 VPN 클라이언트를 완전히 종료한 뒤 다시 연결합니다. 창만 닫지 말고 실행 중인 프로세스가 남아 있지 않은지 확인한 다음 다시 실행합니다.

그래도 동일하면 아래 내용을 정리해 IT 헬프데스크에 전달합니다.

- 발생 시각
- 사용 중인 운영체제
- 사내 계정
- 화면에 보이는 실패 문구
- 재실행 후에도 동일한지 여부

## 증상 2. 인증은 통과했지만 내부 서비스가 열리지 않습니다
### 원인
사용자 단말 문제일 수도 있지만, 일시적인 내부 구간 장애일 수도 있습니다.

### 조치
인증은 통과했지만 내부 서비스가 열리지 않으면 IT 헬프데스크 공지에서 최근 1시간 장애 공지를 먼저 확인합니다. 공지가 있으면 해당 공지의 안내에 따릅니다.

최근 공지가 없으면 브라우저를 새로 고침하고, 다른 내부 서비스도 같은지 확인한 뒤 IT 헬프데스크에 티켓을 등록합니다. 티켓에는 최소한 아래를 포함합니다.

- 인증 성공 여부
- 열리지 않는 내부 서비스 범위
- 최초 발생 시각
- 스크린샷 가능 여부

## 증상 3. 모아 접속도 함께 실패합니다
### 원인
개별 사용자 문제보다 네트워크 이슈 가능성이 높습니다.

### 조치
모아 접속도 함께 실패하면 네트워크 이슈 가능성이 높아 IT 헬프데스크가 아니라 플랫폼·SRE팀 온듀티로 바로 전달합니다.

전달 시 아래 내용을 함께 보냅니다.

- VPN 접속 실패 여부
- 모아 접속 실패 여부
- 현재 사용 중인 네트워크 환경
- 동일 증상 사용자 유무
- 발생 시각

사용자는 중복 문의를 줄이기 위해 동일 건으로 IT 헬프데스크 티켓을 별도로 추가 등록하지 않습니다. 다만 플랫폼·SRE팀 요청이 있으면 후속 정보는 보완합니다.

## 에스컬레이션 기준
다음 기준으로 접수 대상을 구분합니다.

1. 단순 연결 실패 재현, 클라이언트 재실행 후에도 동일함
   - IT 헬프데스크로 전달합니다.
2. 인증 성공 후 내부 서비스만 열리지 않음
   - 최근 공지 확인 후, 공지 없으면 IT 헬프데스크로 전달합니다.
3. VPN 문제와 함께 모아도 접속 불가
   - 플랫폼·SRE팀 온듀티로 바로 전달합니다.
4. 고객지원팀의 L2 에스컬레이션 대응 중 발생한 솔넷 VPN 장애
   - 티켓 우선순위를 P2로 등록합니다.

티켓 등록 시 제목은 증상이 드러나게 간단히 작성하고, 본문에는 재현 여부와 확인한 조치를 빠짐없이 적습니다. 문의 채널이 여러 개여도 동일 이슈는 한 건으로 관리합니다.
