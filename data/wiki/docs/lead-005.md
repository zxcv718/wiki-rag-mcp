# 코드 프리즈 예외 처리 검토 회의록

## 일시와 참석자
- 일시: 2026-06-17 14:00~14:50
- 장소: 본사 5층 중회의실
- 참석: 경영진·팀장, 개발본부 페이코어 팀장, 플랫폼·SRE팀 팀장, 데이터팀 팀장, 제품기획팀 팀장, 고객지원팀 팀장
- 기록: 김도윤

이번 회의는 분기 마지막 주 코드 프리즈 기간에 운영한 핫픽스 창구의 처리 결과를 검토하고, 다음 분기 운영 방식의 보완 사항을 정리하기 위해 진행했습니다.

## 안건
1. 지난 코드 프리즈 기간 예외 배포 요청 처리 결과 검토
2. 배포된 요청의 관측 및 사후 확인 방식 점검
3. 다음 분기 보고 체계와 회의 운영 기준 정리

## 논의 내용
지난 코드 프리즈 기간에는 핫픽스 창구로 접수된 요청이 총 4건이었고, 검토 결과는 4건 중 2건 배포, 2건 보류로 정리되었습니다. 보류된 2건은 긴급성은 있었으나 코드 프리즈 기간 내 즉시 배포가 필요한 수준으로 보기는 어렵다는 의견이 많았고, 다음 분기 첫 배포 순서로 넘기기로 했습니다. 고객지원팀은 가맹점 문의 측면에서 보류 사유를 설명할 수 있도록 제품기획팀과 문구를 맞추는 것이 필요하다고 말했습니다.

배포된 요청 중 첫 번째는 솔게이트의 PRJ-204 급증 대응이었습니다. 해당 건은 결제 흐름에 직접 영향을 주는 사례로 판단하여 예외 배포 대상으로 처리했습니다. 배포는 하늘 카나리 배포로 진행했고, 10퍼센트 트래픽부터 시작했습니다. 초기 관측 구간에서 오류율과 지연시간이 안정적으로 유지되는 것을 확인한 뒤 점진적으로 확대했습니다. 참석자들은 코드 프리즈 기간의 예외 배포라도 점진 배포 원칙은 유지해야 한다는 점에 동의했습니다.

배포된 두 번째 요청은 운영 안정성 측면의 수정이었으며, 기능 추가가 아닌 오류 억제 목적의 변경으로 판단했습니다. 다만 회의에서는 요청서에 영향 범위와 되돌리기 계획이 더 명확히 적혀야 한다는 지적이 있었습니다. 플랫폼·SRE팀은 배포 직전 확인 항목을 간단한 체크리스트 형태로 맞추면 검토 시간이 줄어들 것이라고 제안했습니다.

관측 절차와 관련해서는 예외 배포 건은 모두 배포 직후 모아 대시보드에서 오류율과 지연시간을 1시간 동안 확인했다는 점을 재확인했습니다. 현재 방식은 실무적으로 충분했으나, 관측 결과를 회의 때 다시 확인할 수 있도록 요약 캡처와 간단한 메모를 남기는 것이 필요하다는 의견이 있었습니다.

## 결정 사항
- 지난 코드 프리즈 기간 처리 결과는 4건 중 2건 배포, 2건 다음 분기 이관으로 확정합니다.
- 솔게이트 PRJ-204 대응 건은 코드 프리즈 예외 배포의 대표 사례로 정리합니다.
- 예외 배포 시 하늘을 통한 카나리 배포를 기본값으로 검토합니다.
- 예외 배포 직후에는 모아 대시보드에서 오류율과 지연시간을 확인한 기록을 남깁니다.
- 다음 코드 프리즈부터 핫픽스 창구 처리 건수를 팀장 회의에서 분기마다 보고받기로 합니다.
