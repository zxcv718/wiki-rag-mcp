# 협력 개발자 관리자 회의 참석 기준

## 목적
이 기준은 레드브릭소프트 소속 협력 개발자의 관리자 회의 참석 가능 범위와 제한 사항을 정리하기 위한 문서입니다. 관리자 회의에는 제품, 운영, 조직 관련 안건이 함께 다뤄지는 경우가 있으므로, 외부 인력이 참석할 수 있는 범위를 명확히 구분해야 합니다. 본 기준은 내부 의사결정 보호와 필요한 협업의 균형을 맞추는 데 목적이 있습니다.

또한 레드브릭소프트 소속 협력 개발자는 leadership 스페이스 문서를 직접 열람할 수 없고, 필요한 내용은 내부 팀장이 별도 요약으로 전달합니다. 문서 원문, 회의록 원본, 관련 첨부 자료도 동일한 원칙으로 취급합니다.

## 참석 기준
협력 개발자의 관리자 회의 참석은 예외적이며, 아래 조건을 모두 충족하는 경우에만 가능합니다.

1. 회의 안건이 기술 검토, 구조 변경, 장애 대응 방식, 운영 영향 검토 등 기술 의사결정만 포함하는 경우여야 합니다.
2. 인사, 평가, 보상 안건이 하나라도 포함되면 참석할 수 없습니다.
3. 참석 필요성이 내부 팀장에 의해 사전에 확인되어야 합니다.
4. 협력 개발자는 본인 업무 수행에 필요한 범위 내에서만 발언하고 자료를 공유받습니다.

다음 경우는 참석 불가로 봅니다.

- 조직 개편, 채용 계획, 인력 배치 논의가 포함된 회의
- 개인별 성과, 평가 의견, 보상 검토가 포함된 회의
- 기술 안건과 비기술 안건이 혼합되어 분리 진행이 되지 않는 회의

회의를 기술 안건과 비기술 안건으로 나눌 수 있으면, 협력 개발자는 기술 안건 시간에만 참석할 수 있습니다. 이 경우에도 회의 초대, 회의록, 공유 자료는 참석 범위에 맞게 분리합니다.

## 사전 준비와 진행
협력 개발자 참석이 필요한 경우 내부 DRI인 팀장이 회의 시작 1영업일 전까지 참석 목적과 공유 범위를 회의록 상단에 적어야 합니다. 기재 항목은 아래와 같습니다.

| 항목 | 작성 내용 |
|---|---|
| 참석 목적 | 왜 참석이 필요한지 한두 문장으로 명시합니다. |
| 공유 범위 | 회의 중 구두 공유 내용, 열람 가능한 자료 범위를 적습니다. |
| 제외 안건 | 협력 개발자가 듣거나 열람하면 안 되는 안건이 있으면 적습니다. |
| 내부 DRI | 책임 팀장 이름을 적습니다. |

회의 진행 시 내부 DRI는 안건 시작 전에 참석 범위를 다시 확인합니다. 회의 중 인사, 평가, 보상 관련 논의가 새로 필요해지면 협력 개발자는 해당 시점부터 즉시 퇴장해야 합니다. 퇴장 이후의 논의 내용은 별도 요약 대상이 아닙니다.

## 회의 후 공유 기준
회의 후 외부 공유 메모에는 saesol.example 계정 사용자 이름이나 내부 시스템 경로를 적지 않습니다. 개인 식별이 가능한 내부 계정 표기, 상세 접근 경로, 내부 화면 위치 설명도 포함하지 않습니다. 외부 공유 메모에는 협력 개발자가 업무 수행에 필요한 결정 사항, 일정 영향, 후속 작업만 정리합니다.

내부 팀장이 별도 요약을 전달할 때에도 아래 원칙을 지킵니다.

- 원문 복사 대신 필요한 내용만 요약합니다.
- 참석하지 않은 안건은 전달하지 않습니다.
- 개인 정보나 인사성 판단이 포함된 표현은 제외합니다.
- 내부 전용 식별 정보는 일반적인 설명으로 바꿉니다.

## 담당
내부 DRI인 팀장은 참석 필요성 판단, 사전 기록, 회의 중 범위 통제, 사후 요약 전달을 담당합니다. 회의 주최 팀장은 회의 안건이 참석 기준에 맞는지 확인하고, 혼합 안건이 있을 경우 순서를 분리해 운영합니다.

정보보안팀은 외부 공유 범위에 대한 해석이 필요한 경우 확인 창구 역할을 합니다. 경영진·팀장은 예외 요청이 있는 경우에도 본 기준을 우선 적용하며, 기준에 맞지 않으면 참석을 승인하지 않습니다.
