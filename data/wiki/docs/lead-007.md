# 팀장 회의 의사결정 기록 규칙

## 목적

이 문서는 팀장 이상 회의에서 나온 결정사항을 같은 형식으로 남기고, 이후 확인과 추적이 가능하도록 기록 기준을 정하기 위한 운영 기준입니다. 대상 문서는 팀장 회의에서 작성하는 회의록이며, 보는 사람은 경영진·팀장입니다.

회의록은 논의 과정 자체보다 현재 시점의 판단과 후속 확인 대상을 빠르게 파악할 수 있어야 합니다. 따라서 각 안건은 상태, 책임자, 확인 기한이 빠지지 않도록 작성합니다. 기록 누락이 있으면 회의에서 합의한 내용이 있어도 미완료로 취급합니다.

## 기록 기준

팀장 회의록은 leadership 스페이스에 작성합니다. 모든 안건에는 반드시 "3개 상태" 중 하나를 붙입니다. 상태는 다음과 같이 사용합니다.

- 결정: 실행하거나 공지할 내용이 확정된 안건입니다.
- 보류: 추가 검토가 필요하여 이번 회의에서 확정하지 않은 안건입니다.
- 확인 필요: 사실관계, 영향도, 선행 조건 확인이 끝나지 않은 안건입니다.

안건 제목은 아래 형식을 기본으로 합니다.

```text
[상태] 안건 제목
```

보안, 인력, 예산 관련 안건은 검색과 분류를 위해 제목 앞에 태그를 추가합니다. 예시는 다음과 같습니다.

```text
[보안] [결정] 접근 권한 검토 방식 변경
[인력] [보류] 채용 우선순위 조정
[예산] [확인 필요] 분기 운영비 증액 검토
```

결정사항마다 "DRI 1명"과 확인 기한 1개를 적습니다. DRI는 작업이나 장애의 직접 책임자 한 명입니다. 공동 책임, 팀 단위 책임, 참조만 있는 상태는 허용하지 않습니다. 기한이 없는 항목은 미완료로 봅니다. 보류와 확인 필요 안건도 다음 확인 시점을 적어 추적이 끊기지 않게 합니다.

## 작성 시점과 형식

회의록 작성자는 회의 종료 후 "4시간 안"에 결정사항 요약을 문서 첫머리에 추가해야 합니다. 요약은 5줄 이내로 작성하며, 회의에 참석하지 않은 팀장도 핵심만 보고 판단할 수 있게 씁니다. 요약에는 새로 결정된 내용, 보류된 쟁점, 다음 확인이 필요한 항목을 우선순위대로 적습니다.

본문 안건은 아래 항목을 순서대로 포함합니다.

1. 상태
2. 안건 제목
3. 결정 또는 확인 내용
4. DRI
5. 확인 기한
6. 비고

같은 안건이 다음 회의로 이어질 경우에는 새 문단으로 다시 적고, 이전 기록을 수정해 상태만 바꾸지 않습니다. 이전 판단과 변경 이유를 남겨야 추적이 가능합니다. 다만 오탈자 수정이나 링크 정리는 기존 문서에서 바로 수정해도 됩니다.

## 담당과 검토

회의를 주관한 팀장은 회의록이 작성되었는지 확인할 책임이 있습니다. 실제 작성은 지정된 작성자가 하되, 누락된 상태나 기한이 있으면 주관 팀장이 보완을 요청합니다. DRI로 적힌 사람은 확인 기한 전까지 진행 상황을 갱신해야 하며, 기한 내 완료가 어려우면 다음 회의 안건으로 다시 올립니다.

제품기획팀, 정보보안팀, 인사팀, 재무팀 등 관련 부서가 포함된 안건은 회의록만으로 후속 작업이 가능하도록 문장을 구체적으로 씁니다. 고객지원팀이나 개발본부 등 실행 부서가 별도 문의 없이 이해할 수 있어야 합니다. 외부 협력사가 관련된 경우에도 회의록의 책임 표기는 내부 구성원 기준으로 작성합니다.

## 예시

| 구분 | 작성 예시 |
|---|---|
| 요약 | 1) 정산 보고 절차 변경 결정 2) 채용 우선순위는 보류 3) 운영비 증액은 확인 필요 |
| 안건 | [예산] [확인 필요] 분기 운영비 증액 검토 |
| 내용 | 증액 필요성은 공감했으나 사용 범위와 근거 자료 확인 후 재논의합니다. |
| DRI | 김도윤 |
| 확인 기한 | 2026-06-25 |
| 비고 | 재무팀 수치 확인 후 다음 회의에서 상태 재판단합니다. |

위 기준을 지키지 않은 회의록은 완료된 기록으로 보지 않습니다. 특히 상태, DRI, 확인 기한 누락은 우선 보완 대상입니다.
