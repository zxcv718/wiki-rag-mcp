# 분기 조직 리스크 리뷰 회의록

## 일시와 참석자
- 일시: 2026-08-05 14:00~15:30
- 장소: 본사 8층 중회의실
- 주관: 경영진·팀장
- 참석: 개발본부 팀장 2명, 플랫폼·SRE팀 팀장, 데이터팀 팀장, 정보보안팀 팀장, 제품기획팀 팀장, 고객지원팀 팀장
- 기록: 김서현

이번 회의는 분기 단위 조직 운영 리스크를 점검하고, 즉시 조치가 필요한 항목의 담당과 기한을 정리하기 위해 진행합니다. 개발본부, 데이터팀, 정보보안팀에서 사전 제출한 항목을 기준으로 검토했으며, 총 "7건"을 안건으로 다룹니다.

## 안건
1. 페이코어 인수인계 공백
2. 페이코어 운영 지식 편중
3. 누리 마감 지연과 연계된 운영 리스크
4. 운영 DB 변경 승인 누락 가능성
5. 정산 데이터 접근 통제 미흡
6. 접근 재인증 이력 관리 누락
7. 보안 점검 결과 조치 지연

## 논의 내용
### 1) 개발본부 제출 항목
페이코어는 최근 담당자 변경이 이어지면서 특정 기능과 운영 절차가 일부 인원에게 집중되어 있다는 점을 리스크로 보고합니다. 특히 결제 관련 장애 대응 순서와 배치 의존 관계가 문서보다 구두 전달에 의존하는 구간이 있어, 휴가나 이동 시 공백이 생길 수 있다고 판단합니다. 팀장은 인수인계 문서 최신화와 함께 실제 대응 가능한 예비 인력 확보가 필요하다고 설명합니다.

누리 마감 지연 항목은 단일 장애보다는 반복 징후 관리의 문제로 정리합니다. 월별로 경보가 산발적으로 발생했으나 팀장 회의에 정기적으로 공유되지 않아, 추세를 경영진·팀장이 함께 보지 못한 점이 지적됩니다. 고객지원팀도 마감 지연이 길어질 경우 문의 증가로 이어질 수 있다고 의견을 냅니다.

### 2) 데이터팀 제출 항목
운영 DB 관련 항목은 변경 자체보다 승인과 사후 확인의 일관성 부족이 문제로 제기됩니다. 플랫폼·SRE팀과 DB 관리자 간 역할 경계가 안건별로 달라 보여, 긴급 작업 이후 기록이 늦어지는 경우가 있었다고 공유합니다. 데이터팀은 정산 데이터 파이프라인 영향 범위를 사전에 더 명확히 확인할 필요가 있다고 설명합니다.

정산 데이터 접근 통제 항목은 권한 부여보다 회수와 재검토 절차의 누락 가능성에 초점을 둡니다. 권한 보유자 목록은 유지되고 있으나, 분기 단위 확인이 늦어지면 불필요 권한이 잔존할 수 있어 관리 지표가 필요하다는 의견이 나옵니다.

### 3) 정보보안팀 제출 항목
정보보안팀은 접근 재인증과 점검 결과 조치 완료 여부를 별도 관리하지 않으면 같은 유형의 누락이 반복될 수 있다고 설명합니다. 팀별 자율 관리만으로는 편차가 발생하므로, 월 단위 추적과 팀장 보고를 병행하는 방식이 적절하다는 데 참석자들이 동의합니다.

## 결정 사항
- 이번 회의에서는 개발본부, 데이터팀, 정보보안팀에서 올라온 리스크 7건을 검토했습니다.
- 페이코어의 인수인계 공백 리스크는 10월 첫째 주까지 백업 담당자 2명을 지정하는 것으로 정리합니다.
- 누리 마감 지연과 연계된 운영 리스크는 NR-503 경보 월간 발생 횟수를 다음 분기부터 팀장 회의에 고정 보고하기로 합니다.
- 운영 DB 변경 관련 항목은 플랫폼·SRE팀과 DB 관리자가 공통 점검표 초안을 마련해 다음 회의 전에 공유합니다.
- 정산 데이터 접근 통제 리스크는 접근 재인증 누락 건수를 매달 0건으로 유지하는 목표로 정보보안팀이 추적합니다.
- 보안 점검 결과 조치 지연 항목은 미조치 사유를 팀장 승인 하에 기록하도록 정리합니다.
