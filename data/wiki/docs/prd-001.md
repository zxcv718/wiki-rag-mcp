# 솔북 BK-4010 대응 기능 명세

## 배경
솔북은 매장 예약 관리 앱이며, 일부 예약은 짧은 시간 안에 동일 조건으로 중복 요청될 수 있습니다. 이때 같은 예약 슬롯이 실제로 두 번 생성되면 운영 혼선과 고객 문의가 함께 발생합니다. 본 문서는 "BK-4010"을 감지하고 예약 생성 단계에서 차단하는 서버 동작과 고객 앱 표시 기준을 정의합니다.

본 문서에서 BK-4010은 솔북에서 같은 예약 슬롯이 두 번 잡힌 에러를 뜻합니다. 대상은 예약 생성 요청이며, 이미 생성된 예약의 변경이나 취소는 범위에 포함하지 않습니다.

## 사용자 시나리오
1. 고객이 솔북에서 특정 매장과 날짜, 시작 시각, 좌석 조건을 선택하고 예약을 요청합니다.
2. 네트워크 재전송, 화면 중복 탭, 또는 동일 조건의 연속 요청으로 인해 매우 짧은 시간 안에 같은 요청이 다시 들어올 수 있습니다.
3. 서버는 예약 생성 전에 동일 슬롯 충돌 여부를 확인합니다.
4. 충돌이 확인되면 새 예약을 만들지 않고 BK-4010으로 처리합니다.
5. 고객 앱은 예약이 확정되지 않았다는 안내 문구를 표시하고 재시도 버튼 1개만 노출합니다.

고객 앱 안내 문구는 다음 의미를 전달해야 합니다.

- 현재 요청으로 예약이 완료되지 않았습니다.
- 같은 시간대 예약 가능 여부를 다시 확인한 뒤 재시도할 수 있습니다.
- 중복으로 예약이 생성되었다고 오해하지 않도록 확정 표현은 사용하지 않습니다.

## 기능 요구사항
### 1. 충돌 검사 조건
서버는 같은 매장, 같은 날짜, 같은 시작 시각, 같은 좌석 조건이 2초 안에 중복 요청되면 예약 생성 전에 충돌 검사를 수행합니다.

충돌 검사는 아래 기준을 모두 만족하는 요청을 동일 슬롯으로 판단합니다.

| 항목 | 비교 기준 |
|---|---|
| 매장 | 동일 매장 식별값 |
| 날짜 | 동일 영업일 기준 날짜 |
| 시작 시각 | 동일 시작 시각 |
| 좌석 조건 | 동일 좌석 조건 |

### 2. 처리 방식
- 충돌 검사 결과 이미 처리 중이거나 직전 요청으로 같은 슬롯 예약 생성이 확정된 경우, 현재 요청은 예약 생성 로직으로 진입하지 않습니다.
- 이 경우 서버는 BK-4010 결과를 반환합니다.
- 서버는 중복 차단으로 종료된 요청에 대해 예약 성공 상태를 기록하지 않습니다.
- 서버 응답은 고객 앱이 별도 선택지 없이 재시도만 제공할 수 있도록 단일 오류 상태로 전달합니다.

### 3. 고객 앱 표시
BK-4010이 발생하면 고객 앱에는 예약이 확정되지 않았다는 안내 문구와 함께 재시도 버튼 1개만 노출합니다.

표시 원칙은 다음과 같습니다.

- 확인 버튼, 취소 버튼, 다른 대체 행동 버튼은 함께 노출하지 않습니다.
- 예약 완료 화면과 유사한 문구나 시각 요소는 사용하지 않습니다.
- 고객이 현재 상태를 오인하지 않도록 실패 안내를 우선 표시합니다.

### 4. 기록 및 조회
BK-4010 발생 건은 모아에서 14일 동안 검색 가능하도록 예약 ID와 매장 ID를 함께 남깁니다.

로그에는 아래 항목을 포함합니다.

- 발생 시각
- 예약 ID
- 매장 ID
- 요청 결과 코드
- 충돌 판단에 사용한 날짜, 시작 시각, 좌석 조건

로그는 고객지원팀과 개발본부가 재현 여부를 확인할 수 있도록 동일 형식으로 남깁니다. 다만 고객 개인정보가 직접 노출되는 값은 포함하지 않습니다.

## 제외 범위
다음 항목은 본 문서의 범위에서 제외합니다.

- 예약 변경, 취소, 노쇼 처리 시의 중복 판단
- 결제 승인 또는 환불 처리 방식
- 고객 앱 문구의 최종 표현 확정과 화면 시안
- 모아 외 저장소의 장기 보관 정책
- 운영 알림 기준과 별도 대응 절차

## 일정
- 제품기획팀은 본 명세 기준으로 화면 문구와 예외 흐름을 정리합니다.
- 개발본부는 서버 충돌 검사와 응답 형식을 구현합니다.
- 고객지원팀은 고객 안내 문구 초안을 검토합니다.

세부 일정과 배포 순서는 릴리스 관리 일정에 따르며, 본 문서는 기능 동작 기준만 정의합니다.
