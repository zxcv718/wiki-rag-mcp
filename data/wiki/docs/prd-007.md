# 릴리스 체크리스트 운영 메모

## 일시와 참석자
- 일시: 2026-05-20 14:00
- 장소: 제품 기획 스페이스 회의실
- 참석자: 제품기획팀 김도윤, 제품기획팀 박서현, 개발본부 페이코어 이지훈, 고객지원팀 한유진
- 작성 목적: 제품기획팀이 릴리스 전 확인 항목과 협업 순서를 통일하기 위해 운영 메모로 남깁니다.

## 안건
1. 릴리스 체크리스트의 단계와 단계별 책임 방식을 정리합니다.
2. 고객지원팀 공지 초안 요청 시점과 검토 흐름을 맞춥니다.
3. 하늘 배포 확인 시 기록 항목을 정리합니다.
4. 릴리스 노트 게시 전후의 완료 기록 방식을 맞춥니다.

## 논의 내용
릴리스 체크리스트는 명세 확정, 고객지원팀 공지 초안, 하늘 배포 확인, 릴리스 노트 게시의 4단계로 진행합니다. 각 단계는 선행 단계가 끝난 뒤에만 진행하며, 단계 사이에 구두 전달만으로 넘기지 않습니다.

각 단계에는 DRI 1명을 지정하고 다음 단계로 넘어가기 전에 완료 시각을 기록합니다. DRI는 해당 단계에서 필요한 확인 요청, 회신 취합, 누락 여부 점검을 직접 맡습니다. 참석자가 여러 명이어도 완료 표시는 DRI가 남깁니다. 완료 시각은 문서 본문 또는 표에 남기고, 사내 메신저 대화만으로 대체하지 않습니다.

명세 확정 단계에서는 제품기획팀이 변경 범위, 사용자 공지 필요 여부, 고객지원팀 전달 필요 항목을 최종 확인합니다. 이 단계가 끝나기 전에는 고객지원팀 공지 초안 요청을 보내지 않습니다.

고객지원팀 공지 초안 단계에서는 실제 배포 최소 2영업일 전에 검토 요청을 보내야 합니다. 요청 시에는 변경 요약, 예상 문의 포인트, 공지 반영 희망 시각을 함께 적습니다. 고객지원팀은 문안의 모호한 표현이나 누락된 영향 범위를 회신하고, 제품기획팀 DRI가 반영 여부를 정리합니다.

하늘 배포 확인 단계에서는 배포 대상 버전, 카나리 배포 여부, 롤백 가능 여부, 배포 후 확인 결과를 기록합니다. 코드 프리즈 기간에 포함되는 배포는 핫픽스 창구 승인 여부를 체크리스트에 반드시 남깁니다. 승인 주체나 배경 설명이 길어지면 별도 문서로 빼지 말고 체크리스트에 한 줄로라도 남기는 쪽으로 정리합니다.

릴리스 노트 게시 단계는 실제 배포 확인 이후에 진행합니다. 릴리스 노트에는 사용자 영향이 있는 변경만 추려 적고, 내부 작업 상세는 넣지 않습니다. 게시 후에는 게시 위치와 완료 시각을 체크리스트에 남겨 다음 문의가 들어왔을 때 같은 기준으로 답할 수 있게 합니다.

## 결정 사항
- 릴리스 체크리스트는 4단계 고정 순서로 운영합니다.
- 단계별로 DRI 1명을 지정합니다.
- 각 단계 종료 시 다음 단계로 넘어가기 전에 완료 시각을 기록합니다.
- 고객지원팀 공지 초안은 실제 배포 최소 2영업일 전에 검토 요청을 보냅니다.
- 코드 프리즈 중 배포는 핫픽스 창구 승인 여부를 체크리스트에 남깁니다.
- 하늘 배포 확인 이후에만 릴리스 노트를 게시합니다.
