# 2026년 8월 솔북 릴리스 노트

## 배포일
- 배포일: 2026-08-12
- 대상: 솔북 앱 예약 기능 및 예약금 결제 연동 화면
- 적용 범위: 예약 생성, 예약 상세, 예약금 결제 실패 후 재시도 흐름

이번 배포는 예약 입력 편의성과 중복 예약 방지, 결제 실패 후 재시도 경험을 함께 다루는 변경으로 구성합니다. 고객지원팀은 아래 변경 사항을 기준으로 문의 응대를 진행합니다. 개발본부와 제품기획팀은 동일 문서를 기준으로 검증 결과를 확인합니다.

## 새 기능
| 구분 | 변경 내용 | 사용자 영향 |
|---|---|---|
| 예약 상세 | 고객 메모 입력 한도를 300자에서 500자로 확대합니다. | 매장에서 예약 관련 추가 안내를 더 길게 기록할 수 있습니다. |
| 예약 생성 | BK-4010 감지를 위해 예약 생성 직전 슬롯 잠금 검사를 추가합니다. | 같은 시간대 예약이 겹쳐 저장되는 가능성을 줄입니다. |

BK-4010은 솔북에서 같은 예약 슬롯이 두 번 잡힌 에러를 뜻합니다. 이번 변경에서는 예약 생성 요청이 최종 저장되기 직전에 해당 슬롯의 점유 상태를 다시 확인하도록 처리합니다. 이미 다른 요청이 먼저 점유한 경우에는 생성이 완료되지 않으며, 사용자는 다시 시도해야 합니다.

## 개선
예약금 결제 실패 후 재시도 흐름을 정리했습니다. 기존에는 화면 진입 경로나 실패 시점에 따라 재시도 버튼이 보이는 시간이 다르게 느껴질 수 있었습니다. 이번 배포부터는 예약금 결제 실패 시 재시도 버튼 노출 시간을 15분으로 통일합니다.

이 변경으로 고객지원팀은 결제 실패 문의 응대 시 안내 문구를 단순하게 유지할 수 있습니다. 사용자가 결제 실패 직후 다시 결제를 진행하려는 경우, 버튼 노출 여부를 먼저 확인하도록 안내합니다. 15분이 지난 뒤에는 같은 화면에서 즉시 재시도가 되지 않을 수 있으므로, 사용자는 예약 상태를 다시 확인한 뒤 필요한 절차를 진행해야 합니다.

## 버그 수정
1. 예약 생성 중 동시 요청이 들어올 때 일부 조건에서 동일 슬롯이 연속으로 잡히는 사례를 줄이기 위해 검사 순서를 조정합니다.
2. 예약 상세 화면에서 긴 메모를 입력할 때 저장 전 잘림 여부를 사용자가 늦게 인지하던 문제를 완화합니다. 입력 한도 확대에 따라 실제 사용 가능한 범위를 화면 동작과 맞춥니다.
3. 예약금 결제 실패 후 화면을 다시 열었을 때 재시도 가능 시간이 일관되지 않게 보이던 동작을 정리합니다.

## 알려진 문제
- 예약 생성 직전 슬롯 잠금 검사 추가로 인해, 동시에 같은 시간대를 선택한 사용자가 많은 경우 한쪽 사용자는 저장 직전에 실패를 볼 수 있습니다. 이는 중복 예약 방지를 위한 정상 동작입니다.
- 고객 메모 입력 한도가 500자로 늘어났지만, 기존에 매우 긴 내용을 여러 줄로 붙여 넣는 경우 화면 높이에 따라 입력부가 답답하게 보일 수 있습니다.
- 네트워크 상태가 불안정한 환경에서는 예약금 결제 실패 후 재시도 버튼 상태가 늦게 갱신되어 보일 수 있습니다. 이 경우 화면을 다시 확인한 뒤 진행합니다.

## 릴리스 검증
릴리스 검증은 체크리스트 기반으로 진행합니다. 종료 조건은 제품기획팀 1명과 페이코어 1명이 함께 체크리스트를 완료하는 것입니다. 한쪽만 확인한 상태에서는 검증 종료로 보지 않습니다.

검증 항목은 아래를 포함합니다.
- 예약 상세에서 고객 메모가 500자까지 입력되고 저장되는지 확인합니다.
- 예약 생성 직전 슬롯 잠금 검사가 동작해 BK-4010 재현 가능성이 낮아졌는지 확인합니다.
- 예약금 결제 실패 후 재시도 버튼이 15분 기준으로 동일하게 노출되는지 확인합니다.
- 고객지원팀 공유용 안내 문구와 실제 화면 동작이 일치하는지 확인합니다.
