# 협력 개발자 협업 채널 운영 기준

## 대상
이 문서는 외부 협력사 소속 협력 개발자와 협력 개발자와 함께 일하는 개발본부 구성원을 대상으로 합니다. 주된 목적은 일상적인 업무 소통의 기준을 맞추고, 질문 누락이나 회의 과다를 줄이는 데 있습니다.

적용 범위는 개발본부와의 개발 협업, 제품기획팀과의 일정 조율, 고객지원팀을 통한 이슈 전달 등 협업 과정 전반입니다. 다만 인사, 비용, 보안 정책과 같이 별도 소관 조직의 운영 기준은 각 담당 조직의 안내를 따릅니다.

## 기본 원칙
협력 개발자의 기본 문의 채널은 사내 메신저의 "프로젝트 방"입니다. 업무 질문, 진행 상황 확인, 작업 전제 조건 확인은 먼저 해당 방에 남깁니다. 긴급하지 않은 질문은 같은 스레드에 이어서 남겨 맥락이 끊기지 않도록 합니다.

질문을 남길 때는 아래 정보를 함께 적는 것을 원칙으로 합니다.

1. 현재 작업 내용
2. 막힌 지점
3. 확인한 내용
4. 필요한 결정 또는 답변

개발본부 담당자는 협력 개발자의 업무 질문에 영업일 기준 "6시간" 안에 1차 응답하는 것을 원칙으로 합니다. 1차 응답은 최종 해결이 아니어도 되며, 담당자 확인 여부, 추가 확인이 필요한 항목, 예상 답변 시점을 알려주는 수준이면 됩니다.

긴급 장애나 배포 차질처럼 즉시 확인이 필요한 경우에는 프로젝트 방에 남긴 뒤 직접 관련 담당자를 호출합니다. 단, 단순 진행 확인이나 일반 문의는 호출보다 스레드 답변을 우선합니다.

## 회의 운영 기준
협력 개발자는 필요한 회의에만 참여합니다. 회의 초대 전에는 문서나 메신저 스레드로 해결 가능한지 먼저 확인합니다. 회의가 필요한 경우에도 안건, 참석 목적, 사전 읽을 자료를 함께 공유합니다.

"딥워크 데이"인 매주 수요일에는 협력 개발자 관련 정기 회의를 새로 잡지 않으며, 꼭 필요한 경우 30분 이내로 제한합니다. 수요일에 여는 회의는 장애 대응, 당일 일정 결정, 외부 일정 제약이 있는 경우처럼 미루기 어려운 안건만 대상으로 합니다.

전사 회의 참여 기준도 조정합니다. 이 문서는 2026년 9월에 협력 개발자의 전사 회의 참여 기준을 바꿔, 기존의 매월 참석 권장에서 "분기 마지막 솔데이"만 참석으로 조정했습니다. 협력 개발자는 솔데이에 분기마다 "1회"만 참석하며, 참석 대상은 진행 중인 프로젝트의 DRI와 사전 합의한 사람으로 한정합니다.

## 운영 방법 및 문의처
상황별 권장 채널은 아래와 같습니다.

| 상황 | 기본 채널 | 운영 기준 |
|---|---|---|
| 개발 업무 질문 | 프로젝트 방 | 같은 주제는 같은 스레드에 이어서 남깁니다. |
| 일정 확인 및 조율 | 프로젝트 방 | 변경 사유와 원하는 시점을 함께 적습니다. |
| 회의 요청 | 프로젝트 방 | 안건과 참석 필요 인원을 먼저 합의합니다. |
| 고객 이슈 전달 | 고객지원팀을 통한 공유 | 기술 확인이 필요하면 개발본부 담당자가 이어서 응답합니다. |
| 보안 정책 문의 | 정보보안팀 | 개발본부 판단 대신 소관 조직 안내를 따릅니다. |

문의처는 아래 기준으로 찾습니다.

- 일상적인 개발 협업 문의는 진행 중인 프로젝트의 DRI에게 먼저 확인합니다.
- 인프라 또는 운영 환경 관련 확인은 플랫폼·SRE팀 또는 해당 DB 관리자와 협의합니다.
- 정산 데이터 관련 문의는 데이터팀 담당 경로를 따릅니다.
- 회의 참여 범위나 릴리스 일정 관련 조율은 제품기획팀과 협의합니다.

공통 문의가 필요한 경우 사내 메일 help@saesol.example로 남기며, 메일 제목에 협력사, 프로젝트명, 문의 유형을 함께 적습니다.
