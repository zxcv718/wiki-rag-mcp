# 협력 개발자 계정 발급 안내

레드브릭소프트는 개발 인력을 파견하는 협력사입니다. 이 문서는 레드브릭소프트 소속 협력 개발자가 업무 시작 전에 필요한 계정 발급 순서와 첫 주 확인 사항을 정리한 안내입니다.

## 시작 전 준비

업무 시작 전에 내부 협업 담당자와 함께 계정 발급 요청을 준비합니다. 신청자는 내부 협업 담당자 한 명을 DRI로 적어야 하며, 시작일 2영업일 전까지 다온 계정 신청서를 제출해야 합니다. DRI는 작업이나 장애의 직접 책임자 한 명을 뜻합니다.

신청서에는 아래 내용을 빠짐없이 적습니다.

- 협력 개발자 이름
- 소속 회사명: 레드브릭소프트
- 시작일과 종료 예정일
- 업무 대상 스쿼드 또는 팀
- DRI 이름과 saesol.example 메일 주소
- 저장소 접근 필요 여부

신청서 정보가 누락되면 승인과 생성이 지연될 수 있으므로 제출 전에 DRI가 한 번 더 확인합니다.

## 첫날 할 일

계정 발급 요청이 승인되면 정보보안팀은 보안 서약 제출 여부를 확인한 뒤 영업일 기준 4시간 안에 다온 계정을 생성합니다. 생성이 끝나면 로그인에 필요한 안내를 받습니다.

다온 계정의 기본 아이디는 saesol.example 메일 주소와 같은 값으로 만듭니다. 예시는 아래와 같습니다.

| 항목 | 예시 |
|---|---|
| 메일 주소 | minsu.kim@saesol.example |
| 다온 기본 아이디 | minsu.kim@saesol.example |

최초 로그인 후에는 바로 본인 확인 절차를 진행합니다. 최초 로그인 후 24시간 안에 MFA 기기 등록을 끝내야 합니다. 등록이 완료되지 않으면 이후 업무 시스템 접근이 제한될 수 있습니다.

첫날에는 아래 순서로 진행합니다.

1. 다온 로그인
2. MFA 기기 등록
3. 본인 계정 정보 확인
4. DRI에게 로그인 완료 사실 공유

## 첫 주에 할 일

첫 주에는 업무에 필요한 접근 권한이 실제로 열려 있는지 확인합니다. 협력 개발자의 저장소 권한은 기본적으로 읽기 권한만 열립니다. 문서 확인, 코드 구조 파악, 빌드 절차 검토는 이 권한으로 진행합니다.

첫 코드 기여가 필요한 경우에만 페이코어 또는 해당 스쿼드 리더가 쓰기 권한을 추가 승인합니다. 쓰기 권한이 필요하면 협력 개발자가 직접 요청하기보다 DRI를 통해 요청하는 것을 권장합니다. 요청 시에는 대상 저장소와 필요한 이유를 함께 적습니다.

첫 주 점검 항목은 아래와 같습니다.

- 다온 로그인 가능 여부
- MFA 등록 완료 여부
- 저장소 읽기 권한 확인
- 코드 기여 필요 시 쓰기 권한 승인 요청 여부
- 권한 이상 발생 시 DRI 공유 여부

## 둘째 주에 할 일

둘째 주에는 실제 업무 흐름에 맞게 권한이 과하지도 부족하지도 않은지 점검합니다. 쓰기 권한이 승인된 경우에는 필요한 저장소만 열려 있는지 확인합니다. 더 이상 필요하지 않은 접근 범위가 보이면 DRI에게 알려 조정 요청을 합니다.

계정 정보 변경이 필요한 경우에도 협력 개발자가 단독으로 처리하지 말고 DRI와 먼저 확인합니다. 소속, 기간, 담당 스쿼드가 바뀌면 기존 승인 기준과 달라질 수 있습니다.

## 도움받을 곳

문제가 생기면 아래 순서로 문의합니다.

1. 내부 협업 담당자이자 DRI에게 먼저 문의합니다.
2. 계정 생성 지연, 로그인 불가, MFA 등록 문제는 정보보안팀 확인을 요청합니다.
3. 저장소 읽기 권한 또는 쓰기 권한 관련 요청은 페이코어 또는 해당 스쿼드 리더에게 전달합니다.

문의할 때는 아래 정보를 함께 보내면 확인이 빠릅니다.

- 이름
- 소속 회사명
- 시작일
- DRI 이름
- 발생한 문제
- 확인한 시각

권한 요청이나 장애 문의에는 비밀번호, API 키, 토큰 값은 보내지 않습니다. 필요한 경우에는 `<비밀번호>`처럼 값이 아닌 자리표시자로만 적습니다.
