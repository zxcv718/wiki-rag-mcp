# 협력사 저장소 접근 요청 절차

## 대상

이 문서는 외부 협력사와 개발본부 구성원이 사내 코드 저장소 및 관련 문서 접근을 요청할 때 따르는 절차를 안내합니다. 주 대상은 레드브릭소프트에서 파견 온 협력 개발자와, 해당 요청을 검토하거나 승인하는 개발본부 구성원입니다.

이 문서에서 말하는 저장소 접근은 개발 저장소, 운영 설정이 포함된 저장소, 저장소와 직접 연결된 문서를 포함합니다. 운영 DB 조회 권한, 사외 원격 접속, 채용 및 경비 처리는 이 문서 범위에 포함하지 않습니다.

## 요청 대상과 승인 기준

협력사 저장소 접근은 업무 수행에 필요한 최소 범위로만 요청합니다. 요청자는 필요한 저장소를 개별로 적고, 읽기 또는 쓰기 등 필요한 권한 수준을 명확히 구분합니다.

| 구분 | 기본 승인자 | 추가 확인 |
| --- | --- | --- |
| 일반 개발 저장소 | 해당 업무를 맡은 개발본부 책임자 | 없음 |
| 솔페이 또는 솔북 운영 설정이 들어 있는 저장소 | 스쿼드 리더 | 정보보안팀 |
| 저장소와 연결된 문서 | 해당 업무를 맡은 개발본부 책임자 | 필요 시 별도 요청 |

솔페이 또는 솔북 운영 설정이 들어 있는 저장소는 스쿼드 리더 승인 뒤에 정보보안팀 확인까지 끝나야 접근이 열립니다. 승인 단계 중 하나라도 누락되면 반영하지 않습니다.

개발 저장소 권한은 최대 90일 단위로만 부여합니다. 장기 과제라도 한 번에 더 길게 열지 않으며, 기간이 끝나면 자동 만료되어 재승인을 받아야 합니다.

## 요청 방법

협력사 저장소 접근 요청은 반드시 협력사 안내 스페이스의 템플릿으로 등록합니다. 메일이나 구두 요청만으로는 처리하지 않습니다.

요청서에는 아래 항목을 반드시 적습니다.

1. 저장소 이름
2. 필요한 권한
3. "종료 예정일"

권장 작성 형식은 아래와 같습니다.

```text
요청자: 홍길동
소속: 외부 협력사
업무 목적: 결제 기능 수정
저장소 이름: example-repo
필요한 권한: 읽기, 쓰기
종료 예정일: 2026-07-31
관련 검토자: 김새솔
```

여러 저장소가 필요하면 저장소별로 권한과 종료 예정일을 분리해서 적습니다. 업무 목적이 다른 요청을 한 문서에 섞지 않는 것을 권장합니다. 운영 설정이 포함된 저장소인지 불명확하면 먼저 개발본부 담당자에게 확인한 뒤 요청합니다.

## 처리와 만료

승인된 요청은 플랫폼·SRE팀이 실제 권한을 반영합니다. 권한 요청이 승인된 뒤 실제 반영까지의 목표 시간은 영업일 기준 1시간입니다. 이 시간 안에 반영되지 않으면 플랫폼·SRE팀에 문의합니다.

권한이 열리면 요청자는 필요한 저장소와 문서만 접근 가능한지 직접 확인합니다. 업무 범위를 벗어난 저장소가 함께 열렸다면 즉시 반납 요청을 올립니다. 반대로 필요한 저장소가 빠졌다면 기존 요청을 수정하지 말고 누락된 저장소만 별도 요청합니다.

권한 만료는 요청서에 적은 종료 예정일 또는 부여 기간 종료 시점에 자동으로 처리합니다. 자동 만료 후 계속 업무가 필요하면 같은 절차로 다시 요청합니다. 만료 전에 연장 필요 여부를 검토하는 책임은 요청자와 요청을 맡긴 개발본부 담당자에게 있습니다.

## 문의처

절차 작성이나 승인 경로가 헷갈리면 먼저 요청을 맡긴 개발본부 담당자에게 확인합니다. 실제 반영 지연, 권한 누락, 만료 처리 이상은 플랫폼·SRE팀으로 문의합니다. 운영 설정이 포함된 저장소 여부나 보안 검토 필요성은 정보보안팀 확인이 우선입니다.

문의 시에는 아래 정보를 함께 전달합니다.

- 요청 문서 링크
- 저장소 이름
- 요청자 소속
- 승인 완료 시각
- 현재 문제 내용

메일 문의가 필요하면 `help@saesol.example` 형식의 공식 주소를 사용하고, 긴급하지 않은 경우 문서 링크를 포함해 기록을 남깁니다.
