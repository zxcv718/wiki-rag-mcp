# 보안 점검 시정조치 추적 규칙

## 목적과 적용 범위
이 문서는 정기 보안 점검에서 확인된 시정조치를 등록하고, 완료 전까지 상태를 추적하는 기준을 정합니다. 점검 결과가 확정된 이후의 후속 조치에 적용하며, 정보보안팀이 전체 추적 기준을 관리합니다.

시정조치별로 담당 DRI 한 명을 반드시 지정합니다. DRI는 작업 진행, 일정 갱신, 관련 부서 협의, 완료 근거 정리를 직접 책임집니다. 여러 팀이 함께 수행하는 항목이어도 등록 시점에는 단일 DRI를 정해야 합니다.

## 판단 기준
시정조치는 점검 결과서에 기재된 등급과 영향 범위를 기준으로 관리합니다. 등록 시 아래 항목을 빠짐없이 포함합니다.

| 항목 | 필수 여부 | 작성 기준 |
| --- | --- | --- |
| 점검 항목 | 필수 | 점검 결과서의 항목명을 그대로 적습니다. |
| 위험 등급 | 필수 | 점검 결과서의 등급을 그대로 적습니다. |
| 영향 범위 | 필수 | 서비스, 운영 자산, 업무 범위를 간단히 적습니다. |
| 담당 DRI | 필수 | 직접 책임자 한 명을 적습니다. |
| 완료 예정일 | 필수 | 실제 조치 가능 일정을 기준으로 적습니다. |
| 조치 계획 | 필수 | 무엇을 바꾸는지 구체적으로 적습니다. |
| RFC 링크 | 조건부 | 운영 구조 변경이 포함되면 반드시 붙입니다. |
| 완료 근거 | 완료 시 필수 | 설정 변경 내역, 점검 결과, 확인 방법을 적습니다. |

모든 시정조치는 점검 결과 확정 후 2영업일 안에 등록하고 담당 DRI와 완료 예정일을 함께 적어야 합니다. 완료 예정일은 임의로 넉넉하게 잡지 않고, 검토와 적용에 필요한 실제 일정을 반영합니다.

시정조치가 운영 구조 변경을 포함하면 RFC 링크를 붙여야 하며 CAB 승인 전에는 완료 처리할 수 없습니다. 이 경우 기술 작업이 끝났더라도 승인과 반영 확인이 끝나기 전까지는 진행 중으로 유지합니다.

## 첫 1시간 조치
점검 결과가 확정되면 정보보안팀은 첫 1시간 안에 아래 순서로 착수합니다.

1. 점검 결과서에서 시정조치 대상 항목을 분리합니다.
2. 각 항목의 담당 조직 후보를 확인합니다.
3. 해당 조직과 협의해 DRI 지정 가능 여부를 확인합니다.
4. 치명 또는 높음 등급 항목은 우선 등록 대상으로 표시합니다.
5. 운영 구조 변경 가능성이 있는 항목은 RFC 필요 여부를 함께 표시합니다.

이 단계에서는 해결 방법을 확정하지 않아도 되지만, 등록 책임과 추적 시작 시점은 미루지 않습니다. 담당 조직이 바로 정해지지 않는 경우에도 정보보안팀이 임시 소유 상태로 등록한 뒤 같은 영업일 안에 지정 협의를 이어갑니다.

## 보고 체계와 지연 관리
치명 또는 높음 등급 시정조치는 매주 월요일 오전 11시에 정보보안팀 주관으로 진행 상황을 다시 확인합니다. 이 확인에서는 일정 변동, 차단 사유, RFC 필요 여부, 완료 근거 준비 상태를 함께 봅니다.

완료 예정일이 변경되면 DRI가 변경 사유와 새 일정을 즉시 남깁니다. 단순 일정 미기재나 구두 합의만으로는 변경으로 인정하지 않습니다.

완료 예정일을 두 번 넘긴 항목은 경영진·팀장 보고 대상으로 전환되며 세 번째 지연부터는 팀 OKR 리스크에 포함합니다. 보고 전환 이후에는 지연 사유, 해소 계획, 지원 필요 사항을 함께 정리합니다. 정보보안팀은 보고 대상 항목 목록을 유지하고, 반복 지연 여부를 같은 기준으로 확인합니다.

## 기록과 완료 처리
모든 추적 기록은 항목별로 이어서 남겨 변경 이력을 한곳에서 볼 수 있게 합니다. 기록에는 최소한 아래 내용을 포함합니다.

- 등록일
- 담당 DRI
- 현재 상태
- 완료 예정일과 변경 이력
- 진행 메모
- 관련 RFC 링크
- 완료 근거
- 최종 확인자

완료 처리는 정보보안팀 확인 후 진행합니다. 완료 근거에는 재점검 결과, 설정값 확인, 로그 또는 화면 캡처 등 실제 확인 가능한 자료를 포함합니다. 운영 구조 변경이 포함된 항목은 RFC 링크와 CAB 승인 여부가 확인되어야만 완료로 바꿉니다.

월간 요약이 필요할 때는 전체 건수보다 미완료 사유와 반복 지연 항목을 우선 정리합니다. 기록 누락이 있는 항목은 완료로 보지 않으며, DRI가 보완한 뒤 다시 확인합니다.
