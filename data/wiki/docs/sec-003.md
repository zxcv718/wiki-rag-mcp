# 접근 재인증 운영 기준

## 목적
이 문서는 보안 민감 권한에 대해 분기마다 수행하는 접근 재인증의 운영 기준을 정합니다. 접근 재인증은 분기마다 권한 보유자가 계속 필요한지 확인하는 절차를 뜻합니다. 본 기준은 권한의 장기 방치, 퇴직·이동 이후의 잔존 권한, 업무 종료 후 미회수 권한을 줄이기 위한 최소 통제로 운영합니다.

## 적용 범위
적용 대상은 다음과 같습니다.

- 운영 환경 접근 권한
- 운영 DB 조회·변경 권한
- 인프라 관리 권한
- 비밀 관리 시스템인 금고 접근 권한
- 정산 데이터 원본 및 적재 경로에 대한 고권한 접근
- 고객 정보 또는 결제 관련 민감 정보에 직접 접근 가능한 권한
- 외부 협력사 계정 중 운영 또는 민감 데이터에 닿을 수 있는 권한

대상 조직은 개발본부, 플랫폼·SRE팀, DB 관리자, 데이터팀, 정보보안팀을 포함하며, 필요 시 제품기획팀과 고객지원팀의 예외적 운영 권한도 포함합니다. 전 직원 계정 중 위 권한을 가진 경우와 외부 협력사 계정도 동일하게 적용합니다.

## 통제 항목
접근 재인증에서는 아래 항목을 확인합니다.

1. 권한 보유자가 현재 담당 업무상 해당 권한이 계속 필요한지 확인합니다.
2. 권한 범위가 실제 수행 업무에 비해 과도하지 않은지 확인합니다.
3. 최근 조직 이동, 휴직, 계약 종료 예정, 업무 종료 여부를 함께 확인합니다.
4. 공유 계정 사용 여부를 점검하고, 개인 식별이 되지 않는 권한은 원칙적으로 회수 검토합니다.
5. 외부 협력사인 레드브릭소프트 인력의 권한은 접근 재인증 때마다 내부 DRI 1명이 계속 필요 사유를 함께 남겨야 합니다.

승인 책임은 권한 성격에 따라 나눕니다.

| 권한 종류 | 1차 확인 | 최종 확인 |
|---|---|---|
| 개발본부 운영 권한 | 해당 팀장 | 정보보안팀 |
| 인프라 관리 권한 | 플랫폼·SRE팀 팀장 | 정보보안팀 |
| 운영 DB 권한 | 해당 DB 관리자 소속 책임자 | 정보보안팀 |
| 데이터 접근 권한 | 데이터팀 책임자 | 정보보안팀 |
| 외부 협력사 권한 | 내부 DRI | 정보보안팀 |

재인증 결과 유지, 축소, 회수 중 하나로 기록합니다. 회수로 결정된 권한은 지체 없이 제거 요청을 진행합니다. 금고 운영 경로 권한은 접근 재인증에서 회수되면 신규 신청과 같은 승인 절차를 다시 거쳐야 합니다.

## 예외 승인
정기 접근 재인증 시점에 즉시 판단이 어려운 경우에만 예외를 둘 수 있습니다. 예외는 업무 연속성 보장을 위한 최소 범위로만 허용하며, 사유와 종료 조건이 분명해야 합니다. 예외 승인에는 해당 팀장과 정보보안팀 확인이 모두 필요합니다.

외부 협력사 권한, 운영 DB 변경 권한, 금고 관련 권한은 포괄 승인하지 않습니다. 특히 레드브릭소프트 인력에 대해서는 내부 DRI 없이 예외를 유지할 수 없습니다. 예외 승인 중에도 불필요 권한으로 판단되면 즉시 회수합니다.

## 점검 및 기록
정보보안팀은 각 분기 재인증 완료 후 결과를 취합하고, 접근 재인증 결과는 정보보안팀이 분기마다 요약해 팀장 공유 스페이스에 보고합니다. 보고에는 조직별 대상 수, 유지·축소·회수 건수, 미응답 현황, 외부 협력사 권한 현황을 포함합니다.

재인증 과정의 승인 기록, 회수 요청 내역, 예외 사유는 감사 가능하도록 보관합니다. 접근 재인증 누락 계정 목록은 정보보안팀이 감사 기록으로 3년 동안 보관합니다. 누락이 반복되는 조직은 다음 분기 점검 시 우선 확인 대상으로 관리합니다. 필요 시 정보보안팀은 경영진·팀장에게 후속 조치를 요청할 수 있습니다.
