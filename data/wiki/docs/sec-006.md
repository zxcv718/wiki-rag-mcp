# 보안 취약점 등급별 조치 SLA

## 목적
이 문서는 보안 취약점의 심각도에 따라 조치 기한, 운영 반영 기준, 예외 승인 절차를 일관되게 적용하기 위한 기준을 정합니다. 제품기획팀의 릴리스 일정, 개발본부의 개발 일정, 플랫폼·SRE팀의 운영 변경 일정과 관계없이 취약점 조치는 본 문서의 우선순위를 따릅니다.

본 문서에서 코드 프리즈는 분기 마지막 주의 배포 동결 기간을 뜻합니다. 핫픽스 창구는 코드 프리즈 중에도 긴급 배포를 받는 절차를 뜻합니다. RFC는 구조 변경 전에 쓰는 설계 제안서이며 리뷰를 거쳐 승인합니다.

## 적용 범위
적용 대상은 새솔소프트가 운영하거나 개발하는 서비스, 운영 인프라, 내부 업무 시스템의 보안 취약점입니다. 솔페이와 솔북의 애플리케이션 코드, 배포 산출물, 운영 설정, 데이터 처리 구성, 외부 공개 자산을 포함합니다.

조치 책임은 취약점이 확인된 자산을 관리하는 조직에 있습니다. 개발본부는 애플리케이션과 라이브러리 수정, 플랫폼·SRE팀은 인프라와 운영 설정 변경, DB 관리자는 운영 DB 관련 설정과 권한 조정, 데이터팀은 정산 데이터 파이프라인 관련 조치를 수행합니다. 정보보안팀은 분류, 기한 확인, 예외 승인 검토, 미준수 보고를 담당합니다.

외부 협력사가 수행한 변경에서 발견된 취약점도 동일하게 적용하며, 내부 관리 조직이 최종 조치 책임을 집니다.

## 통제 항목
취약점 등급별 기본 SLA는 아래와 같습니다.

| 등급 | 기본 조치 기준 | 완료 기준 |
|---|---|---|
| 치명 | 접수 후 72시간 안에 조치합니다 | 운영 반영까지 끝나야 합니다 |
| 높음 | 14일 안에 조치해야 합니다 | 운영 반영 또는 위험 제거가 확인되어야 합니다 |
| 중간 | 45일 안에 조치 계획을 등록해야 합니다 | 계획에 담당자, 일정, 방법이 포함되어야 합니다 |

치명 등급 취약점은 접수 후 72시간 안에 운영 반영까지 끝내야 하며, 임시 차단만으로 종료하지 않습니다. 다만 운영 반영 전까지 위험을 낮추기 위한 접근 차단, 기능 비활성화, 규칙 추가 같은 보완 조치는 즉시 시행할 수 있습니다. 미준수 시 정보보안팀장이 경영진·팀장에 보고합니다.

높음 등급 취약점은 14일 안에 조치해야 하고, 중간 등급 취약점은 45일 안에 조치 계획을 등록해야 합니다. 조치 계획만 등록하고 장기간 미이행하는 상태는 허용하지 않으며, 정보보안팀은 등록된 계획의 이행 여부를 별도로 점검합니다.

코드 프리즈 기간에 치명 등급 취약점을 배포할 때도 핫픽스 창구로 접수하고 접수 티켓에 취약점 번호를 적습니다. 코드 프리즈라는 이유로 치명 등급의 운영 반영 기한이 연장되지는 않습니다.

## 예외 승인
정해진 기한 내 조치가 불가능한 경우 예외 승인을 신청해야 합니다. 예외 승인은 최대 30일까지만 가능하며 RFC 번호와 보완 통제를 함께 남기지 않으면 승인하지 않습니다.

예외 신청에는 최소한 다음 내용을 포함합니다.

1. 취약점 번호
2. 영향 범위와 미조치 사유
3. RFC 번호
4. 적용할 보완 통제
5. 요청 기간과 종료 예정일
6. 담당 조직과 책임자

보완 통제는 실제로 위험을 낮출 수 있어야 하며, 접근 제한, 기능 중지, 네트워크 차단, 탐지 규칙 강화, 추가 모니터링 같은 조치를 구체적으로 적습니다. 예외 승인 중에도 조치 작업은 계속 진행해야 하며, 동일 사유의 반복 연장을 전제로 계획을 세워서는 안 됩니다.

## 점검
정보보안팀은 접수된 취약점의 등급, 기한, 예외 승인 상태, 운영 반영 여부를 주 단위로 점검합니다. 기한 임박 건과 미준수 건은 해당 조직 책임자에게 통보합니다.

점검 시 확인하는 항목은 다음과 같습니다.

- 등급 분류의 적정성
- 조치 완료 여부와 운영 반영 증적
- 중간 등급의 조치 계획 등록 여부
- 예외 승인 문서의 RFC 번호와 보완 통제 기재 여부
- 코드 프리즈 기간 중 치명 등급 배포의 핫픽스 창구 접수 여부

반복적으로 기한을 넘기거나 예외 승인 요건을 누락하는 조직은 정보보안팀이 별도 개선을 요청할 수 있습니다. 필요한 경우 경영진·팀장에게 현황을 보고합니다.
