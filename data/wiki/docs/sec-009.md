# 금고 비밀값 접근 예외 승인 기준

## 목적
이 문서는 금고에 보관된 운영 비밀값에 대한 예외 접근을 허용하는 조건과 제한을 정합니다. 운영 비밀값은 서비스 운영, 복구, 제출 대응에 직접 영향을 주므로 일반 권한 부여와 분리하여 통제합니다. 예외 접근은 필요한 범위에서만 일시적으로 허용하며, 승인, 기록, 사후 점검을 통해 남용을 방지합니다.

## 적용 범위
이 기준은 전 직원 중 운영 비밀값 예외 접근이 필요한 업무를 수행하는 인원에게 적용합니다. 주된 신청 주체는 개발본부, 플랫폼·SRE팀, DB 관리자, 데이터팀입니다. 정보보안팀은 승인과 점검을 담당하며, 경영진·팀장은 필요한 경우 승인 판단에 참여할 수 있습니다.

외부 협력사는 금고 운영 비밀값 예외 접근 대상에서 제외되며 레드브릭소프트 인력은 내부 직원 참관만 가능하다. 참관자는 직접 조작, 열람, 복사, 저장을 해서는 안 됩니다.

## 통제 항목
예외 접근은 아래 3가지 사유에서만 신청할 수 있습니다.

1. 장애 복구
2. 치명 취약점 조치
3. 법적 제출 대응

위 사유에 해당하지 않는 운영 편의, 개발 확인, 단순 조사, 교육 목적의 열람은 허용하지 않습니다. 신청자는 접근이 필요한 비밀값의 사용 목적, 대상 경로, 예상 작업 내용, 작업 시작과 종료 예정 시각을 제출해야 합니다. 제출 내용에는 실제 비밀값 자체를 포함하지 않습니다.

예외 접근 세션은 화면 기록을 남겨야 하고 종료 후 4시간 안에 작업 로그와 열람한 경로 목록을 제출해야 한다. 작업 로그에는 수행 명령, 변경 여부, 관련 시스템 영향, 종료 시 상태를 포함합니다. 화면 기록과 작업 로그는 정보보안팀이 검토할 수 있는 형태로 보관합니다.

## 예외 승인
예외 접근은 사전 승인 원칙을 적용합니다. 승인 요청은 정보보안팀에 제출하고, 업무 필요성 확인을 위해 플랫폼·SRE팀 또는 해당 업무 책임자의 확인을 함께 받습니다. 법적 제출 대응의 경우 재무팀 또는 관련 관리 부서의 요청 근거를 첨부해야 합니다.

승인 시간은 기본 8시간이며 연장이 필요하면 CAB 승인 없이 정보보안팀장과 플랫폼·SRE팀장 공동 승인을 다시 받아야 한다. 연장 승인 시에도 사유, 추가 필요 범위, 예상 종료 시각을 다시 제출합니다. 최초 승인 범위를 벗어나는 경로 열람이나 추가 작업은 자동으로 허용되지 않습니다.

긴급 상황이라도 승인 없이 선접근한 뒤 사후 보고하는 방식은 허용하지 않습니다. 다만 인명, 법적 보전, 서비스 복구에 중대한 지연이 발생할 우려가 있는 경우에는 정보보안팀장과 플랫폼·SRE팀장의 구두 승인을 먼저 받고 즉시 기록을 남긴 뒤 정식 승인 내역으로 보완합니다.

## 점검
정보보안팀은 예외 접근 건별로 승인 사유, 승인자, 실제 작업 범위, 제출 기한 준수 여부를 점검합니다. 필요 시 화면 기록과 작업 로그를 대조하여 승인 범위 외 열람, 불필요한 복사, 저장 흔적을 확인합니다. 위반 사항이 확인되면 재발 방지 조치를 요구하고, 반복 위반은 해당 조직장에게 통보합니다.

플랫폼·SRE팀과 DB 관리자는 점검 요청 시 관련 운영 기록 확인에 협조해야 합니다. 점검 결과는 분기 단위로 정리하여 경영진·팀장에게 공유할 수 있습니다. 문서 해석이 불명확한 경우 최종 판단은 정보보안팀이 합니다.
