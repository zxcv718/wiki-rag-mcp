# 침해 의심 계정 격리 절차

## 목적과 적용 범위
이 문서는 계정 탈취 또는 내부 오남용이 의심되는 경우 정보보안팀이 수행하는 초기 격리와 후속 확인 절차를 정리합니다. 적용 대상은 전 직원 계정이며, 외부 협력사 계정은 별도 계약과 운영 기준에 따라 참고만 합니다. 다만 동일한 징후가 확인되면 정보보안팀은 본 절차와 같은 수준으로 즉시 대응합니다.

다온은 사내 계정·SSO 시스템을 뜻합니다. DRI는 작업이나 장애의 직접 책임자 한 명을 뜻합니다.

## 판단 기준
다음 조건을 함께 만족하면 침해 의심 계정으로 분류합니다.

| 항목 | 기준 |
|---|---|
| 로그인 위치 | 다온에서 불가능한 지역의 연속 로그인 |
| 권한 변화 | 로그인 징후와 이어서 15분 안의 권한 상승 |

위 두 조건이 함께 발생하면 단일 이상 징후가 아니라 실제 침해 가능성이 높은 사건으로 보고 즉시 격리 절차를 시작합니다. 한쪽 조건만 확인된 경우에는 단독으로 침해 의심 계정으로 확정하지 않고, 정보보안팀 근무자가 최근 활동과 사용자 확인 가능 여부를 추가로 봅니다. 다만 운영 접근 권한이 있는 계정은 보수적으로 판단합니다.

## 첫 1시간 조치
침해 의심 계정으로 분류되면 정보보안팀은 20분 안에 다온 세션을 강제 종료하고 신규 토큰 발급을 막아야 합니다. 이 조치는 사용자 응답 대기 없이 먼저 수행합니다.

초기 조치 순서는 다음과 같습니다.

1. 다온에서 현재 활성 세션을 확인하고 전부 종료합니다.
2. 신규 토큰 발급 차단 상태를 적용합니다.
3. 최근 로그인 위치, 기기 정보, 권한 변경 이력을 확보합니다.
4. 계정 소유자에게 등록된 연락처로 본인 사용 여부를 확인합니다.
5. 운영 시스템 접근 가능성이 있으면 관련 접근 이력을 분리 보관합니다.

계정 소유자가 개발본부 소속이면 해당 스쿼드 팀장과 DRI에게 동시에 알리고 운영 접근 권한이 있으면 접근 재인증 상태를 즉시 재검토합니다. 접근 재인증은 분기마다 권한 보유자가 계속 필요한지 확인하는 절차를 말합니다. 이때 팀장이나 DRI의 요청이 있더라도 정보보안팀 승인 전에는 세션 복구나 예외 허용을 하지 않습니다.

## 보고 체계와 격리 해제
정보보안팀 근무자는 사건 분류 직후 다음 순서로 알립니다.

1. 정보보안팀 내부 공유
2. 계정 소유자 소속 조직 책임자 통보
3. 필요 시 경영진·팀장 보고

개발본부 소속인 경우에는 스쿼드 팀장과 DRI를 동시 수신자로 지정합니다. 데이터팀, 플랫폼·SRE팀, DB 관리자 등 추가 확인이 필요한 조직이 있으면 정보보안팀이 직접 연결합니다. 고객 응대 중인 계정이거나 문의 유입이 예상되면 고객지원팀에는 사실 확인 전 추정 원인을 전달하지 않고, 계정 사용 중지 사실과 응대 문구만 전달합니다.

격리 해제는 본인 확인 2단계와 최근 24시간 활동 검토를 모두 마친 뒤 정보보안팀 근무자 2명이 승인해야 합니다. 본인 확인은 등록 연락처 확인과 사용 사실 진술 확인으로 진행합니다. 최근 활동 검토에서는 로그인 위치, 권한 변경, 주요 접근 이력의 일관성을 봅니다. 하나라도 설명되지 않으면 해제하지 않고 조사를 이어갑니다.

## 기록과 보관
모든 대응 내역은 사건 기록으로 남깁니다. 최소 기록 항목은 다음과 같습니다.

- 최초 탐지 시각
- 분류 근거
- 세션 종료 시각
- 신규 토큰 발급 차단 시각
- 사용자 확인 결과
- 관련 조직 통보 시각과 수신자
- 격리 해제 승인자 2명
- 후속 조치 필요 사항

기록은 정보보안 스페이스의 사건 문서로 작성하고, 제목에는 날짜와 계정 식별자만 적습니다. 비밀번호, API 키, 토큰 값 등 민감한 값은 기록하지 않고 `<비밀번호>`, `<토큰>`처럼 자리표시자로 대체합니다. 메일 보고가 필요하면 security@saesol.example로 발송하고, 문서 링크를 함께 남깁니다.
