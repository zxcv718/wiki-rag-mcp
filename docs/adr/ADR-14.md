# ADR-14. 자체 골든셋과 가상 위키로 평가

- 상태: 확정
- 주요 대안: 공개 벤치마크, 정성 확인
- 출처: 설계서 7. 평가 체계

| 선택지 | 장점 | 단점 |
|---|---|---|
| 공개 벤치마크 | 다른 결과와 비교 가능 | 사내 위키 특유의 약어·권한·최신성 문제를 반영하지 못함 |
| 직접 질문해 보는 정성 확인 | 빠름 | 개선 여부를 판단할 근거가 없고, 성능 퇴보를 감지할 수 없음 |
| **자체 골든셋 + 가상 위키 (선택)** | 이 서비스의 요구사항을 직접 검증 | 제작 비용, 만든 사람의 편향 |

- **편향 대응**: 질문 작성과 정답 라벨링을 분리합니다.
  - 질문은 LLM이 생성 기록의 핵심 사실로 쓰되, 문서의 표현을 옮기지 않고 직원이 실제로 물을 법한 말로 쓰게 합니다.
  - 정답 라벨은 질문의 출처를 모르는 다른 작성자(질문을 쓴 모델과 다른 모델)가 위키 전체에서 따로 찾아 붙입니다. 출처 문서와 두 번째 라벨이 다르면 검토하고 결과를 기록합니다.
  - 처음 계획은 사람이 질문을 쓰고 라벨링을 다른 날에 하는 것이었습니다. 구현을 AI로 하면서 "다른 날"을 "출처를 모르는 다른 작성자"로 바꿨습니다(2026-09-27). 기억을 지우는 대신 처음부터 모르는 작성자를 쓰는 셈입니다.
  - 질문이 문서 표현을 닮으면 키워드 검색에 유리해집니다. 그래서 질문과 정답 문서의 단어 겹침 비율을 재서 판정 결과와 함께 보고합니다.
- **감수한 비용**: 다른 사람에게 받은 질문은 섞지 못했습니다. 모든 질문이 같은 생성 방식에서 나와, 실제 직원의 질문 분포와 다를 수 있습니다. 실사용 질문 로그가 생기면 ADR-20의 재검토 조건대로 골든셋을 다시 구성합니다(10장 실사용자 확보 계획).
- **도구 선택**: 검색 지표(Recall, MRR, nDCG)는 수십 줄로 구현되므로 직접 작성해 정의를 정확히 통제합니다. LLM 채점이 필요한 답변 품질만 평가 도구 도입을 검토합니다.
- **참고**: [BEIR](https://arxiv.org/abs/2104.08663) (정답 라벨 형식), [Confluence 권한과 제한](https://support.atlassian.com/confluence-cloud/docs/what-are-confluence-cloud-permissions-and-restrictions/) (가상 위키 권한 구조의 기준)
