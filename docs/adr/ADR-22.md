# ADR-22. 검색 저장소를 PostgreSQL + pgvector로 단순화

- 상태: 확정
- 주요 대안: OpenSearch 유지
- 출처: 설계서 2. 전체 아키텍처

ADR-02를 대체합니다. ADR-02는 "사내 위키 질문에는 약어·에러 코드처럼 정확히 일치해야 하는 단어가 많아 한국어 키워드 검색이 필요하다"는 가설로 OpenSearch(nori 형태소 분석 + k-NN)를 골랐습니다. 원칙 2와 충돌하는 결정이라 가설로 두고, 하이브리드 검색의 효과가 증명되지 않으면 PostgreSQL + pgvector로 단순화한다는 조건을 실험 전에 적어 두었습니다. M2 판정(7장, ADR-20)에서 하이브리드는 보류가 나왔습니다.

| 선택지 | 장점 | 단점 |
|---|---|---|
| OpenSearch 유지 (ADR-02) | 키워드 검색을 나중에 켜기 쉬움, 권한 필터를 키워드·벡터 검색에 한 번에 적용 | 효과를 증명하지 못한 구성 요소를 유지, JVM 힙만 1GB 이상 |
| **PostgreSQL + pgvector (선택)** | 구성 요소가 단순하고 위키와 같은 DB 기술이라 운영 지식이 하나로 모임, 메모리가 적음 | 한국어 키워드 검색이 없음, HNSW 인덱스가 필터를 스캔 뒤에 적용 |

- **판정 결과** (`experiments/m2-judgement/README.md`):
  - 하이브리드(BM25 + 벡터, RRF)의 Recall@5는 벡터 단독보다 +1.5%p(0.970에서 0.985, 95% 신뢰구간 −0.4 ~ +3.7)였고, 기준값 2%p로 판정하면 보류입니다.
  - 약어·고유명사 45문항에서는 두 구성의 결과가 하나도 다르지 않았습니다. 이 골든셋에서는 bge-m3가 PRJ-204 같은 에러 코드도 이미 찾아, ADR-02의 출발 가설이 맞지 않았습니다.
  - 보류면 구성 요소를 늘리지 않는다는 규칙(ADR-20)에 따라 단순화했습니다.
- **결정**:
  - 검색 인덱스는 위키 DB와 분리된 PostgreSQL 데이터베이스에 두고(ADR-01), 벡터 검색만 씁니다.
  - 두 권한 필드(ADR-21)는 배열 겹침(`&&`)으로 WHERE 절에 겁니다. 빈 배열은 어떤 배열과도 겹치지 않아, 권한 필드가 빈 문서는 아무에게도 나오지 않습니다.
  - HNSW 인덱스의 매개변수(m=16, ef_construction=128)는 OpenSearch 때와 같게 두었습니다.
- **옮긴 뒤 측정**:
  - 같은 골든셋으로 다시 재니 270문항의 결과가 OpenSearch 벡터 검색과 모두 같았습니다(Recall@5 0.970, MRR@10 0.910). 전체 p95는 106ms에서 109ms, 검색 단계 p95는 3.2ms에서 6.7ms였습니다(청크 1,151개).
  - 4장의 권한 테스트셋과 결과 수 테스트(가장 가까운 500개가 권한 밖이어도 5개 반환)를 두 저장소에서 모두 통과했고, 문서 제한 조건을 일부러 빼면 테스트가 실패하는 것도 확인했습니다.
- **감수한 비용**:
  - 한국어 키워드 검색이 없어, 벡터 검색이 놓치는 정확 일치 질문(드문 코드, 사람 이름)에 약할 수 있습니다.
  - iterative scan도 `hnsw.max_scan_tuples`(기본 20,000)에서 멈추므로, 한 사용자가 볼 수 있는 청크가 전체의 극히 일부이면 k개보다 적게 받을 수 있습니다. 결과 수 테스트를 CI에 두고, 모자라면 이 값을 올리거나 정확 검색으로 바꿉니다.
  - HNSW 인덱스는 2,000차원까지만 지원합니다. 더 큰 임베딩 모델로 바꾸면 halfvec이나 차원 축소가 필요합니다.
  - 판정 골든셋은 기준선이 이미 0.970이라 하이브리드가 개선할 여지가 3%p뿐이었습니다(천장 효과).
- **재검토 조건**: 실사용 질문 로그로 다시 만든 골든셋(ADR-20 재검토 조건)에서 벡터 검색이 정확 일치 질문을 놓치는 비율이 높으면, PostgreSQL 안에서 키워드 검색을 더하는 방안부터 검토합니다. 청크가 수백만 개로 늘어 필터 스캔이 지연 예산을 넘으면 파티션이나 전용 벡터 저장소를 다시 봅니다.
- **참고**: [pgvector](https://github.com/pgvector/pgvector) (iterative index scans, HNSW 2,000차원 제한), ADR-02의 선택지와 판정 기준은 `docs/adr/ADR-02.md`에 남아 있습니다.
