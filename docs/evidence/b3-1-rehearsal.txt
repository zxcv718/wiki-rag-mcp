## 7. 리허설 2 (리뷰 반영 뒤)

바꾼 것: DuckDNS 등록과 HTTP 대기에 상한, 컨테이너의 메타데이터 차단(hop limit 1), 점검 스크립트가 조회 실패를 0으로 찍지 않게.

$ infra/b3-1.sh up --staging
Apply complete! Resources: 13 added, 0 changed, 0 destroyed.
http://13.124.134.139/health 응답 (53초)
https://b3-1.dmssh.store/health 응답 (64초)
# 이때 스크립트는 인프라를 만든 뒤부터 쟀다. 리허설 1(84초)은 시작부터 잰 값이라 둘을 바로 비교하지 않는다

서버 안:
[b3-1] 공인 IP 13.124.134.139
[b3-1] DuckDNS b3-1.duckdns.org -> 13.124.134.139
[b3-1] b3-1.dmssh.store -> 13.124.134.139

localhost 200, example.com 200
인스턴스 메타데이터 HttpPutResponseHopLimit = 1
호스트에서 메타데이터 토큰 요청: 받음
컨테이너(curlimages/curl)에서 메타데이터 토큰 요청: 시간 초과(curl 종료 코드 28)

$ infra/b3-1.sh down
Destroy complete! Resources: 13 destroyed.
삭제 37초 (승인 입력 포함)

점검 스크립트 실패 경로: 없는 프로필로 실행하면 "조회 실패: EC2 (종료되지 않은 것)"를 찍고 종료 코드 1로 멈춘다.
리전 고정: 셸에 AWS_REGION=us-east-1이 있어도 서울을 센다.
