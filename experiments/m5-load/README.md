# M5 부하 측정 (k6)

운영 서버(ADR-23, m7i-flex.large)에서 `search_wiki`가 동시 요청을 얼마나 버티는지 잽니다. 설계서 8장 "부하 테스트"의 계획을 따르고, 판정 기준은 측정 전에 이 문서에 적었습니다. 결과를 본 뒤 기준을 바꾸지 않습니다.

## 판정 기준 (측정 전에 정함)

1장 목표치 두 가지를 동시 50에서 판정합니다. 8장에서 50을 목표 부하로 정했기 때문입니다.

| 지표 | 기준 | 잰 곳 |
|---|---|---|
| `search_wiki` 응답 시간 p95 | 800ms 이하 | k6가 잰 요청 시간(보내기 시작부터 응답을 다 받기까지, 네트워크 포함) |
| 오류율 | 1% 미만 | 아래 "오류로 세는 것"에 해당하는 요청의 비율 |

- 동시 10(평상시)과 100(목표의 두 배)은 판정하지 않고 같은 지표를 기록합니다. 동시 1은 줄을 서지 않을 때의 기준값입니다.
- 동시 50에서 둘 중 하나라도 못 맞추면 ADR-23의 재검토 조건에 따라 bf16 재판정(ADR-11)과 코어 증설 중에서 고릅니다. 8장은 p95가 800ms를 넘으면 ADR-13 재판정(리랭커 제거 검토)부터 하라고 했는데, 리랭커는 M2 판정에서 도입하지 않아 검색 경로에 없으므로 해당하지 않습니다.
- 개선을 하면 같은 방법으로 다시 재고, 개선 전후 수치를 함께 적습니다.

### 오류로 세는 것

- HTTP 상태가 200이 아님
- 응답이 JSON-RPC 오류이거나 도구 결과가 `isError: true`
- 30초 안에 응답이 오지 않음(k6 요청 제한 시간)

## 방법

| 항목 | 내용 |
|---|---|
| 대상 | `https://mcp.dmssh.store/mcp`. Caddy, OAuth 토큰 검증, 그룹 해석, 쿼리 임베딩, pgvector 검색을 모두 거친다 |
| 부하 발생기 | 노트북(서울)의 Docker에서 k6 2.3.0. 서버에서 돌리면 k6가 임베딩과 CPU를 나눠 쓴다 |
| 요청 | MCP 2026-07-28 방식의 `tools/call` 한 번이 검색 한 번이다. MCP Python SDK가 보내는 것과 같은 헤더와 본문을 쓴다 |
| 질의 | 골든셋 질문 300개(`data/golden/golden.jsonl`)에서 무작위로 고르고, 그 질문을 한 사용자(`asker`, 11명)의 토큰으로 보낸다. 권한이 다른 사용자가 섞여 검색 필터가 매번 달라진다 |
| 부하 모양 | 닫힌 모델. 가상 사용자 N명이 생각하는 시간 없이 응답을 받자마자 다음 검색을 보낸다. 그래서 늘 N개의 요청이 서버에 걸려 있다("동시 N요청") |
| 단계 | 동시 1(1분), 10(2분), 50(2분), 100(2분). 단계 사이에 30초 쉰다 |
| 토큰 | 단계마다 새로 받는다(액세스 토큰 수명 10분). 미리 등록한 공개 클라이언트 `wiki-rag-load`(ADR-24)로 로그인과 동의를 거친다. 토큰은 저장소 밖 임시 파일에만 두고 측정이 끝나면 지운다 |
| 서버 쪽 기록 | 단계마다 Prometheus에서 단계별(권한 해석, 쿼리 임베딩, 벡터 검색, 결과 조립) p50·p95와 그룹 캐시 적중률, `vmstat`으로 CPU 사용률을 남긴다. 추적은 Tempo에 모두 남는다 |

실행은 노트북에서 `experiments/m5-load/run.sh <서버 IP>`입니다. 결과는 `runs/<시각>/`에 쌓입니다. 서버에 먼저 이 커밋이 배포되어 있어야 합니다(`tokens.py`를 서버의 저장소에서 읽음).

### 측정 조건에서 알아 둘 것

- 서버는 물리 코어 1개(vCPU 2개), 메모리 8GB이고, 검색 서버 하나가 요청을 모두 받습니다. 동기 도구는 스레드 풀(anyio 기본 40개)에서 돌아, 동시에 임베딩하는 요청이 최대 40개입니다.
- m7i-flex는 기본 성능이 vCPU당 40%이고, 전체 시간의 95% 동안은 최대 성능까지 올라갑니다([AWS 발표 글](https://aws.amazon.com/blogs/aws/new-seventh-generation-general-purpose-amazon-ec2-instances-m7i-flex-and-m7i/)). 측정 중 CPU가 막혔는지는 `vmstat`의 steal(`st`) 열로 확인합니다.
- 관측성의 추적 표본은 1.0(모두)입니다. 운영과 같은 조건입니다.
- 쿼리 임베딩은 float32입니다(ADR-11). 한 요청만 보낼 때 서버에서 잰 값이 약 0.22~0.25초입니다.
