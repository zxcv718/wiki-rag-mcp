# M6 후속: 서버가 주는 범위와 도구 선택

도구를 부를지는 서버가 아니라 클라이언트의 모델이 정합니다. 서버가 줄 수 있는 판단 재료는 안내문(instructions)과 도구 설명뿐입니다. 이 실험은 그 재료에 범위를 적으면, 데모 에이전트가 아닌 일반 클라이언트의 도구 선택이 나아지는지 봅니다.

판정 기준은 측정 전에 이 문서에 적었고, 결과를 본 뒤 바꾸지 않습니다.

## 문제

- **드러난 오류**: M6 측정(`experiments/m6-agent`)에서 데모 에이전트가 회사 질문 300개 중 2개를 위키 없이 일반론으로 답했습니다.
  - q131 "정산 원장 테이블은 보통 어떤 컬럼으로 파티션 잡아?"
  - q295 "예약금 결제 연동이 얼마나 느려지면 사용자 실수가 많아져요?"
  - 둘 다 회사 이름이나 고유명사가 없어 일반 질문처럼 보입니다.
- **서버가 주는 재료**
  - 안내문은 "사내 위키 검색 서버입니다. 사용자 권한에 맞는 근거만 돌려주며 답변은 만들지 않습니다."뿐입니다.
  - `search_wiki` 설명의 "쓸 때"는 "사내 위키에 있을 내용"이라 어느 회사의 무엇인지 알 수 없습니다.
  - "쓰지 말 때: 일반 상식이나 공개된 기술 질문"은 기술 질문처럼 생긴 회사 질문을 도구에서 멀어지게 할 수 있습니다.
- **누가 영향을 받나**: 데모 에이전트는 자기 시스템 프롬프트("회사 안의 일은 도구로 찾아 답한다")로 이를 채웁니다. Claude Code 같은 일반 클라이언트는 서버의 안내문과 도구 설명만 봅니다.
- **반대 방향**: 범위를 넓히면 일반 질문에도 위키를 찾는 과잉 호출이 늘 수 있습니다. 두 방향을 함께 잽니다.

## 바꿀 것 (B안)

A는 운영 서버가 지금 주는 안내문과 도구 정의 그대로입니다. B는 여기서 안내문과 `search_wiki` 설명 두 가지만 바꿉니다. 문구는 `variant_b.yaml`에 있습니다.

- **안내문**: 회사 이름과 범위를 적고, "질문에 회사 이름이 없어도 회사가 정한 기준이나 절차를 묻는 것이면 여기에 해당"한다고 적습니다.
- **`search_wiki` 설명**
  - "쓸 때"에 같은 문장을 더합니다.
  - "쓰지 말 때"를 "회사와 관계없는 일반 지식 질문(프로그래밍 문법, 법령의 일반 규정, 용어 설명 등)"으로 좁힙니다.
- **범위 목록을 어디서 가져왔나**
  - 시험 문항이 아니라 위키의 스페이스 구성(`data/wiki/schema.yaml`)과 용어 사전의 제품 이름에서 가져왔습니다.
  - 제한 스페이스(인사팀, 팀장 공유)의 이름은 넣지 않습니다. 안내문은 모든 사용자에게 보여, 이름을 넣으면 볼 수 없는 스페이스가 있다는 사실이 드러납니다.
- **안 바꾸는 것**
  - "애매하면 먼저 찾는다" 같은 기울기는 서버에 넣지 않습니다. 서버는 질문을 볼 수 없어 맥락을 모르고, 늘 연결된 MCP 서버가 이렇게 말하면 코딩 세션에서 과잉 호출이 늡니다.
  - 기울기는 맥락을 아는 클라이언트 쪽(시스템 프롬프트, CLAUDE.md)의 몫입니다.
- **채택하면 서버 쪽 구현**: 회사 이름과 범위 문장은 서버 코드에 박지 않고 설정으로 받습니다. 도구 설명의 바뀐 문장은 회사와 무관한 일반 문장입니다.

## 질문 (`questions.jsonl`)

40개이고, 측정 전에 Claude가 써서 커밋했습니다. 골든셋 문항은 쓰지 않았습니다. q131, q295처럼 이미 틀린 문항을 넣으면 B에 유리한 문항을 고른 셈이 되기 때문입니다.

| 종류 | 수 | 조건 | 예 |
|---|---|---|---|
| 회사 질문 (`expected: wiki`) | 24 | 위키에 답이 있고(`doc`, `fact`에 적음), 회사 이름이나 고유명사가 없어 일반 질문처럼 보임 | "병가 며칠부터 진단서 내야 돼?" (hr-013, 4일 이상 연속) |
| 일반 질문 (`expected: none`) | 16 | 위키에 답이 없고(키워드로 문서를 찾아 확인), 업무나 기술 이야기처럼 보임 | "근로기준법상 연차는 1년에 며칠 생겨?" |

회사 질문의 근거는 문서마다 해당 문장을 찾아 확인했습니다. 일반 질문은 핵심 키워드(퇴직금, 52시간, JWT, 블루그린 등)가 위키에 없거나, 있더라도 다른 뜻으로만 쓰였는지 확인했습니다. 예를 들어 `401` 검색에 걸린 것은 에러 코드 `BK-4010`이었습니다.

## 클라이언트 조건

- **도구 정의**: 운영 서버에서 받은 것을 그대로 저장해(`tools.A.json`) A로 쓰고, B는 거기서 두 문구만 바꿉니다. 모델 호출에는 서버가 필요 없습니다. 도구를 실제로 부르지 않고 첫 응답만 보기 때문입니다.
- **일반 클라이언트 프롬프트** (`scope.py`의 `GENERIC_PROMPT`)
  - "사용자를 돕는 AI 도우미"라는 한 줄, 오늘 날짜, 서버 안내문만 넣습니다. 회사 이야기는 없습니다.
  - Claude Code 같은 클라이언트가 서버 안내문을 시스템 프롬프트에 붙이는 방식을 흉내 낸 것입니다.
- **데모 에이전트 프롬프트**: `core.py`의 `SYSTEM_PROMPT` 그대로입니다.
- **모델**
  - `gpt-5.4`: 온도 0으로, M6 측정과 같습니다.
  - `gemini-3.1-pro`: 온도를 넘기지 않고 제공자 기본값을 씁니다.
  - Claude는 잴 수 없습니다. COPA가 Claude 모델에 도구 정의를 넘기지 않아, 도구가 있어도 "위키에 접근할 수 없다"고 답했습니다(2026-09-29 확인).

## 판정 기준 (측정 전에 정함)

- **판정 단위**
  - 첫 응답에서 위키 도구(세 도구 중 무엇이든)를 불렀는지 봅니다.
  - 문항마다 반복한 실행 가운데 부른 비율을 내고, 문항을 복원 추출하는 부트스트랩으로 A와 B를 짝지어 비교합니다(ADR-20, `evaluation/judge.py`).
- **주 판정**: `gpt-5.4`, 일반 클라이언트 프롬프트, A와 B를 3번씩 돌립니다.
  1. **회사 질문**: 위키를 찾은 비율의 차이(B − A)를 ADR-20으로 판정합니다. 기준값은 10%p입니다.
  2. **일반 질문**: 둘 다 만족해야 합니다.
     - 부르지 않은 비율의 차이(B − A)의 95% 하한이 −10%p 이상(나빠지지 않음)
     - B의 과잉 호출률이 10% 이하
     - 10%는 M6의 "부르지 않음" 기준과 같은 값입니다.
  3. **데모 에이전트가 나빠지지 않음**: 데모 에이전트 프롬프트에 B를 넣고 M6의 도구용 50문항(`experiments/m6-agent/tool_questions.jsonl`)을 1번 돌려, 의도한 도구마다 오류율이 10% 이하여야 합니다. 이 문항들은 M6에서 A로 잰 적이 있습니다.
- **판정**
  - 채택: 1이 채택이고 2와 3을 만족합니다.
  - 기각: 1이 기각이거나, 2나 3을 만족하지 못합니다.
  - 보류: 그 밖입니다. 보류면 바꾸지 않습니다(ADR-20).
- **기록만 하는 값**
  - `gemini-3.1-pro`, 일반 클라이언트 프롬프트, A와 B 1번씩: 다른 계열 모델에서도 방향이 같은지 봅니다.
  - `gpt-5.4`, 데모 에이전트 프롬프트, 새 질문 40개로 A와 B 1번씩
  - 회사 질문에서 `search_wiki`가 아닌 도구를 먼저 고른 경우
- **채택하면**
  - 안내문 설정과 도구 설명을 서버에 넣고, 검색 서버만 다시 배포합니다.
  - 운영 서버가 B 문구를 주는지 도구 정의를 다시 받아 확인합니다.

## 한계

- **실제 클라이언트의 모델이 아닙니다.** 주된 실제 클라이언트인 Claude Code의 Claude는 잴 수 없고, 일반 클라이언트 프롬프트도 실제 Claude Code의 긴 시스템 프롬프트와 다릅니다.
- **문구와 문항을 같은 사람이 썼습니다.** Claude가 오류를 본 뒤 B 문구와 질문을 모두 썼습니다. 범위 목록은 위키 구성에서 가져왔지만, 문항이 B의 표현에 맞춰졌을 가능성은 남습니다.
- **문항이 적습니다.** 회사 질문 24개라 한두 문항의 변화가 차이를 크게 흔듭니다. 판정은 문항 단위 부트스트랩으로 이 불확실성을 구간에 담습니다.
- **COPA는 시드를 받지 않습니다.** 그래서 주 판정은 3번씩 반복합니다.

## 방법

저장소 최상위에서 돌립니다. 토큰은 M6과 같은 `experiments/m6-agent/token.sh`로 받습니다(`fetch`에만 필요).

```bash
export WIKI_HOST="$(terraform -chdir=infra output -raw public_ip)"
uv run python -m wiki_rag_mcp.agent.scope fetch
uv run python -m wiki_rag_mcp.agent.scope run --model gpt-5.4 --prompt generic --set new --repeat 3
uv run python -m wiki_rag_mcp.agent.scope run --model gpt-5.4 --prompt demo --set old --conditions B
uv run python -m wiki_rag_mcp.agent.scope run --model gemini-3.1-pro --prompt generic --set new
uv run python -m wiki_rag_mcp.agent.scope run --model gpt-5.4 --prompt demo --set new
uv run python -m wiki_rag_mcp.agent.scope report
```
